# 第一章当前目标 HUD 与场景节奏点打磨设计

> Status: Draft  
> Date: 2026-06-30  
> Scope: 第一章打磨小迭代  
> Related: `design/gdd/main-narrative.md`, `design/gdd/exploration-insight.md`, `design/gdd/dialogue-system.md`, `docs/architecture/control-manifest.md`

## 1. 目标

本设计用于第一章技术验收通过后的体验打磨。目标是在不扩张系统范围的前提下，让玩家始终清楚：

1. 当前处于哪个叙事阶段。
2. 下一步要去哪、做什么。
3. 每个场景完成后是否获得了有效反馈。

本轮打磨不做完整任务系统、不重构 Tab 线索本、不新增大段教程。HUD 只承担轻提示，场景节奏点只补短交互和短独白。

## 2. 范围

### In Scope

- 探索态右上角“当前目标 HUD”。
- 第一章五个关键阶段的目标文本更新。
- 入镇、纸钱铺、客栈、命案现场、桥头战斗的节奏反馈点。
- 对话、叙事遮罩、战斗、转场期间的 HUD 隐藏规则。

### Out of Scope

- 完整 Quest 系统。
- Tab 线索本 UI 重构。
- 存档数据结构扩展。
- 大规模新增 NPC、支线或美术资产。
- 第二章《桥东旧祠》内容。

## 3. 当前目标 HUD

### 3.1 布局

HUD 位于探索态右上角，使用半透明深色背景，不遮挡玩家角色、交互提示和场景中心区域。

推荐结构：

```text
第一章 · 江南雨夜
当前目标：去客栈问一问昨夜买纸钱的外乡人
原因提示：纸钱铺掌柜提到三更后有人来过
```

### 3.2 显示规则

- 探索态显示。
- 对话、叙事遮罩、战斗、场景转场期间隐藏。
- 目标变化时短暂高亮 1 秒。
- 目标完成后显示一句短反馈，再切换到下一目标。
- HUD 不显示完整任务列表，只显示当前最关键的一步。

### 3.3 目标节点

| 阶段 | HUD 当前目标 | 原因提示 |
|---|---|---|
| 入镇 | 查看镇口散落的纸钱 | 雨夜镇口留下了不合时宜的纸钱 |
| 纸钱铺后 | 去客栈询问昨夜的外乡人 | 掌柜提到三更后有人来买过同样的纸钱 |
| 客栈后 | 前往命案现场核对纸钱湿痕 | 客栈传闻把外乡人与命案现场连在一起 |
| 命案现场后 | 去桥头追上可疑人 | 血迹与脚印指向桥头 |
| 战斗后 | 回顾线索，准备离开江南雨夜 | 对方不是源头，追查仍未结束 |

### 3.4 驱动方式

第一轮优先由现有第一章流程脚本或章节流程状态驱动 HUD 文本，不引入独立 Quest 系统。若已有 `ChapterManager` 或同等流程状态可用，HUD 只读取当前阶段并展示映射文本。

## 4. 场景节奏点

每个场景只承担一个核心动作，避免堆内容。节奏目标是每 2 到 4 分钟给玩家一次“发现 / 判断 / 反馈”。

| 场景 | 玩家动作 | 反馈 |
|---|---|---|
| 入镇 | 调查湿纸钱 | 获得“纸钱不是自然淋湿”的短独白 |
| 纸钱铺 | 与掌柜对话 | 更新目标到客栈，形成“外乡人”线索感 |
| 客栈 | 听到传闻或询问店家 | 把外乡人与桥头方向关联 |
| 命案现场 | 调查血迹或脚印 | 三条线索合流，触发桥头方向 |
| 桥头战斗 | 战前确认动机，战后收束 | 给章节小结，说明追查仍未结束 |

### 4.1 短独白示例

入镇：

```text
这纸钱湿得太均匀，不像被雨打过。
像是有人先浸湿，再撒在这里。
```

命案现场：

```text
纸钱、血迹、脚印都朝着同一个方向。
桥头那边，恐怕有人在等我。
```

桥头战后：

```text
他知道的不多，却足够证明这不是一场寻常命案。
江南雨夜，只是线头。
```

### 4.2 状态流

```text
入镇目标
  -> 纸钱调查完成
  -> 纸钱铺对话完成
  -> 客栈线索完成
  -> 命案现场合流完成
  -> 桥头战斗完成
  -> 第一章打磨段落完成
```

每次状态推进同时执行：

1. 更新 HUD 当前目标。
2. 播放一条短反馈。
3. 必要时解锁下一个交互点或转场触发。

## 5. 交互与 UI 约束

- HUD 不与 `InteractCue` 争夺视觉焦点。
- HUD 不在对话面板、叙事遮罩、战斗 UI 上方显示。
- 短独白优先复用现有对话或叙事展示能力，不新增全新 UI 控件。
- 若需要暂停玩家移动，应沿用现有锁定路径，避免引入第二套输入锁定。
- 所有新增文本使用中文，保持克制、短句、留白。

## 6. 验收标准

- 玩家不看外部说明也知道下一步去哪。
- 每个关键场景至少有一次明确反馈。
- HUD 在对话、战斗、转场中不会遮挡或残留。
- 第一章从入镇到桥头战斗仍能完整跑通，无新增运行时报错。
- 文本总量克制，不把探索变成连续阅读文档。

## 7. 实现建议

第一轮实现建议拆成三步：

1. 新增或接入当前目标 HUD 展示层。
2. 将第一章流程阶段映射为 HUD 文本。
3. 在五个关键场景补短反馈点，并跑完整第一章验收。

若实现过程中发现第一章流程状态散落在多个脚本中，应只做最小整合，不在本轮重构成通用 Quest 系统。
