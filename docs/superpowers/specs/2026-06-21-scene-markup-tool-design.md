# 场景标注工具设计

> 日期：2026-06-21  
> 状态：已获用户批准，待实现计划  
> 目标项目：`feng-zhi` Godot 原型项目  
> 目标插件：Godot EditorPlugin  
> 目标场景：以 `feng-zhi/StartCave.tscn` 为首个验证场景

## 目标

`Scene Markup Tool` 是一个 Godot 编辑器插件，用于解决完整背景图场景中的碰撞、可行走范围和遮挡标注问题。

当前山洞场景使用一张完整背景图作为主要画面。为了让玩家能在画面中移动、被墙体阻挡、站到前景物体后方，并为后续 NPC 寻路或点击移动保留数据，需要一个可以直接在 2D 视图中圈选区域并生成 Godot 原生节点的工具。

第一版目标是让关卡作者能快速完成以下操作：

1. 在背景图上逐点圈选碰撞区。
2. 在背景图上逐点圈选可行走区。
3. 在背景图上逐点圈选前景遮挡区。
4. 生成的结果能保存到 `.tscn` 场景中。
5. 运行游戏时不依赖编辑器插件逻辑。

## 范围

本次设计包含：

- 一个 Godot EditorPlugin。
- 一个编辑器 Dock。
- 2D 视图中的逐点多边形圈选交互。
- 碰撞、可行走、遮挡三种标注模式。
- 自动生成 `SceneMarkupRoot` 和分类子节点。
- 遮挡区复用背景纹理并计算 UV。
- 编辑器中的辅助轮廓显示开关。

本次设计不包含：

- 自由手绘。
- 自动边缘识别。
- 多边形布尔合并或裁剪。
- 运行时热编辑。
- 额外 JSON、YAML 或 `.tres` 标注数据导出。
- 自动切图。
- 复杂关卡批处理。

## 架构

插件本体使用 GDScript 编写为 Godot EditorPlugin。选择 GDScript 的原因是编辑器插件 API 使用更直接，迭代速度更快；插件只在编辑器中运行，不进入游戏运行时。

插件生成的内容全部是 Godot 原生节点。这样运行时可以直接加载场景，不需要额外工具脚本，也不会把编辑器工具和现有 C# 玩法代码耦合在一起。

推荐插件目录：

```text
feng-zhi/addons/scene_markup_tool/
  plugin.cfg
  scene_markup_plugin.gd
  scene_markup_dock.gd
  scene_markup_dock.tscn
```

生成后的场景结构：

```text
StartCave (Node2D)
  Background (Sprite2D)
  Player (CharacterBody2D)
  Interactions (Node2D)
  SceneMarkupRoot (Node2D)
    Collisions (Node2D)
    Walkable (Node2D)
    Occluders (Node2D)
```

`SceneMarkupRoot` 只承载插件生成的场景标注，不放剧情交互、拾取物或 UI 节点。

## 编辑流程

关卡作者在 Godot 编辑器中打开目标场景后：

1. 选中背景 `Sprite2D`，例如 `Background`。
2. 在插件 Dock 中点击“设为背景”。
3. 选择标注模式：碰撞区、可行走区或遮挡区。
4. 在 2D 视图中左键逐点绘制多边形轮廓。
5. 使用右键或回车闭合多边形。
6. 插件根据当前模式生成节点。
7. 生成后可以继续使用 Godot 原生编辑能力调整节点和多边形。

逐点多边形是第一版唯一支持的圈选方式。它比自由手绘更适合碰撞体、导航区域和前景遮挡片，生成结果也更容易检查和修正。

## 生成规则

### 碰撞区

碰撞模式生成环境碰撞节点：

```text
Collisions (Node2D)
  Collision_001 (StaticBody2D)
    CollisionPolygon2D
```

`CollisionPolygon2D.Polygon` 使用圈选点。碰撞区默认用于阻挡玩家移动，具体碰撞层和遮罩在实现计划中按照 `feng-zhi` 现有玩家碰撞配置确定。

### 可行走区

可行走模式生成导航区域：

```text
Walkable (Node2D)
  Walkable_001 (NavigationRegion2D)
```

`NavigationRegion2D` 的导航多边形来自圈选点。当前山洞原型仍以键盘移动为主，但可行走区会为后续点击移动、NPC 寻路或探索限制提供数据基础。

### 遮挡区

遮挡模式生成前景贴片：

```text
Occluders (Node2D)
  Occluder_001 (Polygon2D)
```

遮挡区的核心规则：

- `Polygon2D.Texture` 复用背景 `Sprite2D.Texture`。
- `Polygon2D.Polygon` 使用圈选点。
- `Polygon2D.Uv` 由圈选点换算为背景纹理坐标。
- `Polygon2D.ZIndex` 默认高于玩家。

圈选点以当前场景的 2D 坐标为准。计算遮挡 UV 时，插件需要使用背景 `Sprite2D` 的变换把圈选点换算回背景纹理坐标，避免背景发生位移、缩放或居中绘制时遮挡贴片错位。

这样可以在不切图的情况下，让主角走到岩石、桌沿、洞口前景等区域后面时被自然遮住。

第一版遮挡层级使用静态预设：

- 前景低
- 前景中
- 前景高

这些预设本质是不同的 `ZIndex`。如果某个物体同时需要前后层次，关卡作者可以圈选多个遮挡片并分别设置层级。

## 编辑器辅助显示

插件 Dock 提供“显示标注辅助线”开关。开启后，编辑器中显示不同类型区域的轮廓：

- 碰撞：红色。
- 可行走：绿色。
- 遮挡：蓝色。

辅助线仅用于编辑器可视化。运行游戏时默认不可见，不影响玩家画面。

## 数据与运行时边界

第一版采用“纯 Godot 节点即数据”的方案，不额外保存 JSON、YAML 或资源文件。`.tscn` 场景文件就是标注结果的权威来源。

插件在编辑器中负责创建和更新节点；游戏运行时只使用已经保存到场景中的节点。碰撞、导航和遮挡都依赖 Godot 原生能力生效。

这个边界有两个好处：

1. 原型阶段更直观，生成后立刻能看见和调试。
2. 未来可以无损升级。如果场景数量增加，再新增标注资源或批量导出流程，不需要推翻当前节点结构。

## 错误处理

插件需要处理以下情况：

- 未设置背景时禁止生成遮挡区，并提示先选择背景 `Sprite2D`。
- 圈选点少于 3 个时不生成多边形。
- 当前场景没有 `SceneMarkupRoot` 时自动创建。
- 分类节点缺失时自动创建。
- 当前选择的背景不是 `Sprite2D` 时提示类型错误。
- 背景没有纹理时禁止生成遮挡区。

所有错误提示应显示在插件 Dock 中，避免弹出过多阻塞式对话框。

## 验收标准

1. 插件能在 Godot 4.7-stable 中启用。
2. 打开 `feng-zhi/StartCave.tscn` 后，可以将 `Background` 设为背景。
3. 碰撞模式下逐点圈选并闭合后，场景中生成碰撞节点。
4. 可行走模式下逐点圈选并闭合后，场景中生成可行走节点。
5. 遮挡模式下逐点圈选并闭合后，场景中生成复用背景纹理的 `Polygon2D`。
6. 生成的遮挡片能在运行时遮住玩家。
7. 生成的碰撞区能在运行时阻挡玩家。
8. 编辑器辅助线能按类型显示和隐藏。
9. 保存并重新打开场景后，生成的节点仍然存在并保持效果。
10. 插件不要求游戏运行时加载额外编辑器脚本。
