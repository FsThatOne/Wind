# Burst+Read 战斗概念

> 本概念文档从纸面原型、v0.2 规则修订、战斗记录和 Godot 引擎 Spike 反向整理而来。原型代码只作为验证证据，不能直接整理进正式生产代码。

## 概述

Burst+Read 是《风止》的核心战斗概念：用短回合、高决策密度的武侠战斗，让玩家观察敌方意图、选择克制招式、管理内息，并在对方露出破绽时打出一击决胜。

原型验证了一个关键判断：敌方意图可读 + 刚 / 柔 / 巧关系，可以带来“读人取胜”的满足感，而不是单调的猜拳计算。

## 原型验证问题

在玩家能看见敌方意图的回合制武侠战斗中，5-15 回合的短战斗是否仍能产生有意义的紧张感？玩家是否会在反制、保留资源和爆发时机之间做真实取舍？

## 范围

- 1v1、1v2、2v2 的纸面规则与战斗模拟。
- v0.2 对反制成本、反巧覆盖、破绽衰减的调参验证。
- Godot 4.7-stable + C# 引擎 Spike，用于验证意图 UI、同时结算和回合节奏。
- 使用占位 UI 与占位数据；不包含正式资产、动画组或最终平衡。

## 已构建 / 已测试内容

- 基于刚 / 柔 / 巧的敌方意图展示。
- 克制关系与修订后的伤害倍率方向。
- 内息作为主要战斗资源。
- 破绽压力与一击决胜窗口。
- 小招式池在 1v1、1v2、2v2 中的表现。
- 引擎手感 Spike：意图颜色可读性、短回合节奏、同时伤害反馈。

## 关键发现

- “读意图 → 反制 → 爆发”的核心循环成立，应继续推进。
- 5-15 回合是合适的目标长度：不拖沓，但有足够决策空间。
- Intent tell 清晰可读，能让玩家在出招前自然停顿思考。
- 一击决胜在正确窗口触发时，有“高手过招、一招分胜负”的收束感。
- 1v1 很干净；2v2 会自然产生同伴协同，不需要额外强行做组合技系统。
- 初始 5 招太少，玩家需要更完整的反制覆盖。
- v0.1 的反制过强，需要更高成本、冷却压力或 AI 反读机制。
- 破绽压力需要衰减或重置规则，避免锁死滚雪球。
- 原始 1.5x / 0.5x 克制倍率在引擎中显得过重；GDD 方向调整为 1.3x / 0.7x。

## 验证价值

- Burst+Read 应进入核心战斗 GDD。
- 刚 / 柔 / 巧可以成为战斗语言，但必须绑定可读意图和资源取舍。
- 多人战斗可以保留“读人”的幻想，前提是每个目标的意图和威胁足够清晰。
- Godot 4.7-stable + C# 足以支撑该战斗原型循环。

## 已知限制

- 多数测试来自设计者自测，仍需要外部玩家验证。
- AI 行为刻意简化，不能证明正式敌人多样性。
- 引擎 Spike 使用占位 UI，没有正式动画、特效、音效或镜头语言。
- 平衡数值只是原型调参目标，不是最终发售数值。

## 带入正式设计的决定

- 保留敌方意图可见或部分可识破，作为核心战斗支柱。
- 保留刚 / 柔 / 巧克制，但优势要明显而非绝对碾压。
- 正式设计中所有招式至少 1 回合冷却，推动招式轮换，避免重复最优解。
- “再动”作为稀有强效果保留，但受每招冷却约束。
- 保留一击决胜作为爆发窗口；临阵突破等特殊事件可以刷新冷却，但必须绑定严格风险 / 收益。
- 原型代码不进入正式生产，只作为验证证据。
