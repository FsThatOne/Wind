## 使用说明

这份用例是给人工实机检查用的，不是自动化测试脚本。

每条用例都按以下格式执行：

- **准备**：测试前需要进入什么状态。
- **操作**：你在游戏窗口里实际做什么。
- **看什么**：重点观察哪些 UI 或行为。
- **通过标准**：什么情况算通过。
- **记录位置**：截图、录屏或备注应该放到哪里。

如果某条用例无法构造场景，不要勉强通过，记录为“无法测试”，并写明原因。

## cu-004：招式选择面板与预览卡

目标：确认玩家行动时能看懂自己有哪些招式、哪些行动可用、为什么不可用，并且预览卡只显示 GDD 允许的预计伤害区间、预计破绽变化、合法范围和关系提示，不暴露胜率、期望值或最终结算输出。

记录位置：

`production/qa/evidence/cu-004-move-selection-panel-and-preview-card-evidence.md`

### 用例 1：面板是否显示完整行动

**准备**

- 进入 Boss 战或测试战斗。
- 等到玩家可以行动。
- 玩家应至少装备 6 个招式。

**操作**

1. 打开招式选择面板。
2. 不急着选择，先观察面板里有哪些行动。

**看什么**

- 是否显示 6 个装备招式。
- 是否显示当前 GDD 允许的基础行动：调息、使用道具。
- 是否没有显示普通攻击。
- 面板是否能让玩家一眼知道当前可以选择什么。

**通过标准**

- 6 个招式都能看到。
- 调息、使用道具都能看到。
- 普通攻击不会出现。
- 没有出现空白按钮、缺字按钮或明显错位。

### 用例 2：招式格信息是否完整

**准备**

- 招式面板已经打开。
- 面板中有多个不同类型的招式。

**操作**

1. 逐个查看每个招式格。
2. 如果可以，用方向键或鼠标逐个聚焦/悬停。

**看什么**

- 招式名。
- 刚/柔/巧等体系或图标。
- 内息消耗。
- 条件图标或条件说明。
- 一句话效果摘要。
- 心法专属招式是否有“心法”角标。

**通过标准**

- 每个招式格的信息都能读懂。
- 心法专属招式有明确标记。
- 玩家不需要打开额外菜单，也能大致理解招式用途。

### 用例 3：不可用行动是否置灰并说明原因

**准备**

- 尽量构造以下状态中的一种或多种：
  - 当前内息不足。
  - 心法被封印。
  - 没有可用战斗道具。

**操作**

1. 打开招式选择面板。
2. 找到不可用的招式或基础行动。
3. 尝试聚焦这些不可用行动。
4. 如果系统允许，尝试确认不可用行动。

**看什么**

- 内息不足的招式是否置灰。
- 是否显示类似“差 X 内息”的原因。
- 心法封印时，心法专属招式是否显示“心法封印中”。
- 没有道具时，“使用道具”是否置灰或无法打开空背包。

**通过标准**

- 不可用行动有明显置灰或禁用表现。
- 玩家能看到不可用原因。
- 确认键不会提交不可用行动。
- 不会把玩家困在不可用行动上。

### 用例 4：预览卡是否显示关系提示

**准备**

- 招式面板已经打开。
- 当前目标存在可判断的体系关系。

**操作**

1. 聚焦或悬停一个克制目标的招式。
2. 查看预览卡。
3. 再聚焦或悬停一个被克或中性的招式。
4. 再次查看预览卡。

**看什么**

- 预览卡是否随聚焦/悬停变化。
- 是否显示克制、被克或中性关系。
- 是否有反制提示或关系说明。

**通过标准**

- 预览卡会跟随当前选择刷新。
- 关系提示清楚。
- 不会出现选中 A 招式却显示 B 招式说明的情况。

### 用例 5：预览卡不能显示胜率、期望值或最终结算输出

**准备**

- 招式面板和预览卡可以正常显示。

**操作**

1. 依次聚焦多个招式。
2. 仔细查看预览卡上的文字和数字。

**看什么**

- 是否出现预计伤害区间、预计破绽变化和合法范围。
- 是否出现胜率。
- 是否出现期望值。
- 是否出现“最终造成 X 点伤害”这类确定结算数字。

**通过标准**

- 预览卡可以显示预计伤害区间、预计破绽变化、合法范围、消耗、条件、关系和提示。
- 预览卡不显示胜率、期望值或最终结算结果。

### 用例 6：打开面板后的默认焦点

**准备**

- 面板尚未打开。
- 玩家进入行动阶段。

**操作**

1. 打开招式选择面板。
2. 不移动鼠标。
3. 不按方向键。
4. 观察默认高亮在哪里。

**看什么**

- 默认焦点是否落在第一个可用行动。
- 默认焦点是否清楚可见。

**通过标准**

- 面板打开后，玩家可以直接按确认键选择一个合法行动。
- 默认焦点不会落到禁用项、装饰文本或面板外。

### 用例 7：资源刷新不会打断操作

**准备**

- 招式面板已经打开。
- 当前存在一个因内息不足而不可用的招式。

**操作**

1. 保持面板打开。
2. 让内息变化，或触发资源刷新。
3. 观察面板是否刷新。
4. 继续移动焦点或选择行动。

**看什么**

- 面板是否突然关闭。
- 当前焦点是否丢失。
- 招式可用状态是否更新。

**通过标准**

- 面板不关闭。
- 玩家操作不中断。
- 可用/不可用状态会更新到最新。

## cu-005：反制与决胜行动提示

目标：确认 UI 能基于敌方当前内功气机正确提示识破 / 克制关系和决胜机会，但不在 UI 层执行扣费、伤害或破绽结算。

记录位置：

`production/qa/evidence/cu-005-counter-and-decisive-action-prompts-evidence.md`

### 用例 1：当前内功气机可被克制时显示提示

**准备**

- 进入战斗。
- 敌方当前内功气机可见。
- 玩家有一个能克制该当前气机的招式。
- 玩家当前内息不少于 3。

**操作**

1. 打开招式选择面板。
2. 聚焦能克制敌方当前内功气机的招式。
3. 观察招式旁边或预览区域。

**看什么**

- 是否出现识破 / 克制当前气机的提示。
- 提示是否是可用状态。
- 是否有明确的视觉强调。

**通过标准**

- 可克制当前气机时显示清晰提示。
- 玩家能看出这个识破 / 克制关系当前可以触发。
- 不显示胜率、期望值或最终结算数字。

### 用例 2：确认反制只提交意图

**准备**

- 延续用例 1 的可反制状态。

**操作**

1. 聚焦带有识破 / 克制提示的招式。
2. 按确认键提交。
3. 观察日志、战斗表现或后续结算。

**看什么**

- UI 是否提交了对应行动意图。
- UI 是否自己扣内息。
- UI 是否自己造成伤害。
- UI 是否自己改变破绽。

**通过标准**

- UI 只提交“我要用这个行动，并且它可克制当前气机”的意图。
- 扣费、伤害、破绽变化都应由战斗核心逻辑处理。
- 聚焦或提示本身不会改变战斗数值。

### 用例 3：内息不足时反制置灰

**准备**

- 敌方当前内功气机仍可被玩家某招式克制。
- 玩家内息低于行动需要的数值。

**操作**

1. 打开招式选择面板。
2. 聚焦这个能克制敌方当前内功气机的招式。

**看什么**

- 是否显示“内息不足”或等价不可用原因。
- 是否为置灰或不可用状态。

**通过标准**

- 玩家能看见有识破 / 克制机会。
- 玩家也能看见当前内息不足，不能触发。
- 不会误显示为可用金色反制。

### 用例 4：内息变化时反制状态刷新

**准备**

- 面板已经打开。
- 当前招式克制敌方当前内功气机。
- 初始内息不足。

**操作**

1. 保持面板打开。
2. 让内息增加到足够触发反制。
3. 再让内息降回不足。

**看什么**

- 识破 / 克制提示是否从不可用变为可用。
- 内息再次不足时是否重新变为不可用。
- 面板是否关闭或重置。

**通过标准**

- 状态会即时刷新。
- 面板不会关闭。
- 当前选择不会莫名丢失。

### 用例 5：目标破绽达标时显示决胜一击

**准备**

- 当前目标破绽达到决胜要求。

**操作**

1. 选择该目标。
2. 打开招式选择面板。
3. 观察面板顶部或行动列表。

**看什么**

- 是否出现“决胜一击”行。
- 该行是否明显。
- 该行是否可交互。

**通过标准**

- 破绽达标时能看到决胜一击。
- 决胜一击是可选择行动，不只是装饰文本。

### 用例 6：切换目标时决胜提示刷新

**准备**

- 至少有两个目标。
- 一个目标破绽达标，另一个目标破绽未达标，或两个都达标。

**操作**

1. 选中目标 A。
2. 查看决胜提示。
3. 切换到目标 B。
4. 再次查看决胜提示。

**看什么**

- 提示是否跟着当前目标变化。
- 是否错误保留上一个目标的决胜状态。

**通过标准**

- 当前目标达标时显示决胜。
- 当前目标不达标时不显示或显示不可用。
- 切换目标不会造成旧提示残留。

### 用例 7：UI 不执行结算

**准备**

- 反制或决胜提示可见。

**操作**

1. 只移动焦点，不确认。
2. 观察内息、破绽、血量是否变化。
3. 再确认行动。
4. 观察变化来源。

**看什么**

- 聚焦提示是否导致数值变化。
- 确认前是否出现伤害或扣费。

**通过标准**

- 聚焦不会扣费、不会伤害、不会改破绽。
- 确认后如发生结算，应由战斗系统处理，不由 UI 直接处理。

## cu-008：双焦点与键盘/手柄导航

目标：确认不用鼠标也能完成战斗决策，并验证鼠标悬停和键盘/手柄焦点不会互相破坏。

记录位置：

`production/qa/evidence/cu-008-dual-focus-and-gamepad-navigation-evidence.md`

### 用例 1：打开面板后默认焦点正确

**准备**

- 进入玩家行动阶段。
- 面板尚未打开。

**操作**

1. 打开招式选择面板。
2. 不移动鼠标。
3. 观察默认高亮。

**看什么**

- 默认焦点是否在第一个可用行动。
- 高亮是否清楚。

**通过标准**

- 玩家可以直接按确认键选择当前默认行动。
- 焦点没有落到面板外或禁用项。

### 用例 2：方向键或 D-pad 能走遍所有行动

**准备**

- 招式选择面板已打开。

**操作**

1. 连续按向下方向键或手柄 D-pad Down。
2. 观察焦点经过的行动。
3. 再连续按向上方向键或 D-pad Up。

**看什么**

- 是否能到达每个可交互行动。
- 是否能到达反制行。
- 是否能到达决胜一击行。

**通过标准**

- 所有可交互行动都能被键盘或手柄焦点访问。
- 没有只能用鼠标点的行动。

### 用例 3：焦点首尾循环

**准备**

- 焦点已经移动到最后一个可交互行动。

**操作**

1. 继续按向下。
2. 再把焦点移动到第一项。
3. 按向上。

**看什么**

- 最后一项向下是否回到第一项。
- 第一项向上是否回到最后一项。

**通过标准**

- 焦点可以首尾循环。
- 循环过程稳定，不跳出面板。

### 用例 4：焦点不会逃出面板

**准备**

- 招式选择面板已打开。
- 屏幕上可能还有 HUD、暂停按钮或其他 UI。

**操作**

1. 持续按方向键，超过一整圈。
2. 尝试让焦点移动到面板外。

**看什么**

- 焦点是否跳到 HUD。
- 焦点是否跳到暂停按钮。
- 焦点是否跳到不可见或无关控件。

**通过标准**

- 焦点始终留在招式选择面板内。
- 不会出现焦点丢失或不知道当前选中什么的情况。

### 用例 5：确认键提交当前焦点

**准备**

- 招式选择面板已打开。
- 焦点位于一个可用行动。

**操作**

1. 用键盘或手柄把焦点移动到某个行动。
2. 按确认键。

**看什么**

- 提交的是不是当前焦点行动。
- 是否错误提交鼠标悬停的另一项。

**通过标准**

- 确认键提交当前键盘/手柄焦点行动。
- UI 只提交行动意图，不直接执行战斗结算。

### 用例 6：反制和决胜行可用键盘/手柄触达

**准备**

- 构造反制可用状态。
- 构造决胜一击可用状态。

**操作**

1. 打开招式选择面板。
2. 用方向键或 D-pad 移动焦点。
3. 尝试到达反制行。
4. 尝试到达决胜一击行。

**看什么**

- 反制行是否能被焦点选中。
- 决胜一击行是否能被焦点选中。

**通过标准**

- 两个特殊行动都不是鼠标专属。
- 键盘或手柄可以触达并确认。

### 用例 7：鼠标悬停和键盘/手柄焦点并存

**准备**

- 招式选择面板已打开。
- 鼠标可用。
- 键盘或手柄可用。

**操作**

1. 用鼠标悬停在一个招式上。
2. 不移动鼠标。
3. 用方向键或 D-pad 把焦点移动到另一个招式。

**看什么**

- 鼠标悬停的视觉状态是否还在。
- 键盘/手柄焦点的视觉状态是否也在。
- 两种状态是否能区分。

**通过标准**

- 鼠标 hover 和键盘/手柄 focus 可以同时存在。
- 玩家能看懂哪个是鼠标位置，哪个是确认目标。
- 焦点不会清掉 hover，hover 也不会抢走确认目标。

### 用例 8：输入方式切换不丢焦点

**准备**

- 招式选择面板已打开。

**操作**

1. 先用键盘或手柄移动焦点。
2. 再移动鼠标悬停到另一项。
3. 再使用键盘或手柄移动焦点。

**看什么**

- 焦点是否丢失。
- 高亮样式是否混乱。
- 当前确认目标是否清楚。

**通过标准**

- 输入方式切换后仍然知道当前确认目标。
- 不会出现两个完全一样的高亮让玩家分不清。
- 不会出现焦点消失。

### 用例 9：禁用项不会困住焦点

**准备**

- 面板中有禁用行动，例如内息不足、无道具或心法封印。

**操作**

1. 用方向键经过禁用项附近。
2. 继续向上或向下移动。

**看什么**

- 焦点是否卡在禁用项。
- 是否还能继续移动到下一个可用项。

**通过标准**

- 禁用项不会困住焦点。
- 玩家仍能完成选择或选择调息等可用行动。

### 用例 10：不用鼠标完成一轮决策

**准备**

- 进入玩家行动阶段。
- 尽量不使用鼠标。

**操作**

1. 用键盘或手柄打开/操作招式面板。
2. 移动焦点。
3. 选择一个行动。
4. 按确认。

**看什么**

- 是否全程不需要鼠标。
- 是否能完成一次玩家行动选择。

**通过标准**

- 玩家只用键盘或手柄即可完成一轮战斗决策。
- 没有 hover-only 阻塞。
