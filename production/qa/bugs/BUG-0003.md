# Bug Report

## Summary

**Title**: cu-005 实机反制提示仍基于旧招式属性口径而非敌方当前内功气机  
**ID**: BUG-0003  
**Severity**: S1-Critical  
**Priority**: P0-Immediate  
**Status**: Superseded — stale target
**Reported**: 2026-06-16  
**Reporter**: User  

## Classification

- **Category**: Gameplay / UI Contract
- **System**: Combat UI / Counter Prompt / Xingqi Tactics
- **Frequency**: Observed in manual QA and debug output
- **Regression**: Design drift after combat redesign

## Environment

- **Engine**: Godot 4.6.3
- **Platform**: macOS local dev build
- **Input**: Mouse + keyboard
- **Scene/Level**: retired stale target `prototypes/fengzhi-vertical-slice` (deleted 2026-06-17)
- **Game State**: Boss combat flow

## Reproduction Steps

**Preconditions**: Start the Fengzhi vertical slice and enter the Boss combat flow.

1. Observe the Boss decision/debug output.
2. Inspect the current counter/decisive prompt behavior.
3. Compare the implementation semantics against the current GDD combat design.

**Expected Result**:

- Counter/read information is based on the enemy's current inner power qi tendency / current qi attribute.
- The player responds to the opponent's currently revealed inner power state, not to a hidden or predicted next move type.
- Combat UI and logs should align with the Xingqi Tactics redesign.
- The UI should not present the old "move counters move" / "public next move type" model as the core counter rule.

**Actual Result**:

- The visible implementation still appears to use the old move-type counter model.
- Debug output reports `Boss决策: Attack 体系:Rou` and `Boss决策: Attack 体系:Gang`.
- Combat log still reports direct move-vs-move resolution such as `寸劲 → Boss -23 | 寒冰掌 → 玩家 -14 [克制!]`.
- User could not see the player-facing information needed for the new counter model.
- User identified the current `cu-005` premise as wrong: "我们游戏是不看对方出招属性进行反制，而是对方当前内功属性，根基错了，cu-005肯定全错。"

## Impact

- Blocks Sprint 5 QA sign-off for `cu-005`.
- Invalidates the current `cu-005` acceptance criteria and manual QA cases.
- Re-opens a Must Have Combat UI story that was previously marked Complete.
- Blocks Production → Polish readiness until the Combat UI prompt model is realigned with current GDD.
- This is a design-contract failure, not a minor UI display issue.
