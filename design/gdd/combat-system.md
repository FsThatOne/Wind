# 回合制战斗（Burst+Read）

> **Status**: Designed
> **Author**: user + game-designer + systems-designer
> **Last Updated**: 2026-06-02
> **Implements Pillar**: Pillar 1 — 一读定生死（核心战斗幻想）

## Overview

回合制战斗是《风止》的核心系统——它回答"为什么玩这个游戏"。

每场战斗遵循一个简洁的核心循环：**看穿（读意）→ 抉择（出招）→ 结算（克制判定）→ 爆发（一击决胜）**。

敌人在每回合开始时亮出下一招的**体系类型**（刚 / 柔 / 巧），但不暴露具体招式。玩家根据这个信息，从自己装备的武学中选择应对——是硬碰硬（刚克巧）、以柔克刚、还是巧取胜。

三体系之间形成循环克制：**刚克巧、巧克柔、柔克刚**。克制方造成增强伤害并累积破绽，被克制方承受增强伤害。当一方破绽累积到阈值，触发**一击决胜窗口**——这是战斗的高潮时刻，一招定胜负。

整个战斗被设计为短而紧张：5-15 回合内必须决出胜负。每一招都像武侠小说中的"过招"——不是数值磨血，而是思维博弈。

技术上，战斗系统从角色属性系统读取所有数值（攻击/防御/速度/内息/气血/破绽），通过刚/柔/巧克制关系和伤害公式结算每回合，并向战斗 UI 系统输出所有需要展示的信息。

## Player Fantasy

**"观其眉目，知其剑意"**

你是一个武学高手。在你面前，对手的每一个细微动作——握剑方式的变化、脚步的移动、呼吸的节奏——都在告诉你他下一招要做什么。你看穿了他的意图，在他出招的瞬间，你的反制已经到了。

这不是数值碾压，不是装备堆砌，不是技能冷却管理。**这是两个高手之间的智力交锋**——你必须真正"读"懂对手，在有限的内息和有限的回合内找到那个一击定胜负的时刻。

当你在第三回合连续读穿对手的两次刚系进攻，用柔系化解并累积了足够破绽，在第四回合一招"断水寒光"终结战斗时——那种感觉是：**我赢了，不是因为等级高，而是因为我比对手聪明。**

参考体验：
- 《Into the Breach》中看到敌人意图后的策略规划感
- 武侠小说中"过招"时那种一招决生死的紧张感
- 象棋残局中发现必杀棋路的顿悟感

## Detailed Design

### Core Rules

**1. 战斗触发与初始化**

- 战斗通过叙事事件或场景遭遇触发，不可逃跑（武侠对决不存在"逃跑"选项）
- 初始化时，所有参战角色的气血/内息设为当前最大值，破绽设为 0
- 玩家方上阵规模：最多 5 人，主角必须上阵；可同行人数随章节和剧情逐步增加，因此早期可能无人可补满 5 人
- 敌方参战人数不设 5 人硬上限，由剧情、关卡空间和信息密度控制；围攻、护送、突围等场景可以出现多于 5 名敌人

**2. 回合流程**

每回合按以下顺序执行：

```
① 回合开始
   → 每个角色内息自然回复（neixi_recovery）
   → 每个角色破绽衰减 1（最低到 0）
   → 检查是否有持续效果到期

② 意图公开（读意阶段）
   → 所有敌方角色的下一招体系类型（刚/柔/巧）显示在屏幕上
   → 不显示具体招式名称和伤害数值
   → 玩家方的意图对敌方隐藏

③ 玩家决策
   → 玩家为己方每个角色选择一个行动：
     a. 使用招式（从 6 个装备槽中选择，消耗对应内息）
     b. 反制（消耗 3 内息，对特定目标使用克制体系招式，额外 +1 破绽）
     c. 决胜一击（当目标破绽 ≥ 阈值时可选）
     d. 调息（放弃攻击，回复内息，详见 F8）
     e. 普通攻击（零消耗，无体系，固定低伤害，紧急备用）
     f. 使用道具（消耗回合，从战斗背包中选取消耗品使用，详见 item-system GDD）
   → 如果一击决胜窗口开启，可选择"决胜一击"

④ 同时结算
   → 所有角色的行动在逻辑上同时发生
   → 按速度排序决定演出顺序（不影响逻辑结果）
   → 结算顺序：
     a. 计算有效攻击力（F1）→ 基础/最终伤害（F2-F4）
     b. 检查命中招式的 special_condition 是否满足（F5）
     c. 若条件满足，应用 special_effect（破绽额外变动、防御减免、内息回复等）
     d. 更新所有角色的资源状态（气血、内息、破绽）

⑤ 回合结束
   → 检查是否有角色气血归零（落败判定）
   → 检查是否战斗结束（一方全灭或特殊条件达成）
   → 未结束则进入下一回合
```

**3. 三体系克制关系**

```
刚 ─克→ 巧 ─克→ 柔 ─克→ 刚
```

| 攻方体系 | 守方体系 | 伤害倍率 | 破绽变化 |
|---|---|---|---|
| 克制（如刚 vs 巧） | — | ×1.3 | 守方 +2 破绽 |
| 被克（如刚 vs 柔） | — | ×0.7 | 攻方 +1 破绽 |
| 同系（如刚 vs 刚） | — | ×1.0 | 无破绽变化 |

（伤害倍率从 prototype 的 1.5/0.5 调整为 1.3/0.7，prototype 玩测反馈差距过大）

**4. 伤害结算**

```
基础伤害 = 攻方体系攻击力 - 守方防御力
    → 最低为 1（防御不能完全免伤）
最终伤害 = 基础伤害 × 克制倍率 × 暴击倍率（如果暴击）
    → 暴击倍率 = 1.5
```

**5. 反制机制**

- 消耗：3 内息
- 触发条件：玩家选择对一个特定敌人使用克制该敌人已公开体系的招式
- 效果：在正常克制效果之上，额外 +1 破绽（总计 +3 破绽）
- 限制：每回合每个角色只能反制一个目标

**6. 一击决胜**

- 触发条件：目标破绽 ≥ 破绽阈值（默认 5）
- 效果：攻方可选择发动"决胜一击"，造成 ×2.0 伤害 + 一段专属演出动画
- 如果不选择：破绽不会因为超过阈值而消失，保持到正常衰减
- 连续回合判定：如果反制成功的下一回合仍然满足条件，可以再次触发

**7. 多人战斗规则**

- 玩家在多人战斗中控制所有己方上阵角色；主角不可下阵，其他上阵席位可在战斗前由队伍配置决定（特定场景或战役可锁定）
- 协同效果：如果两个己方角色在同一回合攻击同一目标，且都触发克制，额外 +1 破绽（协同加成）
- 目标选择：每个角色独立选择攻击目标
- **敌方协同**：多敌人战斗中，敌方 AI 不享有协同破绽加成（非对称设计——敌方通过数量和血量优势弥补）。但如果两名敌人同回合攻击同一己方角色，视觉上呈现"围攻"效果，由 enemy-ai 的 `SelectTarget` 自然涌现（无额外机制加成）

**8. 多人战斗 UI 信息密度管理（W20）**

玩家方最多 5 人，敌方数量可能超过 5 人，因此信息密度需严格控制：

| 层级 | 显示内容 | 适用对象 |
|------|---------|---------|
| **焦点层** | 全信息（HP/内息/破绽/体系/状态buff/意图详情） | 当前正在操作的己方角色 + 其攻击目标 |
| **概览层** | 精简信息（HP条 + 体系图标 + 意图类型符号） | 其他所有单位 |
| **告警层** | 脉动高亮（HP条闪烁 / 破绽即将达阈值标记） | 任何处于危险状态的单位 |

规则：
- **焦点跟随**：玩家切换控制角色时，焦点层自动跟随；点击任何单位可临时切换焦点查看详情
- **意图顺序揭示**：多敌人意图不同时弹出，而是按速度序依次揭示（每个间隔 0.3s），降低瞬时认知负荷
- **协同提示合并**：当两名敌人同时瞄准同一目标时，合并为一条"围攻警告"而非两条独立意图
- **信息密度上限**：同屏可见的数值条（HP/内息/破绽）最多 6 条；超出时概览层单位仅显示 HP 条

> **Anti-Pillar 对齐**：Pillar 3（武侠味先于游戏味）要求战斗 UI 不像"数据面板"，信息分层确保玩家注意力聚焦于当前对决而非全局数值管理。

**9. 战斗结束条件**

| 条件 | 结果 |
|---|---|
| 敌方全部气血归零 | 玩家胜利 |
| 玩家方全部气血归零 | 战斗失败（叙事处理，非 Game Over） |
| 特殊剧情条件达成 | 剧情中断战斗 |
| 回合数达到上限（15） | 平局 / 敌方撤退（叙事处理） |

### States and Transitions

```
[战斗外]
   ↓ 叙事触发 / 场景遭遇
[战斗初始化]
   → 加载参战角色属性、初始化资源
   ↓
[回合循环]
   → 回合开始 → 意图公开 → 玩家决策 → 同时结算 → 回合结束
   ↓ （循环直到结束条件）
[战斗结束]
   → 胜利 / 失败 / 剧情中断
   ↓
[结算界面]
   → 显示战斗统计、获得经验/道具
   ↓
[返回战斗外]
```

战斗内的角色状态：

| 状态 | 说明 | 转换 |
|---|---|---|
| **正常** | 可以自由选招 | 气血 > 0 |
| **破绽暴露** | 破绽 ≥ 阈值，面临一击决胜风险 | 破绽 ≥ 5 |
| **一击决胜窗口** | 可以被决胜一击打击 | 破绽 ≥ 5 且攻方选择发动 |
| **落败** | 无法行动 | 气血 = 0 |

### Action Registry

战斗中玩家可执行的完整行动类型注册表。所有子系统（UI、AI、存档回放）均以此为行动类型的 SSoT。

| ID | 行动类型 | 内息消耗 | 前置条件 | 结果摘要 |
|---|---|---|---|---|
| `action_move` | 使用招式 | 招式定义值 | 内息 ≥ 消耗 | 造成伤害/施加效果；扣除内息 |
| `action_counter` | 反制 | 3 | 内息 ≥ 3；选择的招式体系克制目标意图体系 | 伤害×1.3 + 目标破绽+2；若不克制则降级为普通攻击 |
| `action_decisive` | 决胜一击 | 0 | 目标破绽 ≥ 5（阈值） | 伤害×2.0 + 专属演出；清空目标破绽 |
| `action_breathe` | 调息 | 0（恢复） | 无 | 放弃攻击；回复内息 = F8 `meditation_recovery`（`ceil(neixi_recovery × meditation_efficiency)`，详见 character-attributes）；防御 +20% 持续至下回合结算前 |
| `action_basic` | 普通攻击 | 0 | 无 | 固定低伤害（`basic_attack_damage` = 角色攻击力×0.3）；无体系属性 |
| `action_item` | 使用道具 | 0 | 战斗背包中有可用消耗品 | 消耗回合；效果由道具定义（见 item-system GDD `RegisterCombatAction("use_item")`） |
| `action_epiphany` | 凝神顿悟 | 0 | 顿悟抉择状态激活（见顿悟交互协议） | 进入 `凝神` 状态 3 个自然行动轮；完成后获得永久奖励 + 悟后状态 buff + 刷新该角色普通技能冷却；普通战斗无默认免死 |
| `action_epiphany_skip` | 稳妥取胜 | 0 | 顿悟抉择状态激活 | 获得 skip_reward（气血/内息回复、清除自身破绽、下一击必暴击、短时减伤）；正常进入本回合决策 |

> **扩展约定**：新增战斗行动须在此表注册并分配唯一 ID，同步更新 UI 面板和 AI 决策树。

### Epiphany Integration Protocol（顿悟交互协议）

本节定义战斗系统与顿悟突破系统的完整交互时序、凝神状态和 UI 状态切换。解决的核心问题：**顿悟判定发生在回合结束，但玩家需要在下一回合做出选择——如何衔接？**

**1. 时序规则**

```
回合 N 结束
  → 结算完毕
  → 战斗系统检查顿悟前置条件（HP/回合/连续被反制）
  → 若条件满足：发射 OnEpiphanyTrigger()
  → 顿悟系统执行概率判定
  → 返回 EpiphanyCheckResult(success, epiphany_id)
  → 若 success=false：正常进入回合 N+1
  → 若 success=true：战斗进入 [顿悟抉择状态]

回合 N+1 开始
  → 内息回复 / 破绽衰减 照常执行
  → 意图公开 照常执行
  → 玩家决策阶段：
    ┌── 若 [顿悟抉择状态] 激活 ──┐
    │  UI 呈现排他性二选一：      │
    │  ① 凝神顿悟 (action_epiphany)  │
    │  ② 稳妥取胜 (action_epiphany_skip) │
    │  正常行动菜单 **不可用**     │ ← B7 修复点
    └────────────────────────────┘
  → 玩家选择后：顿悟系统回传 EpiphanyChoiceResult(choice)
  → 战斗系统执行对应行动
  → 若选择稳妥：立即获得生存收益，并回到正常决策
  → 若选择凝神：该角色进入 [凝神状态]，其他角色继续正常行动
```

**2. 凝神状态规则 (Epiphany Focus State)**

选择 `action_epiphany` 后，该角色进入 `凝神` 状态，默认持续 `epiphany_focus_turns = 3` 个自然行动轮：

- 凝神角色不能移动、出招、普通攻击、使用道具、切换内功、调息或使用轻功
- 凝神角色仍可被攻击、被施加 debuff、累积破绽、受到位移或控制效果（除非具体效果另有规则）
- 普通战斗中凝神**没有默认免死保护**；若 HP ≤ 0，按正常落败/倒地处理，顿悟失败
- `death_protection: true` 仅用于教学顿悟或脚本战斗，不能作为通用规则
- 凝神完成时，战斗系统通知顿悟系统执行 `OnEpiphanyComplete(actor, epiphany_id)`
- 完成后才发放永久奖励、悟后 buff，并刷新该角色所有普通招式、心法主动和轻功主动冷却
- 凝神失败不发放奖励、不刷新冷却、不设置 `_done` flag

> 设计意图：凝神不是白拿永久成长，而是一次战场上的共同冒险。选择凝神的人把命交给队友，队友需要用站位、控制、治疗和牵制为他争取三轮。这能把"临阵突破"从个人爽点变成有江湖味的团队时刻。

**3. 稳妥取胜执行规则**

选择 `action_epiphany_skip` 时：

- 立即发放 skip_reward（回复 50% 最大气血、回复 50% 最大内息、清除自身破绽、下一击必暴击、短时受到伤害 -30%）
- 顿悟抉择状态解除，**本回合立即切换为正常决策阶段**
- 玩家可继续从正常行动菜单选择本回合行动（不浪费回合）
- 不刷新任何招式或轻功冷却
- 该顿悟事件不标记完成，未来仍可再次触发（受 skip_limit 约束）

> 设计意图：稳妥不是"放弃然后空过"——它的即时战术收益应明显强于凝神的起手收益。玩家应该经常产生"我很想凝神，但这三轮可能撑不住，先活下来才有以后"的判断。

**4. 多角色场景**

多人战斗中，若己方某角色触发顿悟：

- 仅该角色的行动被替换为顿悟二选一
- 其他己方角色正常从行动菜单选择
- 选择凝神后，其他己方角色继续按速度队列行动，可保护、治疗、牵制或阻断敌方接近
- 不会同时出现多个角色的顿悟窗口（每场战斗同一时刻只处理一个顿悟）

**5. 顿悟抉择状态的 UI 要求**

| 元素 | 描述 |
|------|------|
| 屏幕表现 | 时间微缩慢放（0.3x 演出速度）+ 墨色涟漪从角色脚下扩散 |
| 选项呈现 | 屏幕中央左右分列两个选项："凝神顿悟"（左，金色光晕）/ "稳妥取胜"（右，蓝色稳固感） |
| 信息提示 | 凝神侧显示风险摘要（"三轮不能行动，完成后突破"）；稳妥侧显示"回气回血，稳住此战" |
| 其他 UI | 正常行动菜单隐藏；敌方意图仍可见（帮助玩家评估风险） |
| 时间限制 | 无（顿悟抉择不限时，玩家可充分思考） |

### Event Bus — 战斗事件清单

战斗系统通过事件总线（Event Bus）向所有订阅方广播状态变更。以下为完整事件清单：

| 事件名 | 参数 | 触发时机 | 订阅方 |
|---|---|---|---|
| `OnRoundStart(round_number)` | 当前回合数 | 每回合开始，意图公开前 | 战斗 UI, 敌方 AI |
| `OnIntentRevealed(enemies[])` | 每个敌人的意图类型（或"?"） | AI 意图决策后 | 战斗 UI |
| `OnPlayerActionSubmitted(actor, action_id, target)` | 行动者、行动ID、目标 | 玩家确认行动选择后 | 战斗系统内部（结算管线入口） |
| `OnDamageDealt(source, target, amount, is_crit, is_counter)` | 来源、目标、伤害值、暴击标记、反制标记 | 伤害结算后 | 战斗 UI, 顿悟突破 |
| `OnStaggerChanged(target, new_stagger)` | 目标、新破绽值 | 破绽增减后 | 战斗 UI |
| `OnNeixiChanged(actor, new_value)` | 行动者、新内息值 | 内息消耗或恢复后 | 战斗 UI |
| `OnDecisiveStrikeAvailable(target)` | 破绽达标的目标 | 破绽 ≥ 阈值时 | 战斗 UI |
| `OnBattleEnd(result)` | 胜/败/平/惜败 + 奖励数据 | 战斗结束条件满足时 | 战斗 UI, 主线叙事, 心境双轴 |
| `OnEpiphanyTrigger(actor, condition)` | 角色、触发条件 | 特殊战斗条件满足时 | 顿悟突破 |
| `OnRoundEnd(round_number)` | 当前回合数 | 结算完毕、下一回合开始前 | 战斗 UI（回合计数刷新） |

> **订阅方注册**：各系统在初始化时通过 `BattleEventBus.Subscribe(event_name, callback)` 注册；战斗结束时自动解除所有订阅。

### Battle Entry Interface

外部系统通过以下接口发起战斗：

```
InitiateBattle(config: BattleConfig) → BattleInstance
```

**BattleConfig 数据结构**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `battle_type` | enum | `lethal`（致命）/ `narrative`（剧情杀）/ `non_lethal`（非致命） |
| `player_party` | CharacterId[] | 己方参战角色列表（1-3人） |
| `enemy_group` | EnemyConfig[] | 敌方配置（id、等级、AI策略、意图公开规则） |
| `max_rounds` | int | 最大回合数（默认 15） |
| `environment` | string? | 战场环境标识（影响演出背景，不影响数值） |
| `on_victory` | Callback | 胜利后回调（推进叙事节点/发放奖励） |
| `on_defeat` | Callback | 失败后回调（依 battle_type 决定：致命→死亡；剧情杀→继续；非致命→记录 choice_log） |
| `on_draw` | Callback | 平局回调（达到 max_rounds） |

**调用方**：

| 系统 | 场景 |
|---|---|
| 主线叙事 (#9) | 剧情节点触发的必打战斗 |
| 大地图/奇遇 (#3) | 移动中遭遇敌人 |
| NPC 系统 (#10) | 与特定 NPC 切磋/冲突 |

**返回值 `BattleInstance`**：战斗实例句柄，外部可通过 `BattleInstance.status` 查询战斗状态（进行中/已结束）。

## Formulas

### F1. 有效攻击力（武学加成）

战斗从武学组合获取招式参数，先计算有效攻击力，再进入伤害计算管线：

`effective_attack = attack_for_type × move.base_multiplier × move.completion × realm_scaling`

| 变量 | 来源 | 说明 |
|---|---|---|
| `attack_for_type` | 角色属性 `GetAttackForType(type)` | 对应体系的基础攻击力 |
| `move.base_multiplier` | 武学组合 `GetMoveDetails(id)` | 招式固有伤害倍率（0.6-1.5） |
| `move.completion` | 武学组合 `GetMoveDetails(id)` | 完整度（残卷 0.55 / 拓本 0.72 / 完本 0.88 / 真传&批注版 1.00）|
| `realm_scaling` | 武学组合 `GetMoveDetails(id)` | 境界缩放系数（0.7-2.0，由角色属性境界决定） |

### F2. 基础伤害

`base_damage = max(1, effective_attack - defense)`

### F3. 伤害波动

`actual_damage = base_damage × random(0.95, 1.05)`

保留最低伤害为 1 的兜底规则。

### F4. 最终伤害

`final_damage = actual_damage × counter_multiplier × crit_multiplier`

| 情况 | counter_multiplier | crit_multiplier |
|---|---|---|
| 克制 + 暴击 | 1.3 | 1.5 |
| 克制 + 未暴击 | 1.3 | 1.0 |
| 同系 + 暴击 | 1.0 | 1.5 |
| 同系 + 未暴击 | 1.0 | 1.0 |
| 被克 + 暴击 | 0.7 | 1.5 |
| 被克 + 未暴击 | 0.7 | 1.0 |

### F5. 招式特殊效果结算

每次命中后，检查攻方招式的 `special_condition`：

```
if move.special_condition.met(battle_context):
    apply move.special_effect
```

`special_effect` 的应用时机为**伤害结算后、资源更新前**：

| 效果类型 | 示例 | 应用方式 |
|---------|------|---------|
| 破绽加成 | "破绽 +2" | 叠加到本回合破绽变化，与克制破绽相加 |
| 防御减免 | "无视防御 25%" | 在 F2 计算时，defense 降低 25%（本次攻击有效） |
| 内息回复 | "回复内息 2" | 攻方回复内息，在资源更新阶段应用 |
| 破绽减少 | "自身破绽 -1" | 攻方破绽在本回合结束时减少 1 |

**批注版增强**：批注版招式的 `condition_override` 和 `effect_override` 替换原版对应字段，结算逻辑不变，只是条件和效果值不同。

### F6. 一击决胜伤害

`decisive_damage = base_damage × 2.0`

无视克制倍率和暴击，直接以基础伤害的 2 倍计算。

### F7. 破绽累积

| 情况 | 破绽变化 |
|---|---|
| 克制命中 | 守方 +2 |
| 被克制命中 | 攻方 +1 |
| 反制成功（克制 + 指定目标） | 守方额外 +1（总计 +3） |
| 协同攻击（两人同回合克制同一目标） | 目标额外 +1 |
| 每轮衰减 | 每个角色 -1（最低到 0） |

> **设计意图（W19 说明）**：阈值 5 + 衰减 -1/轮 意味着需要 **连续 3 轮**克制才能从 0 达标（2+2+2-1-1=4→再来一轮 +2-1=5）。这与"5-15 回合短战斗"兼容——中等战斗（7-8 回合）中约第 5 轮可触发首次决胜。若设计需要更快节奏，调 `stagger_on_counter` 至 3 或 `stagger_decay` 至 0 可让 2 轮克制即达标。当前默认值倾向于让反制（+3）成为更快达标路径。

### F8. 调息回复

`meditation_recovery = ceil(neixi_recovery × 0.5)`

角色主动选择调息时回复的内息量。本回合不进行攻击。角色也可以选择已装备的零消耗招式替代调息。

### F9. 意图洞察概率

每回合开始时，对每个敌人独立判定：

`insight_chance = base_chance + insight × 1%`

| 功力比（自身/敌方） | base_chance | 公开内容 |
|---|---|---|
| > 1.5 | 100%（且显示具体招式名） | 完全看破 |
| 1.0-1.5 | 100% | 正常看破（仅体系类型） |
| 0.7-1.0 | 80% | 模糊（20% 看到"?"） |
| 0.5-0.7 | 50% | 迷雾 |
| < 0.5 | 30% | 完全迷雾 |

- 每回合、每个敌人独立判定（不是战斗开始时一次性计算）
- 洞察属性提供加成：每点洞察 +1% 概率（叠加在 base_chance 上）
- 上限 100%（意图永远不会"超额"公开）

## Edge Cases

- **如果玩家方和敌方同回合气血归零**：判定为"惜败"，触发特殊叙事分支（不同于正常失败）。
- **如果一击决胜未能击杀目标**：正常扣血，目标存活。一击决胜不保证击杀。
- **如果多个敌人同时破绽达标**：玩家每回合每个角色只能对一个目标发动决胜一击。
- **如果内息为 0 且有零消耗招式**：可以正常使用零消耗招式，也可以选择调息。不强制调息。
- **如果内息为 0 且无零消耗招式**：只能选择调息或普通攻击（零消耗、无体系、固定低伤害）。
- **如果 boss 有多阶段且第一阶段气血归零**：不判定战斗结束，进入下一阶段（气血/破绽重置，行为模式可能改变）。
- **如果战斗达到 15 回合上限**：叙事处理为"旗鼓相当，各自收手"或"敌方撤退"，不算失败。
- **如果意图洞察判定为"?"**：该敌人的体系图标显示为问号，玩家必须猜测或用通用策略应对。
- **如果协同 burst 导致 boss 在 2-3 回合被击杀**：通过 boss 设计解决（高破绽阈值 + 阶段重置），不在战斗系统层面限制。
- **如果伤害波动使最终伤害低于 1**：钳位到 1。

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 过高/过低影响 |
|---|---|---|---|
| `counter_advantage_multiplier` | 1.3 | 1.1-1.6 | 过高→克制一招定胜负；过低→克制无感 |
| `counter_disadvantage_multiplier` | 0.7 | 0.4-0.9 | 过低→被克无伤；过高→被克也痛 |
| `decisive_strike_multiplier` | 2.0 | 1.5-3.0 | 过高→必杀；过低→不值得等破绽 |
| `crit_multiplier` | 1.5 | 1.2-2.0 | 影响暴击价值感 |
| `damage_variance` | ±5% | ±2%-±10% | 过高→伤害不可预测；过低→太确定 |
| `stagger_on_counter` | 2 | 1-3 | 影响破绽累积速度 |
| `stagger_on_countered` | 1 | 0-2 | 被克时的自损破绽 |
| `counter_extra_stagger` | 1 | 0-2 | 反制的额外破绽奖励 |
| `coop_extra_stagger` | 1 | 0-2 | 协同攻击的额外破绽 |
| `max_rounds` | 15 | 10-25 | 过短→来不及决胜；过长→拖沓 |
| `min_damage` | 1 | 0-3 | 防御高于攻击时的保底伤害 |
| `meditation_efficiency` | 0.5 | 0.3-0.8 | 调息恢复效率 |
| `insight_bonus_per_point` | 1% | 0.5%-2% | 洞察对意图概率的加成 |

## Visual/Audio Requirements

- **意图公开**：敌人头顶浮现体系图标（刚=红色拳头、柔=蓝色水纹、巧=绿色风旋），"?"显示为灰色问号。配以"唰"的提示音
- **克制命中**：画面闪光 + 击打音效增强 + 伤害数字放大弹出
- **被克制**：画面微震 + 钝击音效 + 角色短暂后退
- **一击决胜**：全屏慢动作 + 特写镜头 + 专属招式动画 + 力量感音效爆发。每种体系的决胜一击有不同的演出风格（刚=劈裂、柔=旋涡、巧=瞬闪）
- **调息**：角色闭目静立 + 内息条缓慢回升的视觉效果 + 轻柔吐息音效
- **意图看破**：体系图标从模糊渐变为清晰（普通看破）；完全看破时图标金色高亮 + 招式名文字浮现
- **战斗背景音乐**：紧张节奏感 BGM，boss 战切换为更激昂的变奏
- **回合转换**：简短的"过招"音效标记回合分界

## UI Requirements

- **意图显示面板**：每个敌人头顶的体系图标（或"?"）
- **招式选择面板**：列出可用招式，每条显示：名称、体系图标（体系色）、内息消耗、**触发条件图标**（可快速识别条件类型）、**特殊效果摘要**；灰显内息不足的招式；额外显示"调息"、"普通攻击"、"使用道具"选项。**无品质颜色标注**，玩家根据条件和效果自行判断取舍
- **气血/内息/破绽条**：实时更新的资源条
- **反制按钮**：选择克制体系招式后出现"反制"选项
- **一击决胜提示**：当目标破绽达标时，高亮"决胜一击"选项
- **回合数显示**：当前回合 / 最大回合
- **伤害数字**：弹出式伤害数字（克制放大 + 变色，被克缩小）
- **协同提示**：两人同时克制同一目标时显示"协同！"字样
- **凝神守护提示**：己方角色凝神时，在其头顶显示剩余自然行动轮数，并在敌方可能攻击该角色时强化危险提示
- **敌群折叠显示**：敌方人数超过 5 时，非焦点敌人只显示精简 HP/意图图标；焦点目标和高威胁目标自动提升为概览层

## Acceptance Criteria

1. **GIVEN** 敌人公开刚系意图，玩家选择柔系招式，**WHEN** 结算，**THEN** 伤害乘以 1.3（±5%波动）且敌人获得 +2 破绽。
2. **GIVEN** 敌人破绽累积到 5，**WHEN** 玩家选择"决胜一击"，**THEN** 造成 ×2.0 伤害并播放专属动画。
3. **GIVEN** 玩家内息为 2，反制消耗 3，**WHEN** 查看反制按钮，**THEN** 反制按钮灰显不可选。
4. **GIVEN** 两个己方角色同回合克制同一目标，**WHEN** 结算，**THEN** 目标额外获得 +1 协同破绽。
5. **GIVEN** 战斗进行到第 15 回合，**WHEN** 回合结束，**THEN** 战斗结束，叙事处理为平局。
6. **GIVEN** 玩家方和敌方同回合气血归零，**WHEN** 结算，**THEN** 判定为"惜败"。
7. **GIVEN** 内息为 0 且有零消耗招式，**WHEN** 玩家查看招式面板，**THEN** 零消耗招式可选，同时"调息"也可选。
8. **GIVEN** 内息为 0 且无零消耗招式，**WHEN** 玩家查看招式面板，**THEN** 只有"调息"和"普通攻击"可选。
9. **GIVEN** 功力比为 0.6（模糊范围），**WHEN** 回合开始判定意图洞察，**THEN** 50% 概率看到体系图标，50% 显示"?"。每回合独立判定。
10. **GIVEN** 功力比 > 1.5，**WHEN** 意图公开，**THEN** 显示体系图标 + 具体招式名。
11. **GIVEN** 队伍可同行人数 ≥ 5，**WHEN** 战前配置上阵角色，**THEN** 玩家方最多可选择 5 人且主角不可下阵。
12. **GIVEN** 剧情配置 6 名以上敌人，**WHEN** 战斗初始化，**THEN** 战斗允许生成全部敌人，并按 UI 信息密度规则折叠非焦点目标。
13. **GIVEN** 角色选择凝神顿悟，**WHEN** 进入后续自然行动轮，**THEN** 该角色不能移动、出招、用道具、切换内功、调息或使用轻功，其他己方角色正常行动。
14. **GIVEN** 凝神角色撑过 epiphany_focus_turns，**WHEN** 凝神完成，**THEN** 发放顿悟奖励、悟后 buff，并刷新该角色普通技能冷却。
15. **GIVEN** 凝神角色在普通战斗中 HP ≤ 0，**WHEN** 结算落败，**THEN** 顿悟失败，不发放奖励、不刷新冷却、不设置完成 flag。
