# 敌方 AI

> **Status**: Approved
> **Author**: user + game-designer + ai-programmer
> **Last Updated**: 2026-06-03
> **Implements Pillar**: Pillar 3 — 武侠味先于游戏味（AI 行为像"高手过招"，不是数值机器）

## Overview

敌方 AI 是所有非玩家战斗角色的"大脑"——它决定每个敌人每回合出什么类型的招式（刚/柔/巧）、攻击谁、以及何时动用特殊能力。

在 Burst+Read 战斗中，AI 的角色独特而核心：它必须在回合开始时先确定自己的行动（`DecideAction`），然后将体系类型公开给玩家（`GetIntentType`）——这是"高手过招"信息不对称模型的另一半。玩家"读"的对象正是 AI 的决策。

因此，AI 行为必须同时满足两个看似矛盾的要求：**可读性**（行为有规律可循，让"读人"有意义）和**不可预测性**（不能退化为固定模式，否则每场战斗变成记忆题）。解决方案是"有个性的随机"——每类敌人有性格驱动的行为倾向（如刚猛型偏好连续进攻、柔韧型倾向防御反击），但在倾向框架内保留随机选择空间。

系统分为两个层级：
- **普通敌人**：基于性格模板的加权随机决策，行为简洁、可读性高，用于教学和练手
- **Boss**：多阶段行为模式 + 特殊机制（如优先攻击、体系锁定、破绽重置），每个 Boss 是一道独特的"谜题"

AI 从角色属性系统读取自身数值，从战斗系统获取场上状态（双方血量/内息/破绽），输出招式决策给战斗系统执行。它不直接与玩家交互，但玩家对战斗的全部"读"与"反制"体验都建立在 AI 的决策质量之上。

## Player Fantasy

**"这个对手不是随机出招的木桩——他有脾气、有偏好、有弱点，而我正在一招一招地读懂他。"**

在武侠小说中，高手对决最精彩的部分不是招式的花哨，而是"读人"——从对方握剑的方式推断他下一招是攻还是守，从他的步法预判他要走刚猛路线还是灵巧取胜。

敌方 AI 要给玩家的正是这种体验：

- **普通敌人是"可读的性格"**：刚猛的山贼就是一股蛮劲向前冲，你读到他连续两回合都出刚，第三回合你准备柔系反制——成功了。这不是背答案，而是"我懂你了"
- **Boss 是"层层揭开的谜题"**：第一阶段你被打得手忙脚乱，第二阶段你开始发现他的规律，第三阶段你胸有成竹地反击——这是"高手过招，越打越懂"的武侠体验
- **被 AI 读懂的恐惧**：当 Boss 突然改变了连续三回合的刚系模式，切入巧系打你措手不及——那一刻的"他也在读我"让战斗从单向博弈变成双向交锋

参考体验：
- 《Into the Breach》中每种虫子都有固定行为模式，你根据模式制定策略
- 《黑暗之魂》Boss 的"学习曲线"——第一次被打死、第三次摸清套路、第五次完美击杀
- 古龙小说中西门吹雪与叶孤城的"决战紫禁之巅"——两个顶尖高手互相试探、读意、最终一剑分胜负

## Detailed Design

### Core Rules

**1. AI 决策管线（两阶段模型）**

每回合每个敌人角色按以下管线决策。管线分为 **Phase A（选体系）** 和 **Phase B（否决与选招）**，求值顺序严格固定：

```
┌─ 蓄力检查（仅 Boss）───────────────────────────┐
│ ⓪ pending_charge 非空？                         │
│    → 是 → 直接执行已承诺招式，跳过 ①-⑨ 全部    │
│    → 否 → 继续下方管线                          │
└─────────────────────────────────────────────────┘

┌─ 前置检查 ─────────────────────────────────────┐
│ ① 调息检查：内息 ≤ meditation_threshold?        │
│    → 是 → 按 meditation_chance 概率选择调息      │
│    → 选择调息则跳过 Phase A/B，直接输出调息决策  │
└─────────────────────────────────────────────────┘

┌─ Phase A：选定体系（性格驱动）─────────────────┐
│ ② 读取战场上下文                                │
│    → 自身属性（HP/内息/破绽/可用招式）          │
│    → 所有角色当前状态（HP比、破绽比）           │
│    → 自身当前状态机状态 + 状态修正              │
│    → 招式预兆序列进度                           │
│                                                  │
│ ③ 计算各体系加权概率                            │
│    → 基础权重（性格模板）                        │
│    → + 当前状态修正                              │
│    → + 情境修正（目标相关）                      │
│    → + 连续同体系惩罚（首次重复 0，之后 -15/回合）│
│    → + 招式预兆加成（序列匹配时）               │
│    → 归一化为概率分布（min_type_weight 钳位）    │
│                                                  │
│ ④ 按概率随机选定体系                            │
└─────────────────────────────────────────────────┘

┌─ Phase B：否决检查 + 选招 ─────────────────────┐
│ ⑤ 反读否决：满足触发条件？                      │
│    → 是且概率命中 → 覆盖 Phase A 结果，         │
│       选用克制玩家最常用体系                     │
│    → 否 → 保持 Phase A 结果                     │
│                                                  │
│ ⑥ 选定目标（目标优先级评分 F3）                 │
│                                                  │
│ ⑦ 体系内选招：                                  │
│    → 从选定体系中筛选"内息足够的可用招式"       │
│    → 均匀随机选择一个                            │
│    → 如果该体系无可用招式 → 回退到其他体系中    │
│       有内息的招式，均匀随机                     │
└─────────────────────────────────────────────────┘

┌─ 输出 ─────────────────────────────────────────┐
│ ⑧ 写入 GetIntentType()（选定体系类型）          │
│    → 调息时：返回 Type.MEDITATION（特殊值）     │
│    → 蓄力执行时：返回 pending_charge 的体系类型 │
│ ⑨ 写入 DecideAction()（具体招式 + 目标）        │
└─────────────────────────────────────────────────┘
```

**求值顺序不变量**：蓄力检查 > 调息前置 > 性格权重 > 状态/情境修正 > 反读否决 > 选招。任何环节的结果被后续环节覆盖时，前序环节不回溯。

**"上回合体系"语义定义**：在整条管线中，"上回合使用的体系"统一指该敌人**上回合最终实际输出的体系类型**（即 `GetIntentType()` 的返回值）。如果上回合 Phase B 反读否决覆盖了 Phase A 的选择，则"上回合体系" = 反读后的最终输出，而非 Phase A 的原始选择。此语义适用于：连续同体系惩罚计数、警觉状态的"上回合体系 -20"修正、情境修正的"上回合被克制"判定、以及招式预兆序列的指针推进。

**2. 性格模板系统（Personality Templates）**

每个敌人定义一个性格模板，包含：

| 字段 | 说明 |
|---|---|
| `name` | 模板名（如"刚猛型"、"柔韧型"、"诡诈型"） |
| `base_weights` | 三体系基础权重（刚/柔/巧），总和为 100 |
| `weakness_type` | 弱点体系（刚/柔/巧之一）——被此体系击中时额外 +1 破绽 |
| `conditions[]` | 条件修正规则列表 |
| `counter_read_enabled` | 是否启用"反读"（默认 false，Boss 级开启） |
| `special_moves[]` | 可用特殊招式列表（优先攻击等） |

预设性格模板（MVP）：

| 模板名 | 刚/柔/巧权重 | 弱点体系 | 行为特征 | 适用角色 |
|---|---|---|---|---|
| 刚猛型 | 60/15/25 | 柔 | 正面硬刚为主，偶尔巧取；被柔系击中时额外暴露破绽 | 山贼、重甲卫士 |
| 柔韧型 | 15/55/30 | 巧 | 防守反击，偏好柔系回息；被巧系击中时额外暴露破绽 | 僧侣、内功高手 |
| 诡诈型 | 25/20/55 | 刚 | 机动灵活，偏好巧系高破绽；被刚系击中时额外暴露破绽 | 刺客、轻功高手 |
| Boss-自定义 | 按阶段变化 | 按阶段变化 | 每个 Boss 有独立行为脚本 | 各章 Boss |

> **均衡型（35/30/35）**暂不纳入 MVP。原因：5-15 回合内"无模式"不可被玩家感知为独立性格。后续版本如需加入，须先定义可感知的元规律（如"被克后必反读"或"每 3 回合切换偏好"）。

**最短可感知回合数估算**：完整的"读人弧"（观察 → 假说 → 测试 → 奖励）约需 4 回合。各性格模板因偏好强度不同，产生足够"可辨识信号"的最短回合数也不同：

| 性格模板 | 最短可感知回合 | 理由 |
|---|---|---|
| 刚猛型（60/15/25） | 3 回合 | 主体系概率 60%，前 3 回合有 ≈85% 概率出现 ≥2 次刚系 |
| 柔韧型（15/55/30） | 3-4 回合 | 主体系 55%，略低于刚猛型但仍有高辨识度 |
| 诡诈型（25/20/55） | 3-4 回合 | 主体系 55%，与柔韧型相当 |
| Boss（按阶段变化） | Phase 1 需 3-4 回合 | 均衡偏刚（40/25/35）的辨识度较低，依赖招式预兆序列补偿 |

> **关卡设计约束**：使用性格模板的普通战斗不应短于 5 回合（给"读人弧"至少 1 回合容错）。低于 5 回合的战斗建议使用固定行为脚本而非性格模板。

**弱点体系规则（Weakness Type）**：
每个性格模板定义一个弱点体系（`weakness_type`），遵循"偏好的克制者"规律——偏刚则弱柔，偏柔则弱巧，偏巧则弱刚。当敌人被弱点体系的招式命中时，额外 +1 破绽（叠加在正常克制/同系/被克结果之上）。

设计意图：让玩家"读懂性格"产生直接机械收益——识别出刚猛型山贼后，优先使用柔系攻击可更快累积破绽、更快触发一击决胜。性格不再只是 AI 内部的权重参数，而是玩家可利用的战术信息。

> **跨系统影响**：弱点体系的额外 +1 破绽由战斗系统在伤害结算阶段处理。`combat-system.md` 需追加一条破绽规则：`if attacker_type == target.weakness_type: target.stagger += 1`。

**3. 统一修正系统（状态修正 + 情境修正 + 连续惩罚）**

权重修正统一由**状态机**和**情境条件**驱动，不再有两套并存的独立系统。

**状态修正**（由当前行为状态决定，见"States and Transitions"）：

| 状态 | 自带修正 | 设计意图 |
|---|---|---|
| 正常 | 无 | 基础性格权重 |
| 警觉 | 当前体系 -20（倾向切换） | "被克制后求变" |
| 防御 | 柔系 +20 | "受伤后变谨慎" |
| 绝境 | 刚系 +30 | "拼死一搏" |

**情境修正**（每回合根据战场状态独立判定，与状态机无交叉）：

| 条件 | 权重修正 | 设计意图 |
|---|---|---|
| 自身破绽 ≥ 3 | 柔系 +15 | 模拟"危险时收招保守" |
| 目标破绽 ≥ 3 | 刚系 +20 | 模拟"看到破绽猛攻" |
| 上回合被克制 | 上回合所用体系 -30 | 性格内生的求变反应 |

**连续同体系惩罚**（渐进式软衰减，保留短期性格惯性）：

```
consecutive_penalty:
  连续 1 回合（首次重复）：0（无惩罚——性格模板的短期重复是"可读节奏"的一部分）
  连续 2+ 回合：(连续回合数 - 1) × -15
```

- 连续 1 回合：无惩罚（性格得以表达，如刚猛型连出两回合刚 = 符合预期）
- 连续 2 回合：该体系 -15（仍可能选中，性格顽固感保留）
- 连续 3 回合：该体系 -30（概率较低但非零）
- 连续 4+ 回合：该体系 -45+（几乎不可能，但配合 `min_type_weight=5` 仍有微小概率）

与 `min_type_weight=5` 共存——任何体系经钳位后最低仍有 5% 概率被选中。

> **设计原理变更**：原 -20/回合的惩罚在第 3 回合即可将刚猛型的刚系概率压至 33%（低于巧系），反噬了性格模板的可读性。新版首次重复零惩罚 + 后续 -15/回合，使刚猛型第 3 回合刚系概率仍为 ~53%（45/15/25 归一化），保持性格可辨识性。配合弱点体系，连续出招的"惯性"反而成为玩家可利用的战术窗口。

**计算方式**：基础权重 + 状态修正 + 情境修正 + 连续惩罚 → 各体系钳位到 min_type_weight → 归一化为概率分布。

**叠加声明**：状态修正与情境修正可叠加。极端场景下，警觉状态的"上回合体系 -20" + 情境修正的"上回合被克制 -30" 可叠加至 -50，使刚猛型的刚系从 60 降至 10。这是已知的设计权衡——当 AI 在警觉状态下又被克制时，极端地远离该体系是预期行为（"痛定思痛"），由 `min_type_weight=5` 兜底确保不归零。

**4. 反读系统（Counter-Intelligence）**

- **数据输入**：跟踪玩家方每个角色最近 3 回合的出招体系
- **分析**：计算玩家最常用体系（模式识别）
- **响应**：如果玩家连续 2+ 回合使用同一体系，AI 有概率（`counter_read_chance`）主动选择克制该体系的招式
- **限制**：
  - 普通敌人：`counter_read_enabled = false`，不反读
  - 精英敌人：`counter_read_chance = 20%`
  - Boss：`counter_read_chance = 25-40%`（按阶段递减——后期降低以给玩家收获精通的空间）
- **设计意图**：让玩家不能"找到一招打天下"，必须混合使用三体系

**5. 目标选择逻辑**

多人战斗中（如 3v4、5v6 或被围攻战），AI 按以下优先级选择目标：

| 优先级 | 条件 | 说明 |
|---|---|---|
| 1 | 目标破绽 ≥ 阈值 | 可一击决胜——立即锁定 |
| 2 | 目标 HP < 30% | 补刀优先 |
| 3 | 上回合对自己造成最高伤害的角色 | 仇恨/威胁机制 |
| 4 | HP 最高的角色 | 分散伤害（避免过快击杀） |

Boss 可覆盖目标选择逻辑（如"只攻击主角"、"随机切换"等）。

**6. Boss 行为系统**

Boss 不使用性格模板，而是用**阶段脚本（Phase Script）**：

```
Boss 定义：
├── Phase 1（HP 100%-60%）
│   ├── 行为模式："试探"
│   ├── 权重：均衡偏刚（40/25/35）
│   ├── 弱点体系：柔（Boss 脚本可覆盖）
│   ├── 特殊机制：无
│   └── 转换条件：HP ≤ 60%
├── Phase 2（HP 60%-30%）
│   ├── 行为模式："认真"
│   ├── 权重：偏巧（25/25/50）
│   ├── 弱点体系：柔（Boss 脚本可覆盖）
│   ├── 特殊机制：优先攻击（每 3 回合一次）
│   ├── counter_read_chance：40%
│   └── 转换条件：HP ≤ 30%
├── Phase 3a（HP 30%-15%）— "收获"
│   ├── 行为模式："穷途"
│   ├── 权重：偏刚但可读（50/20/30）
│   ├── 弱点体系：柔（Boss 脚本可覆盖）
│   ├── 特殊机制：体系锁定更频繁（每 2 回合一次）+ 蓄力预告频率 ×2
│   ├── counter_read_chance：30%（降低——给玩家收获精通的空间）
│   ├── 破绽阈值提升至 7
│   └── 转换条件：HP ≤ 15%
└── Phase 3b（HP 15%-0%）— "绝境爆发"
    ├── 行为模式："殊死"
    ├── 权重：极端偏刚（70/10/20）
    ├── 弱点体系：柔（与前阶段一致，跨阶段弱点知识可迁移。Boss 脚本可覆盖）
    ├── 特殊机制：忽略连续同体系惩罚 + 优先攻击冷却减至 1 回合
    ├── counter_read_chance：25%（降低——绝境下 Boss 弃守全攻，行为更可读但每一击更致命。玩家的精通来自前几阶段学到的弱点利用，而非 AI 主动放水）
    ├── 破绽阈值不变（7）
    └── 转换条件：HP = 0
```

**Boss 特殊机制清单：**

| 机制 | 说明 | 设计意图 |
|---|---|---|
| 优先攻击（Priority Strike） | Boss 的该招在所有角色之前结算，无视同时结算规则 | 打破节奏，制造压力 |
| 体系锁定（Type Lock） | 软锁：锁定期间目标体系偏好提升至 65%，非硬性 100%（详见下方完整规格） | 给玩家"读"的窗口——推断而非白送答案 |
| 破绽重置（Stagger Reset） | 阶段转换时破绽归零 | 防止跨阶段积累一击决胜 |
| 破绽阈值调整 | 特定阶段提高/降低阈值 | 控制一击决胜的可达性 |
| 蓄力预告（Charge Announce） | Boss 在预告回合选择并承诺下回合招式，下回合直接执行已承诺招式（详见下方完整规格） | 给玩家紧急应对的选择窗口 |
| 内息吸取 | 攻击命中时额外吸取玩家 1 内息 | 资源压力 |

**6a. 体系锁定完整规格（Type Lock Specification）**

体系锁定是 Boss 的阶段性"偏执"行为——锁定期间 Boss 强烈偏好某一体系，但并非 100% 确定。这给玩家"推断"的窗口（≈65% 命中预测），而非"白送答案"。

| 属性 | 值 | 说明 |
|---|---|---|
| 触发方式 | Boss 脚本声明 | Phase 3a 每 `type_lock_cooldown` 回合触发一次（默认 2 回合） |
| 锁定体系选择 | 当前阶段权重最高的体系 | Boss 脚本可覆盖为指定体系 |
| 锁定强度 | 软锁（`type_lock_bias=65`） | 目标体系权重设为 65，其余两体系按原比例分配剩余 35 |
| 持续回合数 | `type_lock_duration`（默认 2） | 锁定结束后进入冷却 |
| 连续惩罚 | 锁定期间暂停 | 锁定结束后惩罚计数从 0 重新开始 |
| 反读交互 | 锁定期间反读概率减半 | Phase B 反读仍可否决锁定体系，但概率较低 |
| 阶段转换 | 锁定状态清除 + 冷却重置 | 新阶段从零开始计算锁定触发 |
| 序列指针 | 正常推进 | 锁定不影响招式预兆序列的追踪 |

**锁定期间 Phase A 权重计算**：

```
if type_lock_active:
    locked_type_weight = type_lock_bias  # 默认 65
    remaining = 100 - type_lock_bias     # 默认 35
    # 其余两体系按原始基础权重比例分配 remaining
    other_ratio = base_weight[other1] / (base_weight[other1] + base_weight[other2])
    other1_weight = remaining × other_ratio
    other2_weight = remaining × (1 - other_ratio)
    # 状态修正和情境修正照常叠加（在锁定权重之上）
    # 连续惩罚不叠加（暂停）
```

**设计意图**：65% 偏好而非 100% 硬锁确保玩家需要"推断"而非"确信"——符合武侠"观敌路数"幻想。玩家读到锁定后选择克制体系，有 ≈65% 的概率是对的，35% 的概率被打意外——这个不确定性正是张力所在。

**6b. 蓄力预告完整规格（Charge Announce Specification）**

蓄力预告采用"预承诺"架构：Boss 在预告回合选择并锁定下一回合的招式，预告回合本身执行一个防御性/蓄力性动作。

**管线扩展**：在现有管线前置检查之前新增 `⓪ 蓄力检查`：

```
⓪ 蓄力检查：pending_charge 非空？
   → 是 → 直接执行 pending_charge 招式，跳过 ①-⑨ 全部管线
   → 否 → 继续正常管线
```

**预告回合行为**：

| 阶段 | 行为 | 说明 |
|---|---|---|
| 触发 | Boss 脚本在特定回合声明预告（`charge_frequency` 控制频率） | Phase 2 首次可用；Phase 3a 频率 ×2 |
| 预告回合决策 | Boss 选择下一回合的具体招式，写入 `pending_charge` | 选招走正常 Phase A/B 管线，但结果不立即执行 |
| 预告回合行动 | Boss 本回合执行一个蓄力动作（防御姿态，内息回复 1 点） | 非正常攻击，降低本回合威胁，给玩家准备时间 |
| 预告信息公开 | `GetChargeAnnounce() → MoveName` 输出下回合招式名称 | 战斗 UI 显示招式名（不仅是体系类型） |
| 下一回合 | `⓪ 蓄力检查`命中，直接执行已承诺招式 | 跳过全部管线，`GetIntentType()` = 已承诺招式的体系 |
| 打断条件 | 如果预告回合 Boss 被一击决胜 / 阶段转换，`pending_charge` 清空 | 蓄力被打断是有效的反制策略 |

**与反读交互**：预告回合的选招过程可被反读否决（反读可能改变承诺的招式体系）。一旦承诺写入 `pending_charge`，下回合执行时不再做二次判定。

**7. 招式预兆系统（Signature Patterns）— 可读性核心机制**

每种性格模板拥有 1-2 个**标志性行为序列**——不是硬性脚本，而是通过权重加成使其在自然随机中更容易涌现的节奏模式。

| 性格模板 | 标志序列 | 序列加成 | 设计意图 |
|---|---|---|---|
| 刚猛型 | 刚→刚→(任意) | 序列匹配时当前步骤体系 +25 | "蛮牛冲锋"节奏 |
| 柔韧型 | 柔→巧→柔 | 序列匹配时当前步骤体系 +25 | "以退为进"节奏 |
| 诡诈型 | 巧→刚→巧 | 序列匹配时当前步骤体系 +25 | "虚实交替"节奏 |

**序列判定规则**：
- AI 维护一个隐藏的"序列进度指针"
- 每次 AI 的实际出招（不论是否由序列加成促成）匹配序列下一步时，指针前进
- 指针完成整个序列后重置
- 序列加成仅在战斗前 4 回合额外 ×1.5（**开场强调**：确保短战斗中玩家有足够信号）

**洞察反馈（"读破！"）**：
- **触发条件**：玩家在**敌人意图公开后**，选择了克制该敌人公开体系的招式，且连续 2 回合正确预判（即"我看到你出刚，所以我选柔"的认知行为）
- **判定时机**：意图公开 → 玩家选招 → 结算前。判定的是"玩家的选择是否克制了公开的意图体系"，不论实际伤害结果
- 触发后 UI 弹出"读破！"反馈，该敌人本场剩余回合的意图洞察概率 +20%（让"读懂"有实际收益）
- 此机制不影响 AI 的决策——只影响玩家获取信息的清晰度
- **设计意图**：奖励的是"我识别了你的模式"这一认知行为，而非"我碰巧连出了同一招"。乱按的玩家不会触发读破——只有观察到意图后做出针对性选择的玩家才会获得此奖励

**设计意图**：解决"5-15 回合内如何让玩家感知性格"的核心问题。标志序列 = 性格的"招牌节奏"，玩家可以像武侠小说中的高手一样，从对手的前几招推断其路数。

**8. 防止退化策略（Anti-Degenerate）**

以下机制确保 AI 行为不会产生"必胜公式"或"无意义"的局面：

- **连续同体系渐进惩罚**：首次重复无惩罚，之后每回合 -15 权重（累积）。性格极端者仍可能顽固连用，但概率自然衰减（替代原硬性强制换规则）
- **弱点体系天然反轮换**：机械轮换（刚→柔→巧→...）只有 1/3 概率命中弱点体系，而"读懂性格后优先打弱点"的策略可持续获得额外破绽——不需要"读人"的轮换策略在弱点体系面前收益显著低于有针对性的策略
- **反制冷却**：AI 的反读触发后，下一回合反读概率减半
- **调息智能**：当内息 ≤ meditation_threshold 时，按 meditation_chance 概率选择调息（管线前置检查）
- **不追杀玩家**：如果己方有多个目标，AI 不会全部集中攻击同一个（除非该目标破绽达标）

**9. 玩家感知信号层（Observable Tells）**

AI 的决策品质只有在玩家可感知时才有意义。以下定义了每个关键 AI 行为对应的玩家侧信号——信号必须在玩家可行动之前到达，使应对基于"我观察到了"而非"我碰巧选对了"。

| AI 行为 | 玩家侧 Tell | 信号时机 | 承载系统 |
|---|---|---|---|
| **反读触发** | Boss 做出"凝视"演出（眼神闪光 + 短暂停顿 ≤0.5 秒），意图公开图标附加"洞察"标记（⊙） | 意图公开时 | 战斗 UI |
| **性格偏好涌现** | 敌人连续 2+ 回合出同一体系时，该体系图标获得"惯性"视觉强调（渐亮边框） | 第 2 次连续时开始 | 战斗 UI |
| **体系锁定激活** | Boss 头顶出现"执念"状态图标 + 短演出（气场集中），锁定期间图标每回合脉动 | 锁定触发时 | 战斗 UI |
| **蓄力预告** | 蓄力回合显示具体招式名 + 蓄力进度条（1 回合倒计时） | 预告回合开始时 | 战斗 UI |
| **绝境爆发** | Boss 进入 Phase 3b 时播放"狂化"演出 + 持续暗红色调氛围变化 | 阶段转换时 | CG/演出 |
| **弱点体系命中** | 命中弱点时的额外破绽 +1 有独立视觉反馈（金色破裂特效 + "弱点！"文字） | 伤害结算时 | 战斗 UI |

**设计原则**：
- **信号 ≠ 答案**：tell 暗示 AI 的行为模式，但不直接告诉玩家"正确操作是什么"。玩家需要从 tell 推断应对策略。
- **渐进式信息量**：普通敌人的 tell 简单直白（性格偏好强调）；Boss 的 tell 层次更丰富（反读凝视 + 锁定执念 + 蓄力预告），对应更深的"读"体验。
- **跨系统协作**：tell 的视觉/音频表现由战斗 UI GDD 和 CG/演出系统定义。本 GDD 仅定义 tell 的触发条件和语义。

> **跨系统依赖**：战斗 UI GDD 需新增上述 6 类 tell 的视觉规格。AI 系统通过以下事件通知战斗 UI：`OnCounterReadTriggered(enemy_id)`、`OnTypeLockActivated(enemy_id, locked_type)`、`OnChargeAnnounced(enemy_id, move_name)`、`OnDesperatePhaseEntered(enemy_id)`、`OnWeaknessHit(enemy_id, attacker_type)`。性格偏好涌现由战斗 UI 自行根据连续体系记录判定（无需 AI 事件）。

### States and Transitions

**普通敌人状态机**（唯一修正来源，不与条件修正表重叠）：

| 状态 | 进入条件 | 退出条件 | 自带修正 |
|---|---|---|---|
| **正常** | 战斗开始 | 见下方转换 | 无 |
| **警觉** | 单场战斗中累计被克制 ≥ 2 次 | HP < 40% 进入防御 / 不可退回正常 | 上回合体系 -20 |
| **防御** | HP < 40% | HP < 15% 进入绝境 / 不可退回 | 柔系 +20 |
| **绝境** | HP < 15% | 战斗结束 | 刚系 +30（且一击决胜条件满足时优先选择高伤害招式） |

```
[正常] →（累计被克制 ≥ 2 次）→ [警觉]
[正常/警觉] →（HP < 40%）→ [防御]
[防御] →（HP < 15%）→ [绝境]
```

状态转换为单向不可逆（一场战斗内），避免状态回退导致行为抖动。

**Boss 状态：**

```
[Phase 1] →（HP ≤ 阶段阈值）→ [Phase Transition（破绽重置 + 短暂无敌演出）]
   → [Phase 2] → ... → [Phase N] → [落败]
```

Boss 阶段转换时：
- 清空所有破绽
- 播放阶段转换动画（约 2 秒，双方不可行动）
- 可能解锁新招式或新机制

## Formulas

### F1. 体系选择概率（Type Selection Probability）

```
raw_weight[type] = base_weight[type] + state_modifier[type] + situational_modifier[type] + consecutive_penalty[type] + signature_bonus[type]
clamped_weight[type] = max(min_type_weight, raw_weight[type])
P(type) = clamped_weight[type] / Σ clamped_weight[all types]
```

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| base_weight | `bw` | int | 0-100 | 性格模板中的体系基础权重 |
| state_modifier | `sm` | int | -20 to +30 | 当前状态自带修正 |
| situational_modifier | `cm` | int | -30 to +20 | 战场情境修正（目标相关） |
| consecutive_penalty | `cp` | int | 无下界 to 0 | 首次重复 0，之后 (连续回合数-1) × consecutive_penalty_per_round。理论无下界，由 min_type_weight 钳位兜底 |
| signature_bonus | `sb` | int | 0 to +80 | 招式预兆序列匹配加成 floor(signature_bonus × signature_opening_multiplier)。默认 floor(25×1.5)=37，Tuning Knobs 极值 floor(40×2.0)=80 |
| min_type_weight | — | int | 5 | 钳位下限 |

**Output Range**: min_type_weight/(3×min_type_weight) ~ max/(sum) ≈ 4%-94%（三体系之和恒为 100%。极端情况下单体系 raw_weight 可达 60+30+20+37=147，其余两系钳位到 5，概率上限约 147/157≈94%）
**Example**: 刚猛型（60/15/25），防御状态（柔+20），无连续惩罚 → 60/35/25 → 归一化 50%/29%/21%

### F2. 反读触发概率（Counter-Read Trigger）

```
if player_used_same_type >= 2 consecutive rounds:
    trigger_chance = min(1.0, counter_read_chance × (1 - cooldown_penalty))
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| counter_read_chance | float | 0-0.8 | 敌人的反读基础概率（普通=0，精英=0.2，Boss=0.25-0.4 按阶段递减，Tuning Knobs 上限 0.8） |
| cooldown_penalty | float | 0 or 0.5 | 上回合已触发反读时为 0.5（冷却减半） |

**Output Range**: 0%-80%（含 Tuning Knobs 极端值；默认配置下 0%-40%）
**Example**: Boss Phase 2（0.4），无冷却 → 40% 概率反读。上回合已反读 → 0.4 × 0.5 = 20%

**Phase B 否决行为**：如果反读触发，覆盖 Phase A 选定的体系，改为选择克制玩家最常用体系的招式。如果克制体系无内息可用招式，反读失败，保持 Phase A 结果。

**多人战反读规则**：AI 对每个玩家角色独立维护出招历史窗口。反读触发判定时，取**所有玩家角色中连续同体系回合数最高者**的数据。克制的目标体系 = 该玩家角色最常用的体系。如果多个玩家角色同时满足触发条件（连续 2+ 回合同体系），取 `counter_read_chance` 最高的那次判定（不叠加多次判定）。

### F3. 目标优先级评分（Target Priority Score）

```
score = decisive_bonus + kill_bonus + threat_bonus + spread_penalty
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| decisive_bonus | int | 0 or f3_decisive_bonus | 目标破绽 ≥ 阈值时 +f3_decisive_bonus（可调，见 Tuning Knobs） |
| kill_bonus | int | 0 or f3_kill_bonus | 目标 HP < 30% 时 +f3_kill_bonus（可调，见 Tuning Knobs） |
| threat_bonus | int | 0-f3_threat_cap | min(f3_threat_cap, 上回合该目标对自身造成伤害 × f3_threat_pct)（向下取整）（可调，见 Tuning Knobs） |
| spread_penalty | int | f3_spread_penalty or 0 | 如果已有队友攻击该目标且该目标非破绽达标 → f3_spread_penalty（可调，见 Tuning Knobs） |

**spread_penalty 求值顺序**：多敌人场景下，AI 决策按场上位置**从左到右顺序求值**（非同时）。第 1 个敌人的 spread_penalty 始终为 0；第 2+ 个敌人在求值时，可看到前序敌人已选定的目标。这是唯一一处顺序依赖的决策环节——其余管线（Phase A/B）对每个敌人独立求值。

**Output Range**: f3_spread_penalty to (f3_decisive_bonus + f3_kill_bonus + f3_threat_cap)（默认 -20 to 200）
选择得分最高的目标。平分时随机。

### F4. 调息决策阈值（Meditation Threshold）

```
if current_neixi <= meditation_threshold:
    meditation_chance = min(100%, meditation_base_chance + (meditation_threshold - current_neixi) × 10%)
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| meditation_threshold | int | 2（可调 1-4） | 内息低于等于此值时考虑调息 |
| meditation_base_chance | float | 40%（可调 20%-70%） | 基础调息概率 |
| current_neixi | int | 0-145 | 当前内息 |

**Output Range**: 20%-100%（含钳位；默认 meditation_base_chance=40% 时为 40%-70%，安全范围下限 20% 时最低 20%）
**Example**: threshold=2, neixi=2 → 40%; neixi=1 → 50%; neixi=0 → 60%
**Boundary**: threshold=4, neixi=0 → min(100%, 40%+40%) = 80%

**调息行为表现**：AI 调息不是"原地打坐"——武侠高手在险境中"以退为进"。调息回合 AI 采取防御反击姿态：视觉上表现为后撤半步 + 运气，期间 AI 仍占据场上位置（不是跳过回合）。调息回合 AI 的防御力 +20%（由战斗系统结算），体现"蓄势待发"。这保证调息回合对玩家仍有战术意义——不是白送的输出回合。

**调息恢复量**：AI 调息时回复的内息量 = 角色属性系统的 `neixi_recovery` 派生属性（公式：`2 + 内力×0.2`，详见 `character-attributes.md` F6）。由战斗系统的调息结算逻辑处理（`combat-system.md` F8: `meditation_recovery = ceil(neixi_recovery × 0.5)`）。

**死锁防护**：如果 AI 连续 3 回合选择调息（未使用任何招式），第 4 回合强制跳过调息检查，进入 Phase A 正常决策。即使选出的招式内息不足，回退到零消耗招式或普通攻击。此规则防止低恢复 + 高消耗招式组合下 AI 永久停战。

## Edge Cases

- **If 所有可用招式的内息消耗 > 当前内息**：AI 选择调息。如果有零消耗招式，80% 概率使用零消耗招式，20% 概率调息。
- **If 反读触发但克制体系无可用招式（内息不足）**：反读失败（Phase B 否决不生效），保持 Phase A 结果。
- **If Phase A 选定的体系无内息可用招式**：回退到其他体系中有内息的招式，均匀随机选择。如果所有招式都无法支付，使用调息。
- **If Boss 阶段转换的同一回合 AI 已做出决策**：决策仍然执行（阶段转换在回合结束时生效，不会回溯当前回合的决策）。
- **If 两个玩家角色同回合对 AI 触发一击决胜条件**：AI 的目标选择不受此影响——AI 在回合开始时已做出决策，不会在结算阶段更改。
- **If 多个敌人同时面对同一个破绽达标的目标**：每个敌人独立决策（按场上位置左到右顺序处理 spread_penalty）。可能出现多个敌人集中攻击同一目标——这是预期行为（"群狼扑虎"）。
- **If 玩家近 3 回合使用了 3 种不同体系**：反读系统不触发（无"连续同体系"模式可读），AI 按正常 Phase A 决策。
- **If Boss 的体系锁定与连续同体系惩罚冲突**：体系锁定期间暂停连续同体系惩罚计数。锁定结束后惩罚从 0 重新开始。体系锁定是 Boss 的设计意图行为。
- **If Boss 蓄力预告回合被一击决胜或触发阶段转换**：`pending_charge` 清空，蓄力被打断。阶段转换后 Boss 以新阶段参数重新决策。
- **If Boss 阶段转换时体系锁定激活**：锁定状态清除，锁定冷却重置。新阶段从零开始计算锁定触发。
- **If 战斗只剩最后 1 回合（第 15 回合）**：AI 行为不变。不做"最后一搏"的特殊逻辑——15 回合上限的叙事处理由战斗系统负责。
- **If 修正叠加使某一体系 raw_weight ≤ 0**：钳位到 min_type_weight（默认 5），确保任何体系都有微小概率被选中。
- **If Boss 进入 Phase Transition 时玩家发动一击决胜**：一击决胜先结算（在阶段转换触发之前），可能直接跳过下一阶段或击杀 Boss。
- **If 招式预兆序列进度被反读否决打断**：序列指针停滞在当前位置（不前进也不后退）。反读回合视为"AI 被迫中断节奏但未忘记路数"。下回合如果 AI 回归正常决策并匹配序列下一步，指针继续推进。
- **If Boss Phase 3b（绝境）忽略连续惩罚导致长期连刚**：这是预期行为——绝境 Boss 弃守全攻、以命相搏，行为可读但容错归零（优先攻击冷却=1 回合使每回合都有即死威胁）。反读概率降至 25%。玩家此时的优势来自前几阶段积累的弱点知识——终局不是 AI 放水，而是玩家兑现精通。

- 属性系统 → AI：所有 Get 接口（HP/内息/破绽/攻击/防御）

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 过高/过低影响 |
|---|---|---|---|
| `min_type_weight` | 5 | 1-15 | 过低→极端惩罚下某体系接近 0%；过高→性格差异不明显 |
| `consecutive_penalty_per_round` | -15 | -5 to -30 | 过低→连续同体系太容易；过高→性格被惩罚压制。首次重复无惩罚，此值从第 2 次重复开始生效 |
| `hp_defensive_threshold` | 40% | 25%-60% | 过低→AI 不知道自保；过高→太早变保守 |
| `hp_desperate_threshold` | 15% | 5%-25% | 影响"绝境拼杀"的触发时机 |
| `stagger_defensive_threshold` | 3 | 2-4 | 影响 AI 何时开始保护破绽（情境修正触发） |
| `counter_read_chance_elite` | 20% | 10%-35% | 精英敌人的反读能力 |
| `counter_read_chance_boss_phase2` | 40% | 25%-60% | Boss Phase 2 反读概率 |
| `counter_read_chance_boss_phase3a` | 30% | 20%-50% | Boss Phase 3a "收获"阶段反读概率（降低——给玩家收获精通的空间） |
| `counter_read_chance_boss_phase3b` | 25% | 15%-40% | Boss Phase 3b "绝境"阶段反读概率（最低——绝境下更可读） |
| `counter_read_cooldown` | 50% | 30%-70% | 反读冷却惩罚（连续反读概率衰减） |

| `boss_stagger_threshold_override` | 7 | 5-10 | Boss Phase 3+ 的破绽阈值 |
| `priority_strike_cooldown` | 3 | 2-5 | 优先攻击间隔回合数（Phase 3b 可降至 1） |
| `type_lock_duration` | 2 | 1-3 | 体系锁定持续回合数 |

| `type_lock_cooldown` | 2 | 1-4 | 体系锁定触发间隔回合数 |
| `charge_frequency_phase2` | 4 | 3-6 | Phase 2 蓄力预告间隔回合数 |
| `charge_frequency_phase3a` | 2 | 1-4 | Phase 3a 蓄力预告间隔回合数（Phase 3a 频率 ×2） |
| `signature_bonus` | 25 | 15-40 | 招式预兆序列匹配时的权重加成（与 opening_multiplier 相乘后向下取整） |
| `signature_opening_multiplier` | 1.5 | 1.0-2.0 | 前 4 回合序列加成的额外倍率 |
| `read_insight_bonus` | 20% | 10%-30% | "读破！"触发后的洞察概率加成 |
| `f3_decisive_bonus` | 100 | 50-200 | F3 目标破绽达标时的优先级加成 |
| `f3_kill_bonus` | 50 | 25-100 | F3 目标 HP < 30% 时的优先级加成 |
| `f3_threat_pct` | 30% | 15%-50% | F3 上回合伤害转化为威胁分数的系数 |
| `f3_threat_cap` | 50 | 30-80 | F3 威胁分数上限 |
| `f3_spread_penalty` | -20 | -40 to -10 | F3 重复攻击同一非破绽达标目标的惩罚 |

- **反读"凝视"tell**（眼神闪光 + 短暂停顿 ≤0.5 秒 + "洞察"标记）由战斗 UI 负责

## Acceptance Criteria

1. **GIVEN** 刚猛型敌人（权重 60/15/25），无修正、无连续惩罚，**WHEN** 运行 1000 回合模拟（seeded random），**THEN** 刚系出招频率在 57%-63% 范围内（95% CI, n=1000, p=0.6, σ≈0.0155）。
2. **GIVEN** 敌人进入"防御"状态（HP < 40%），**WHEN** 提取 Phase A 的 raw_weight，**THEN** 柔系 raw_weight = base_weight[柔] + 20，且无其他来源重复添加此修正。
3. **GIVEN** 敌人连续 2 回合使用刚系（consecutive_penalty = (2-1)×-15 = -15），**WHEN** 第 3 回合 Phase A 计算刚系权重，**THEN** 刚系 raw_weight = base_weight[刚] - 15，经钳位后仍 ≥ min_type_weight(5)。
4. **GIVEN** Boss 反读概率 40%，玩家连续 2 回合使用柔系，无冷却，**WHEN** 运行 1000 次 Phase B 反读判定，**THEN** 反读触发次数在 370-430 次范围内（95% CI, n=1000, p=0.4）。
5. **GIVEN** Boss HP 降至 60% 阈值，**WHEN** 当前回合结算结束，**THEN** 触发阶段转换：破绽归零 + 请求转换动画 + AI 切换到 Phase 2 行为参数。
6. **GIVEN** 多人战斗中目标 A 破绽 = 5（达标）、目标 B HP = 满血，**WHEN** F3 计算优先级评分，**THEN** 目标 A 得分 ≥ 100，目标 B 得分 = 0，AI 选择目标 A。
7. **GIVEN** AI 内息 = 1（≤ meditation_threshold=2，meditation_base_chance=40%，故 meditation_chance=50%），**WHEN** 运行 1000 次前置调息检查（seeded random），**THEN** 调息触发次数在 469-531 次范围内（95% CI, n=1000, p=0.5, σ≈0.0158），且触发时跳过后续管线。
8. **GIVEN** 刚猛型敌人（标志序列：刚→刚→任意），战斗第 1 回合，**WHEN** Phase A 计算权重，**THEN** 刚系权重包含 floor(signature_bonus(25) × opening_multiplier(1.5)) = +37 的额外加成。
9. **GIVEN** 敌人意图公开为刚系，玩家在意图公开后选择了柔系招式（克制刚），且上一回合也做出了正确克制选择（连续 2 回合正确预判），**WHEN** "读破！"条件判定（意图公开→玩家选招→结算前），**THEN** 触发 `OnReadBreak(enemy_id)` 事件 + 该敌人剩余回合意图洞察概率（combat-system F9 的 `base_chance`）+20%（加算，不超过 100%）。
10. **GIVEN** 修正叠加使某体系 raw_weight = -15，**WHEN** F1 钳位计算，**THEN** clamped_weight = min_type_weight(5)。
11. **GIVEN** Boss Phase 3a（HP 25%），体系锁定激活（锁定体系=刚，type_lock_bias=65），**WHEN** Phase A 计算权重，**THEN** 刚系权重基准为 65（非原 base_weight），其余两体系按原比例分配 35；连续同体系惩罚暂停（不叠加）。
12. **GIVEN** Boss Phase 3b（HP 10%），**WHEN** AI 决策，**THEN** 连续同体系惩罚被忽略 + 优先攻击冷却 = 1 回合 + counter_read_chance = 25%。
13. **GIVEN** 敌人累计被克制 2 次，当前状态为"正常"，上回合最终输出体系为刚系，**WHEN** 状态转换判定，**THEN** 进入"警觉"状态，刚系 -20 修正生效（"上回合体系"= 上回合 `GetIntentType()` 的返回值）。
14. **GIVEN** 敌人处于"防御"状态（HP < 40%），HP 降至 14%（< 15%），**WHEN** 状态转换判定，**THEN** 进入"绝境"状态，刚系 +30 修正生效。
15. **GIVEN** 刚猛型敌人（weakness_type = 柔），被柔系招式命中，**WHEN** 破绽结算，**THEN** 在正常克制/同系/被克的破绽变化之外，额外 +1 破绽（如柔克刚：正常 +2 + 弱点 +1 = 守方 +3 破绽）。
16. **GIVEN** Phase A 选定巧系，但巧系所有招式内息消耗 > 当前内息，**WHEN** 选招阶段回退，**THEN** 从刚/柔系中筛选内息可用招式均匀随机选择。如果全部招式不可用，选择调息。
17. **GIVEN** Boss 体系锁定激活（type_lock_bias=65，锁定刚系，持续 2 回合），**WHEN** 锁定结束后下一回合，**THEN** 连续同体系惩罚计数从 0 重新开始（锁定期间惩罚暂停，不计入连续回合数）。
18. **GIVEN** Boss Phase 2 蓄力预告激活，**WHEN** 预告回合，**THEN** AI 通过正常 Phase A/B 管线选定下回合招式并写入 `pending_charge`，本回合执行蓄力动作（非攻击），通过 `GetChargeAnnounce() → MoveName` 输出下回合招式名称。下一回合 `⓪ 蓄力检查`命中，直接执行 `pending_charge` 招式，跳过全部管线。
19. **GIVEN** AI 连续 3 回合选择调息（未使用任何攻击招式），**WHEN** 第 4 回合前置调息检查，**THEN** 强制跳过调息，进入 Phase A 正常决策。
20. **GIVEN** 5v6 多人战，玩家角色 A 连续 2 回合使用柔系、角色 B 使用混合体系，Boss counter_read_chance=40%，**WHEN** Phase B 反读判定，**THEN** 基于角色 A 的数据触发反读（选择克柔的巧系），角色 B 的数据不触发（无连续同体系）。

21. **GIVEN** Boss 上回合反读已触发（cooldown_penalty=0.5），counter_read_chance=40%，玩家本回合仍连续同体系，**WHEN** Phase B 反读判定，**THEN** 实际触发概率 = 40% × (1 - 0.5) = 20%。运行 1000 次判定（seeded random），触发次数在 175-225 范围内（95% CI, n=1000, p=0.2）。
22. **GIVEN** Boss Phase 3a 体系锁定激活（锁定刚系，剩余 1 回合），HP 降至 15% 触发阶段转换到 Phase 3b，**WHEN** 阶段转换处理，**THEN** 锁定状态清除 + 锁定冷却重置 + 破绽归零 + Phase 3b 参数生效。下一回合 Phase A 不再使用锁定权重。
23. **GIVEN** 刚猛型敌人（weakness_type = 柔），被**非弱点体系**（刚系或巧系）命中，**WHEN** 破绽结算，**THEN** 不额外 +1 破绽（弱点加成仅在命中弱点体系时生效）。
24. **GIVEN** Boss 反读触发，**WHEN** 反读生效回合的意图公开，**THEN** 触发 `OnCounterReadTriggered(enemy_id)` 事件，战斗 UI 可据此显示"凝视"tell 信号。
