# 角色属性 / 功力

> **Status**: Designed
> **Author**: user + game-designer + systems-designer
> **Last Updated**: 2026-06-16
> **Implements Pillar**: 全部（战斗公式 / 心境成长 / 文学 UI 的数据根基）

## Overview

**角色属性 / 功力** 是整个游戏的数值根基 —— 一个集中管理所有可战斗角色（玩家、同伴、敌人）核心数据的系统。它不直接呈现给玩家，而是为下游系统（行气战棋战斗、武学组合、队伍管理、敌方 AI、自然日+体力、物品/道具、朦胧化 UI）提供统一的属性定义、数值访问和成长规则。

玩家不与本系统直接交互。玩家"感受到"属性的方式是：战斗中的伤害数字、朦胧化 UI 中"炉火纯青"或"登堂入室"这样的境界文学描述、以及角色随章节成长带来的战斗策略变化。

没有本系统，战斗无法计算伤害、武学搭配没有数值基础、朦胧化 UI 不知道把什么翻译成文学语言——整个 gameplay 层失去了数据来源。

## Player Fantasy

本系统是纯基础设施——玩家永远不会看到"你的攻击力是 47"这样的裸数值。他们感受到的是下游系统传递的体验：

- **通过战斗感受（战内清晰）**：进入战斗后，HP / 内息 / 破绽条和伤害数字完全透明。一招"断水寒光"打出 3 格破绽——这背后是战斗系统读取属性快照后的结算结果
- **通过朦胧化 UI 感受（战外朦胧）**："你已踏入化劲之境"——这是功力总值映射为境界文学。对敌时看到"此人内力深厚，不可小觑"——这是属性系统输出的**相对强度比较**经朦胧化 UI 翻译后的结果
- **通过成长感受**：第三章的主角明显比第一章强，因为属性随章节和顿悟积累

设计目标不是创造情感体验，而是确保上述情感体验有一致、可调、可预测的数值基础。"该不该打"的判断权交给朦胧化 UI 和叙事系统，属性系统只提供准确数据。

## Detailed Design

### Core Rules

**1. 属性分类**

所有可战斗角色（玩家、同伴、敌人）共享统一的属性结构，分为三层：

| 层 | 名称 | 说明 |
|---|---|---|
| **资源属性** | 可进入战斗快照的角色资源 | HP、内息 |
| **基础属性** | 角色的内在能力（五维） | 力量、敏捷、内力、洞察、体魄 |
| **派生属性** | 由基础属性 + 装备 + 心法计算得出 | 攻击、防御、行气增长、暴击、内息回复、功力总值 |

**2. 资源属性（战斗资源）**

| 属性 | 代号 | 说明 | 初始值 | 最大值来源 |
|---|---|---|---|---|
| 气血 (HP) | `hp` | 生命值。归零→落败 | 100 | `base_hp + 体魄×4` |
| 内息 (NeiXi) | `neixi` | 招式、轻功、道具等战斗行动的能量池。调息可回复内息 | 20 | `base_neixi + 内力×2` |

- 破绽 (`stagger`) 是 Combat 战斗临时态，不由属性系统持有当前值、阈值或衰减规则
- 内息调息/自然回复量 = `neixi_recovery` 派生属性

**3. 基础属性（五维）**

| 属性 | 代号 | 对应体系 | 影响 |
|---|---|---|---|
| 力量 | `strength` | 刚 | 刚系招式伤害加成 |
| 敏捷 | `agility` | 巧 | 巧系招式伤害加成、行气增长、战棋身法表现、暴击率 |
| 内力 | `inner_power` | 柔 | 柔系招式伤害加成、内息池上限、内息回复 |
| 洞察 | `insight` | 读气 | 气机识破、招路规律判断、隐藏信息揭示、对敌信息深度 |
| 体魄 | `constitution` | 生存 | HP 上限、防御力、体力上限（自然日系统） |

- 每个基础属性初始值范围：5-15（玩家起始总点数约 40，五维分配）
- 成长上限：单项 50（终章理论极限，需要多次顿悟）

**4. 派生属性**

| 属性 | 代号 | 公式概要 | 说明 |
|---|---|---|---|
| 攻击力 | `attack` | 取决于出招体系（见 Formulas） | 刚招用力量、巧招用敏捷、柔招用内力 |
| 防御力 | `defense` | `体魄×0.6 + 力量×0.2` | 减伤基础 |
| 行气增长 | `xingqi_gain` | 见 Formulas F3 | 决定战斗脉冲中的行气增量；洞察不参与 |
| 暴击率 | `crit_rate` | `敏捷×0.5%` | 每点敏捷 +0.5% 暴击 |
| 内息回复 | `neixi_recovery` | `2 + 内力×0.2` | 调息或自然行动触发的回复量（下限 2） |
| 功力总值 | `total_power` | `力量 + 敏捷 + 内力 + 洞察 + 体魄` | 用于境界映射和相对强度比较 |

**5. 功力境界映射（朦胧化 UI 接口）**

| 功力总值 | 境界 | 含义 | 对应游戏阶段 |
|---|---|---|---|
| 25-34 | 初学乍练 | 刚接触功法，招式生硬 | 第一章开局 |
| 35-49 | 初窥门径 | 摸清基础路数，入门 | 第一章中段 |
| 50-69 | 登堂入室 | 吃透基础，正式踏入武道厅堂 | 第二章 |
| 70-89 | 融会贯通 | 招式互相串联，不再死板 | 第三章 |
| 90-114 | 驾轻就熟 | 出招随心所欲，熟练自如 | 第四章 |
| 115-139 | 炉火纯青 | 功法纯熟，内力收发可控 | 第五章 |
| 140-169 | 出神入化 | 招式超出套路，以意驭招 | 第六章 |
| 170-199 | 登峰造极 | 当世顶尖，本门功法练到极致 | 终章 |
| 200+ | 返璞归真 | 去繁从简，大巧若拙，武道圆满 | True Ending |

**6. 角色类型**

| 类型 | 属性来源 | 成长方式 |
|---|---|---|
| 主角 | 初始模板 + 章节成长 + 顿悟 + 装备/武学 | 完全可控；必须上阵 |
| 同伴 | 固定初始模板 + 同一套可玩角色成长渠道 + 个人旅程 | 可控配置 + 自主旅程；可替换上阵，特定场景可锁定 |
| 敌人 | 固定模板（按章节/区域缩放） | 不可控（由关卡设计设定） |
| Boss | 多阶段固定模板 | 不可控（剧情驱动） |

**7. 属性修改器层（Modifier Stack）**

属性的最终值 = 基础值 + 所有修改器之和（加算）× 所有修改器之积（乘算）。

修改器来源：
- **永久**：顿悟突破、章节成长节点
- **半永久**：装备的心法、武器
- **临时**：战斗中的增益/减益、消耗品、顿悟"悟后状态"buff（全属性 ×1.1，持续当场战斗剩余回合，来源：epiphany-breakthrough `OnEpiphanyComplete`）

修改器按优先级叠加，同源修改器不叠加（取最高值）。

**7.1 武器属性职责**

武器是半永久 modifier 来源，不改变角色基础五维，也不推进 `total_power` 境界。武器只通过以下方式影响战斗：

| 武器数据 | 归属 | 属性系统职责 |
|---|---|---|
| `weapon_type` | 物品/武学 | 记录为装备标签，供武学组合判断招式可用性 |
| `attack_modifier` | 物品/道具 | 写入 `attack` 派生属性 modifier |
| `crit_modifier` | 物品/道具 | 写入 `crit_rate` modifier |
| `xingqi_modifier` | 物品/道具 | 仅当词条明确声明 `xingqi_bonus_percent` 时写入行气相关 modifier |
| `move_range_modifier` / `move_shape_tag` | 战斗/武学 | 不进入属性公式，由战斗系统和武学数据解释 |

师门武器口径：
- 风止山庄门人默认使用 `ruler` 类武器，叙事表现为玉尺或铁尺。
- `jade_ruler` 是主角序章默认武器；倾向低伤、柔/巧招式适配、较低杀伤意象。
- `iron_ruler` 可作为同类武器的更重版本；可提供更高攻击或破绽相关 modifier，但不得把风止尺法改写为刚系门派。
- 主角后续可学习并使用剑、刀等其他武器；这属于武学组合与物品配置，不改变属性系统五维职责。
- 武器不得通过“洞察”提高行动频率；任何行动频率收益必须显式写作 `xingqi_bonus_percent` 或战斗状态词条。

**8. 成长系统 (Growth System)**

`total_power` 的成长来源由“主线保底 + 顿悟跃迁 + 队伍追赶”共同构成，分别服务不同的叙事角色：

| 路径 | 类型 | 每次增量 | 总计贡献 | 叙事角色 |
|------|------|---------|---------|---------|
| **章节成长节点** | 固定、保底 | +3~+8 | ~107 点 | "日积月累的修炼"——基线保障 |
| **顿悟突破** | 条件触发、稀有 | +2~+4 | ~24-72 点 | "质变的瞬间"——加速器 |
| **队伍/个人旅程成长** | 条件触发、章节封顶 | +1~+4 | 按角色线配置 | "同伴也在走自己的江湖"——板凳追赶与人物弧 |
| **装备/心法** | 半永久 | — | 不计入 total_power | 仅影响派生属性，不推进境界 |

> **核心原则**：章节成长保证任何玩家都能稳定推进境界；顿悟是锦上添花的加速器，不是唯一来源。
>
> **队伍原则**：主角与同伴共享同一套属性结构和成长接口。不存在通过刷怪升级；任何永久成长必须绑定叙事节点、关键战斗、顿悟、个人旅程或队伍追赶机制。详见 [party-management.md](party-management.md)。

**8.1 章节成长节点 (Chapter Growth Nodes)**

每章包含 2-4 个固定叙事锚点，触发时发放**不可配置的固定属性点**。这些节点代表角色在故事中的自然成长——练功、实战积累、前辈指点。

```yaml
growth_node:
  id: "ch1_biaoju_strength_training"
  chapter: 1
  trigger: narrative_milestone     # 由主线叙事系统在到达节点时调用
  attributes: { strength: +2, constitution: +1 }
  total_gain: 3
  narration_key: "growth_biaoju_training"  # 朦胧化 UI 显示文学描述
```

**发放规则：**
- 成长节点属性直接加到**基础属性**（计入 total_power）
- 每个节点的属性分配由关卡设计预设，玩家不可选择（防止 min-max）
- 触发条件 = 到达对应叙事里程碑（不是战斗次数、不是时间）
- 每个节点仅触发一次，存档记录 flag

**8.2 章节成长预算表**

| 章节 | 成长节点数 | 每节点增量 | 章节总增长 | 累计 total_power | 对应境界上限 |
|------|-----------|-----------|-----------|-----------------|-------------|
| 序章 | 1 | +3 | 3 | 43 | 初窥门径 (35) |
| 第一章 | 3 | +4~+5 | 13 | 56 | 登堂入室 (50) |
| 第二章 | 3 | +5~+6 | 16 | 72 | 融会贯通 (70) |
| 第三章 | 4 | +5~+6 | 22 | 94 | 驾轻就熟 (90) |
| 第四章 | 3 | +6~+7 | 19 | 113 | — |
| 第五章 | 3 | +6~+7 | 19 | 132 | — |
| 终章 | 2 | +7~+8 | 15 | 147 | 出神入化 (140) |
| **合计** | **19 节点** | — | **107** | — | — |

> **数学验证**：
> - 仅靠章节成长（无顿悟）：40 + 107 = **147**（出神入化，可通关）
> - 章节 + 平均顿悟（~48）：40 + 107 + 48 = **195**（登峰造极）
> - 章节 + 全顿悟（72）：40 + 107 + 72 = **219**（返璞归真 = True Ending 解锁条件之一）
>
> 设计意图：不追求顿悟的玩家仍能以"出神入化"境界完成主线；只有积极追求顿悟（含冥想路径）的玩家能触及返璞归真。

> **章节基线功力 (chapter_baseline_power)**
>
> 章节成长节点隐式定义了每章结束时的"基线功力"——即仅通过主线成长节点可达的 `total_power`：
>
> ```
> chapter_baseline_power(chapter) = initial_total_power + sum(growth_nodes up to chapter)
> ```
>
> | 章节 | 章节基线功力 | 计算 |
> |------|-------------|------|
> | 序章 | 43 | 40 + 3 |
> | 第一章 | 56 | 40 + 3 + 13 |
> | 第二章 | 72 | 40 + 3 + 13 + 16 |
> | 第三章 | 94 | 40 + 3 + 13 + 16 + 22 |
> | 第四章 | 113 | 40 + ... + 19 |
> | 第五章 | 132 | 40 + ... + 19 |
> | 终章 | 147 | 40 + 107 |
>
> 此基线由 `GetChapterBaselinePower(chapter)` 接口对外暴露，是队伍管理系统 (party-management) 末尾追赶机制 (F2) 的参考锚点：落后同伴的追赶目标不超过当前章节基线功力，确保追赶不会超越主线自然成长上限。

> **章节基线敏捷 (chapter_baseline_agility)**
>
> 新版战斗采用行气驱动。敏捷决定角色“起手、身法、反应”的行气增长，但必须按章节基线归一化，避免后期敏捷数值膨胀导致行动频率失控：
>
> ```
> chapter_baseline_agility(chapter) = expected_agility_for_mainline_combatants_at_chapter
> ```
>
> 此基线由 `GetChapterBaselineAgility(chapter)` 接口对外暴露，供战斗系统计算 `agility_factor`。它不是玩家可见属性，也不进入功力境界映射。
>
> **属性职责边界**：
> - `agility` 影响行气增长、巧系攻击力、暴击率和战棋身法表现。
> - `insight` 不影响行气增长；它只影响气机识破、招路规律判断、隐藏信息揭示和战外洞察。
> - 任何提高行动频率的设计必须通过敏捷、明确轻功行气词条或显式状态词条表达，不得借用洞察。

**8.4 成长曲线约束**

- **无磨血增长**：不存在"打 N 场获得经验值升级"机制。任何属性增长必须绑定到可识别的叙事节点。
- **不可错过**：章节成长节点位于主线必经路径上，不会因支线选择而跳过。
- **五维均衡引导**：每章的节点集合覆盖至少 3 种不同属性，防止某一维严重落后。
- **境界突破仍需叙事前置**：即使 total_power 达到阈值，仍需满足对应的叙事条件（如特定顿悟事件或剧情节点）。章节成长让数值到位，但"悟道"的仪式感由叙事系统把关。

**8.5 与顿悟突破的分工**

| 维度 | 章节成长 | 顿悟突破 |
|------|---------|---------|
| 确定性 | 100% 触发（到达节点即获得） | 概率/条件触发 |
| 玩家感知 | 平缓、自然、"水到渠成" | 突然、戏剧性、"灵光一闪" |
| 属性增量 | 较大（+3~+8/次，是主要来源） | 较小（+2~+4/次，是加速器） |
| 附加奖励 | 无（纯属性） | 解锁招式/叙事选项/特殊能力 |
| 境界推动 | 负责把 total_power 推到"阈值附近" | 负责"跨越阈值"的最后一击 |

**8.6 与队伍管理 / 同伴成长的分工**

队伍管理系统负责判断“谁应该在何时成长”，角色属性系统只负责执行属性写入和境界检查。

| 成长来源 | 触发系统 | 属性系统职责 |
|----------|----------|--------------|
| 上阵关键战斗心得 | 队伍管理 / 行气战棋战斗 | 接收 `ApplyPartyGrowthNode(character_id, node_id)` 写入固定属性 |
| 观战心得 | 队伍管理 | 接收低强度成长节点，优先补足落后属性 |
| 末尾追赶 | 队伍管理 | 接收 `ApplyCatchupGrowth(character_id, reason)`，钳位到属性上限 |
| 离队历练 / 代办成长 | NPC 状态管理 / 活江湖层 / 队伍管理 | 写入预设属性奖励或仅记录剧情标记 |
| 同伴顿悟 | 顿悟突破 / 队伍管理 | 按目标角色发放 `ApplyEpiphanyReward(attrs{})` |

### States and Transitions

属性系统本身没有传统状态机。但**功力境界**构成一个单向状态链：

```
初学乍练 → 初窥门径 → 登堂入室 → 融会贯通 → 驾轻就熟 → 炉火纯青 → 出神入化 → 登峰造极 → 返璞归真
```

- 转换条件：功力总值跨越阈值 **且** 满足叙事前置条件（如特定顿悟事件）
- 不可逆：一旦突破不会降级
- 每次境界突破触发一次叙事事件（由主线叙事系统调度）

**境界突破叙事前置条件清单**（W2 解决）：

| 境界 | total_power 阈值 | 叙事前置条件 | 最早可达章节 |
|------|-----------------|-------------|-------------|
| 初窥门径 | 25 | 完成序章"师门遗训"节点 | 序章 |
| 登堂入室 | 35 | 第一章首次战斗胜利 | 第一章 |
| 融会贯通 | 50 | 第一章末尾"三体系领悟"顿悟事件 | 第一章 |
| 驾轻就熟 | 70 | 第二章"实战淬炼"成长节点 | 第二章 |
| 炉火纯青 | 90 | 第三章"绝境求生"战斗顿悟 | 第三章 |
| 出神入化 | 115 | 第四章"自悟"冥想顿悟 | 第四章 |
| 登峰造极 | 140 | 第五章"破茧"主线 gate 节点 | 第五章 |
| 返璞归真 | 170 | 终章"风止"最终叙事触发 | 终章 |

> **规则**：若 total_power 已达阈值但叙事条件未满足，角色提示"蕴积感"但不突破。待条件满足时自动补触发。叙事条件的具体节点 ID 由 main-narrative 的章节节点图定义。

战斗中资源属性的状态流转：

```
战斗开始 → Combat 读取 HP/NeiXi 最大值生成战斗快照
  ↓
角色自然行动 / 调息 / 特定状态 → NeiXi 回复或消耗
  ↓
受到攻击 → HP 减少
  ↓
使用招式 → NeiXi 消耗
  ↓
HP 归零 → 落败
```

破绽 (`stagger`) 的累积、衰减、阈值和决胜窗口由 `combat-system.md` 拥有；属性系统只提供攻击、防御、敏捷、内息等输入。

## Formulas

### F1. 体系攻击力（attack_for_type）

`attack = base_attack + primary_attr × scaling_factor + modifier_sum`

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| base_attack | `ba` | int | 5-15 | 角色基础攻击（模板设定） |
| primary_attr | `pa` | int | 5-50 | 对应体系的主属性（刚→力量，巧→敏捷，柔→内力） |
| scaling_factor | `sf` | float | 0.8-1.2 | 体系缩放系数（默认 1.0，心法可调） |
| modifier_sum | `ms` | int | 0-30 | 装备/buff 加算总和 |

**Output Range**: 10-80（早期 ~15，中期 ~35，终章 ~60）
**Example**: 力量=20, base=10, sf=1.0, mod=5 → 10 + 20×1.0 + 5 = **35**

### F2. 防御力（defense）

`defense = constitution × 0.6 + strength × 0.2 + modifier_sum`

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| constitution | int | 5-50 | 体魄 |
| strength | int | 5-50 | 力量 |
| modifier_sum | int | 0-20 | 装备/buff |

**Output Range**: 5-55
**Example**: 体魄=15, 力量=12, mod=3 → 15×0.6 + 12×0.2 + 3 = **14.4**

### F3. 行气增长（xingqi_gain）

```text
xingqi_gain = base_xingqi_gain * agility_factor * qinggong_xingqi_multiplier * status_xingqi_multiplier

agility_factor = clamp(agility / chapter_baseline_agility, 0.75, 1.35)
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| base_xingqi_gain | float | 由战斗系统调参 | 每个战斗脉冲的基础行气增长 |
| agility | int | 5-50 | 敏捷，代表身法、反应和起手快慢 |
| chapter_baseline_agility | int | 5-50 | 当前章节推荐敏捷基线，用于归一化 |
| agility_factor | float | 0.75-1.35 | 敏捷相对章节基线的倍率 |
| qinggong_xingqi_multiplier | float | 0.85-1.30 | 仅来自明确写有 `xingqi_bonus_percent` 的轻功词条 |
| status_xingqi_multiplier | float | 0.00-1.50 | 来自明确声明的战斗 buff/debuff |

**Output Range**: 由战斗系统的 `base_xingqi_gain` 和状态词条共同决定；属性系统只负责提供敏捷与章节基线敏捷。
**Example**: 敏捷=20，章节基线敏捷=15，无轻功或状态词条 → `agility_factor = clamp(20 / 15, 0.75, 1.35) = 1.33`。
**Rule**: 洞察不参与 `xingqi_gain`。洞察只能进入气机识破、敌方信息深度、探索隐藏线索和对话洞察。

### F4. HP 上限（max_hp）

`max_hp = base_hp + constitution × 4 + modifier_sum`

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| base_hp | int | 80-120 | 模板基础（玩家默认 100） |
| constitution | int | 5-50 | 体魄 |
| modifier_sum | int | 0-50 | 装备/buff |

**Output Range**: 100-370
**Example**: base=100, 体魄=10, mod=0 → 100 + 40 = **140**

### F5. 内息上限（max_neixi）

`max_neixi = base_neixi + inner_power × 2 + modifier_sum`

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| base_neixi | int | 15-25 | 模板基础（玩家默认 20） |
| inner_power | int | 5-50 | 内力 |
| modifier_sum | int | 0-20 | 装备/buff |

**Output Range**: 25-145
**Example**: base=20, 内力=10, mod=0 → 20 + 20 = **40**

### F6. 内息回复（neixi_recovery）

`neixi_recovery = max(2, 2 + inner_power × 0.2 + modifier_sum)`

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| inner_power | int | 5-50 | 内力 |
| modifier_sum | float | 0-5 | buff |

**Output Range**: 2-15（下限硬性锁定为 2）
**Example**: 内力=15, mod=0 → 2 + 15×0.2 = **5**

### F7. 暴击率（crit_rate）

`crit_rate = min(30%, agility × 0.5% + modifier_sum)`

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| agility | int | 5-50 | 敏捷 |
| modifier_sum | float | 0-10% | buff |

**Output Range**: 2.5%-30%（硬上限 30%）
**Example**: 敏捷=20, mod=0% → 20×0.5% = **10%**

### F8. 相对强度比较（power_comparison）

`ratio = self.total_power / target.total_power`

| ratio 范围 | 输出等级 | 朦胧化 UI 示例 |
|---|---|---|
| < 0.5 | 远弱 | "此人气势如渊，你感到难以抗衡" |
| 0.5-0.8 | 弱 | "此人内力深厚，不可小觑" |
| 0.8-1.2 | 相当 | "你与此人旗鼓相当" |
| 1.2-2.0 | 强 | "此人功力尚浅" |
| > 2.0 | 远强 | "此人不足为惧" |

## Edge Cases

- **If 气血降至 0 且角色处于"一击决胜"反击动画中**：动画正常播完后再判定落败，不中断演出。
- **If 内息不足以支付招式消耗**：禁止选择该招式。界面灰显并提示"内息不足"。
- **If 内息恰好为 0 且无可用零消耗招式**：强制调息。系统不提供"普通攻击"兜底，也不以道具、切换内功或原地结束作为默认兜底；该规则用于推动玩家合理配置低/零消耗招式。
- **If 战斗系统修改破绽**：属性系统不接收、不存储、不衰减 `stagger`。破绽完全由 Combat 战斗临时态持有。
- **If 多个角色同一战斗脉冲达到行气阈值且行气值相同**：由战斗系统按玩家方优先、敏捷高者优先、棋盘读序兜底排序；洞察不参与排序。
- **If 修改器叠加使某属性降至 0 以下**：钳位到 1。任何基础/派生属性最小值为 1（气血除外，气血归零=落败）。
- **If 同一来源的修改器重复施加**：同源不叠加，取最高值。不同来源正常叠加。
- **If 境界突破的叙事条件未满足但功力总值已达标**：不触发突破。显示"你隐约感到体内有股力量正在蕴积"作为提示。功力值照常增长，待叙事条件满足时补触发。
- **If 战斗中临时增益使功力总值跨越境界阈值**：不触发境界突破（境界只看永久属性总值）。
- **If 五维总和达到理论上限（250）**：返璞归真境界解锁后不再有属性成长空间。此时顿悟提供的不是属性点，而是解锁特殊武学/叙事选项。

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 过高/过低影响 |
|---|---|---|---|
| `base_hp` | 100 | 60-150 | 过高→战斗拖沓；过低→一招秒杀 |
| `base_neixi` | 20 | 12-30 | 过高→资源不紧张；过低→断息压力过高，频繁强制调息 |
| `chapter_baseline_agility` | 按章节配置 | 5-50 | 过低→快角色行动过密；过高→敏捷成长无感 |
| `agility_factor_clamp` | 0.75-1.35 | 0.60-1.50 | 过宽→行动频率失控；过窄→敏捷差异不明显 |
| `crit_rate_cap` | 30% | 15%-50% | 过低→暴击不存在；过高→暴击成常态 |
| `attr_cap_per_stat` | 50 | 30-80 | 影响终章功力上限和境界可达性 |
| 境界阈值数组 | [25,35,50,70,90,115,140,170,200] | 各项±15 | 影响境界突破的节奏感 |
| 体系缩放系数 `scaling_factor` | 1.0 | 0.6-1.5 | 影响三体系伤害平衡 |
| `growth_node_total_budget` | 107 | 80-130 | 过低→仅靠成长无法通关境界；过高→顿悟变得无意义 |
| `growth_per_node_min` | 3 | 2-5 | 过低→成长节点感知弱；过高→单节点跨境界 |
| `growth_per_node_max` | 8 | 5-12 | 终章节点需足够分量感 |
| `catchup_growth_cap_per_chapter` | 8 | 4-12 | 板凳追赶每章上限；过高→不上阵也能追平主力，过低→同伴掉队 |

## Acceptance Criteria

1. **GIVEN** 玩家角色五维总和为 40（初始），**WHEN** 游戏开始，**THEN** 境界显示为"初学乍练"。
2. **GIVEN** 角色力量为 20，使用刚系招式，**WHEN** 调用体系攻击力公式，**THEN** 返回 `base_attack + 20 × scaling_factor + modifier_sum`。
3. **GIVEN** 角色内息为 3，一个招式消耗 5 内息，**WHEN** 玩家尝试选择该招式，**THEN** 界面灰显该招式并提示"内息不足"。
4. **GIVEN** 战斗系统需要结算破绽，**WHEN** 查询属性系统，**THEN** 属性系统不提供 `stagger` 当前值、阈值或衰减规则；这些状态由 `combat-system.md` 持有。
5. **GIVEN** 角色功力总值为 114，**WHEN** 发生顿悟事件使力量 +2（总值变为 116），**THEN** 境界从"驾轻就熟"突破为"炉火纯青"（如果叙事条件已满足），并播放炉火纯青专属突破动画和音效。
6. **GIVEN** 功力总值已达 115 但叙事条件未触发，**WHEN** 检查境界，**THEN** 仍为"驾轻就熟"，并显示"你隐约感到体内有股力量正在蕴积"。
7. **GIVEN** 玩家角色功力总值 80，面对功力总值 160 的敌人，**WHEN** 调用相对强度比较，**THEN** 返回"远弱"等级。
8. **GIVEN** 敏捷为 20、章节基线敏捷为 15，**WHEN** 调用 `GetXingqiGain()`，**THEN** `agility_factor = clamp(20 / 15, 0.75, 1.35)`，且公式中不读取 `insight`。
9. **GIVEN** 角色洞察发生变化但敏捷、章节基线敏捷、轻功词条和状态词条不变，**WHEN** 再次调用 `GetXingqiGain()`，**THEN** 行气增长结果不变。
10. **GIVEN** 多个角色同一战斗脉冲达到行气阈值且行气值相同，**WHEN** 战斗系统排序，**THEN** 属性系统只提供 `agility`；洞察不参与排序。
11. **GIVEN** 角色体魄为 10，**WHEN** 计算气血上限，**THEN** 结果为 `100 + 10×4 = 140`。
12. **GIVEN** 同一装备的修改器被施加两次，**WHEN** 计算最终属性，**THEN** 只取一次最高值。
