# 队伍管理 / 同伴成长 (Party Management)

> **Status**: Designed
> **System #**: 25
> **Category**: Gameplay
> **Priority**: Vertical Slice
> **Last Updated**: 2026-06-08
> **Depends On**: 角色属性, 回合制战斗, 武学组合, 物品/道具, NPC 状态管理, 顿悟突破, 活江湖层
> **Referenced By**: 角色属性, 回合制战斗, 武学组合, 物品/道具, 存档系统

---

## Overview

队伍管理 / 同伴成长系统负责定义主角与同伴的可玩角色结构、上阵规则、板凳成长和非刷怪成长路径。

核心结论：

- 主角和队友使用完全相同的可玩角色结构：五维属性、资源属性、装备槽、武学槽、内功/心法槽、轻功槽、顿悟系统和战斗冷却规则。
- 主角必须上阵，不能下阵；其他角色可替换，特定场景或战役可锁定上阵名单。
- 玩家方上阵人数上限始终为 5 人；前期可同行人数随剧情逐步增加，因此可能无人补满 5 人。
- 队伍名单可大于 5 人；未上阵角色通过观战、末尾追赶、个人旅程、离队历练、代办和战斗外顿悟获得成长机会。
- 成长不依赖刷怪升级。属性成长必须来自叙事节点、关键战斗表现、顿悟、个人旅程或队伍追赶机制。

本系统的目标不是让玩家经营一张“板凳经验表”，而是让每位同行者都像真实江湖人：有自己的武学、有自己的装备、有自己的危局和顿悟，也会在玩家看不见的地方继续走路。

## Player Fantasy

队友不是主角的挂件，而是有完整武学、装备、顿悟和个人旅程的同行者。

玩家在战斗前调配五人上阵，不是在挑“数值最高的四个随从”，而是在决定这一次江湖险局由谁一同赴约。有人擅长护住凝神顿悟中的同伴，有人适合轻功切入，有人因个人支线必须亲自上阵。即使某位同伴暂时坐在板凳上，也不会像被世界遗忘：他可能观战有所心得，也可能离队代办一桩支线，或在飞书里告诉你自己于山雨夜中有所顿悟。

理想体验是：玩家想练主力，但也愿意带不同同伴上阵，因为每个人都有可理解的成长方式和自然出现的上阵理由。

## Detailed Design

### Core Rules

#### CR-1. 可玩角色统一结构

所有可被玩家控制的角色，包括主角和同伴，使用同一套可玩角色 schema：

| 模块 | 规则 |
|------|------|
| 属性 | 五维一致：力量、内力、敏捷、洞察、体魄；资源一致：气血、内息、破绽 |
| 装备 | 5 个装备槽：主手、身甲、足具、饰品 1、饰品 2 |
| 武学 | 6 个招式槽，至少建议覆盖刚/柔/巧各 1 个 |
| 内功/心法 | 1 个内功/心法槽，战斗中可按 combat-system 规则切换运行中的内功 |
| 轻功 | 1 个独立轻功槽；轻功是独立武学类，影响战棋移动范围和少量主动机动效果 |
| 顿悟 | 可触发临阵顿悟和平时顿悟，奖励池可按角色配置 |
| 冷却 | 招式、内功主动、轻功主动均按角色独立冷却 |

主角与同伴的差异不来自系统格子，而来自初始模板、人物弧、偏好标签、剧情锁定和专属顿悟奖励。

#### CR-2. 上阵与换人

- 玩家方上阵人数上限：`max_deployed_party = 5`。
- 主角必须上阵，不能下阵。
- 其他上阵席位由玩家在战斗前配置。
- 特定场景、战役、个人支线或教学可锁定上阵角色。
- 可同行人数随章节和剧情逐步开放。若当前可同行人数不足 5 人，允许少于 5 人进入战斗。
- 敌方人数不受 5 人限制。剧情需要时可以被围攻，敌方规模由战斗设计决定。

#### CR-3. 成长不靠刷怪

不存在通过反复刷普通战斗获得经验升级的机制。可玩角色的永久成长来自以下来源：

| 来源 | 适用对象 | 说明 |
|------|----------|------|
| 章节基线成长 | 主角 + 同伴 | 主线叙事节点触发，保证队伍整体不会掉出章节强度 |
| 关键战斗心得 | 上阵角色为主，观战角色少量 | 只在关键战斗或首次挑战中结算，不因重复刷怪累积 |
| 顿悟突破 | 主角 + 同伴 | 临阵顿悟、叙事顿悟、冥想顿悟，按角色奖励池发放 |
| 个人旅程成长 | 同伴为主 | 离队调查、人物弧推进、代办支线、重逢节点发放 |
| 末尾追赶 | 长期落后角色 | 补足章节基线或队伍均值落差，不反超长期上阵角色 |
| 装备/武学/内功 | 主角 + 同伴 | 改变派生属性和战斗工具，不直接计入永久 `total_power` |

#### CR-4. 观战心得

未上阵但当前处于队伍同行范围内的角色，可在关键战斗结束后获得“观战心得”。

- 观战心得不是经验值，不逐战刷取。
- 只在 `battle_growth_eligible=true` 的战斗中结算。
- 奖励低于上阵角色，默认约为上阵心得的 35%。
- 观战心得优先补足角色明显落后的属性，不用于制造新的最优板凳养成路线。

#### CR-5. 末尾追赶

末尾追赶用于避免玩家因叙事偏好长期不用某同伴，导致该角色永久失去上阵资格。

追赶目标：

```
catchup_target = max(chapter_baseline_power, party_average_power * catchup_floor_ratio)
```

默认 `catchup_floor_ratio = 0.85`。

规则：

- 只有低于 `catchup_target` 的同伴可获得追赶。
- 每章追赶增量有上限，默认 `catchup_chapter_cap = 8` 点 total_power。
- 追赶只补落差，不让板凳角色反超长期上阵角色。
- 追赶应绑定叙事包装：观战心得、前辈指点、路上自省、离队历练，而不是弹出“获得追赶经验”。

#### CR-6. 离队历练 / 代办成长

当同伴不在当前上阵或不在场时，NPC 状态管理与活江湖层可让其进入离队历练或代办任务。

- 代办任务必须由内容显式标记 `delegate_allowed=true`。
- 代办结果由预设分支决定，不自动生成。
- 代办能力读取角色属性系统的能力评估。
- 成功、部分成功或失败都可以带来成长，但成长类型不同：
  - 成功：少量属性或武学进度
  - 部分成功：少量洞察/体魄/剧情经验，可能附带伤病或后患
  - 失败：通常不发放属性，可解锁后续弥补剧情或低强度顿悟契机
- 离队历练成长计入每章板凳追赶上限，防止"派出去比上阵更赚"。

> **与活江湖层边界**：离队历练的**内容触发和结果分支**由活江湖层（#16）的"同伴代办"子系统管理；party-management 仅负责**成长结算**（属性写入、cap 管理、追赶上限扣减）。代办资格判定使用 NPC 状态管理（#10）的 `delegate_allowed` 标记。

#### CR-7. 战斗外顿悟

同伴可以在战斗外触发顿悟：

- 触发来源：个人对话、修炼地点、读书、旅途事件、代办归来、重逢节点。
- 奖励池按角色配置，优先体现其人物弧和武学身份。
- 战斗外顿悟不刷新战斗中的当前冷却，因为它不发生在战斗场景。
- 冥想顿悟的全局上限仍由 epiphany-breakthrough 控制。

#### CR-8. 自然上阵机会

为避免玩家只用固定五人，本系统允许内容设计制造自然上阵理由：

- 个人支线推荐或锁定某同伴上阵。
- 某敌人或地形偏向特定轻功、内功或体系。
- 同伴因剧情熟识某 NPC，带其上阵可解锁战前对话、说服、识破或特殊结算。
- 战役可临时要求“主角 + 指定同伴 + 自选席位”。

这些理由应以叙事和战术信息表达，不用强迫玩家在每场普通战斗轮换。

### States and Transitions

队伍成员状态：

```
未加入 → 可同行 → 可上阵
                 → 未上阵同行
                 → 离队远行 / 代办中
                 → 剧情锁定 / 不可用
                 → 重逢归队
```

成长结算状态：

```
战斗/剧情结束
  → 判断是否 growth_eligible
  → 上阵心得 / 观战心得 / 个人旅程 / 追赶
  → 写入角色属性
  → 检查境界与顿悟前置
  → 存档记录 growth_node flag
```

## Formulas

### F1. 关键战斗心得

```
deployed_insight_gain = configured_gain
observer_gain = floor(configured_gain * observation_growth_rate)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `configured_gain` | 1-3 | 由关键战斗配置，不用于普通刷怪 |
| `observation_growth_rate` | 0.35 | 观战角色获得的心得比例 |

### F2. 末尾追赶目标

```
catchup_target = max(chapter_baseline_power, party_average_power * catchup_floor_ratio)
catchup_gain = min(catchup_target - character_total_power, catchup_chapter_remaining_cap)
```

默认 `catchup_floor_ratio = 0.85`，`catchup_chapter_cap = 8`。

### F3. 代办能力评估

```
delegate_power = total_power * 0.6
               + relevant_attribute * 1.2
               + relationship_context_bonus
               + matching_tag_bonus
```

此公式只服务 NPC 状态管理的求援和代办结算，不直接等同战斗力。

## Edge Cases

- **If 当前可同行人数不足 5 人**：允许少于 5 人上阵；UI 不显示“未补满惩罚”。
- **If 玩家尝试移除主角**：禁止操作，提示“此战你必须亲自赴约”。
- **If 同伴处于剧情锁定、重伤、离队或失踪状态**：不可上阵，原因由角色状态说明，不显示为系统错误。
- **If 某装备实例已被另一角色穿戴**：必须先卸下，不能同时装备给两人。
- **If 板凳追赶会让角色超过队伍平均**：追赶值钳位到队伍平均以下。
- **If 同伴在代办中死亡或永久离队**：停止代办成长结算，按 NPC 状态管理的失败/中断规则处理。
- **If 同一章节内同伴通过多个板凳渠道成长**：共享 `catchup_chapter_cap`，避免叠加过量。
- **If 特定战役锁定上阵名单导致玩家常用角色无法出场**：该战役不应以被锁角色缺席造成不可逆成长损失；必要时给未出场主力观战或剧情补偿。

## Dependencies

| 系统 | 方向 | 接口 |
|------|------|------|
| 角色属性 | 队伍→属性 | `ApplyPartyGrowthNode(character_id, node_id)`、`ApplyCatchupGrowth(character_id, reason)`、`GetChapterBaselinePower(chapter)` |
| 回合制战斗 | 队伍→战斗 | `GetDeployedParty()`、`GetBenchObservers()`、`IsDeploymentLocked(battle_id)` |
| 武学组合 | 队伍→武学 | 读取/写入每个可玩角色的招式、内功/心法、轻功配置 |
| 物品/道具 | 队伍→物品 | 装备实例绑定到 `character_id`，同一实例不可多角色共用 |
| NPC 状态管理 | 双向 | 查询同伴是否可用、离队、代办中；写入代办成长与重逢节点 |
| 顿悟突破 | 双向 | 同伴顿悟事件奖励池、临阵/平时顿悟状态保存 |
| 活江湖层 | 双向 | 离队历练、代办结果、飞书反馈 |
| 存档系统 | 队伍→存档 | 保存队伍名单、上阵配置、锁定状态、成长节点、观战/追赶结算记录 |

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 影响 |
|------|--------|----------|------|
| `max_deployed_party` | 5 | 固定 | 核心战棋体验规模；不建议调整 |
| `observation_growth_rate` | 0.35 | 0.2-0.5 | 过高会削弱上阵意义，过低会让板凳掉队 |
| `catchup_floor_ratio` | 0.85 | 0.75-0.95 | 过高会让轮换成本过低，过低会让弱角色难追 |
| `catchup_chapter_cap` | 8 | 4-12 | 控制每章板凳补偿上限 |
| `max_concurrent_away_training` | 2 | 1-3 | 控制离队历练并发，避免队伍管理过重 |
| `battle_growth_eligible_rate` | 关键战斗限定 | 仅内容配置 | 防止普通战斗变刷成长点 |
| `delegate_growth_cap_per_chapter` | 4 | 2-8 | 控制代办成长不反超上阵 |

## Visual/Audio Requirements

- 队伍界面应呈现“同行名册”而非雇佣兵列表，角色卡显示状态：上阵、同行未上阵、离队远行、代办中、剧情锁定。
- 上阵配置界面显示 5 个席位，主角席位锁定。
- 板凳成长结算以短句文学反馈呈现，如“她在旁观中记下了破绽”“他来信说，此行终于懂了那句旧诀”。
- 同伴重逢归队时若获得个人旅程成长，应有一小段归队反馈，不用长演出打断节奏。

## UI Requirements

- 队伍界面提供角色切换、上阵配置、装备配置、武学配置入口。
- 每个可玩角色的装备/武学/轻功槽布局一致。
- 主角锁定上阵应在 UI 上以锁标识表达。
- 未上阵角色的成长状态只展示朦胧描述，不展示“板凳经验百分比”。
- 代办中角色显示当前去向和预计回信节点，但不暴露成功概率。

## Acceptance Criteria

1. **GIVEN** 玩家进入战前配置，**WHEN** 当前可同行人数 ≥ 5，**THEN** 最多选择 5 名角色上阵，且主角不可移除。
2. **GIVEN** 当前可同行人数为 3，**WHEN** 进入战斗，**THEN** 允许 3 人上阵，不提示人数不足惩罚。
3. **GIVEN** 同伴处于离队远行状态，**WHEN** 玩家尝试将其加入上阵名单，**THEN** 禁止选择并显示叙事原因。
4. **GIVEN** 某装备实例已由同伴 A 穿戴，**WHEN** 玩家尝试给同伴 B 装备同一实例，**THEN** 提示需先卸下。
5. **GIVEN** 一场关键战斗标记 `battle_growth_eligible=true`，**WHEN** 战斗胜利，**THEN** 上阵角色获得完整心得，同行未上阵角色获得观战心得。
6. **GIVEN** 某同伴低于章节基线，**WHEN** 到达追赶结算节点，**THEN** 系统按 `catchup_target` 发放补足成长，但不超过章节上限。
7. **GIVEN** 同伴完成代办支线，**WHEN** 结果飞书送达或重逢归队，**THEN** 根据预设结果发放个人旅程成长或后续剧情标记。
8. **GIVEN** 同伴触发临阵顿悟，**WHEN** 选择凝神且撑过 3 个自然行动轮，**THEN** 该同伴获得自己的顿悟奖励并刷新该角色普通招式/内功主动/轻功主动冷却。

## Open Questions

1. 每位核心同伴的个人旅程成长节点和专属顿悟奖励池，待角色线详细设计时逐一配置。
2. 轻功系统需要独立 GDD 细化：移动范围、主动轻功、轻功冷却和地形交互。
