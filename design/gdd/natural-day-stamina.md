# 自然日 + 体力

> **Status**: Designed
> **Author**: user + agents
> **Last Updated**: 2026-06-04
> **Implements Pillar**: Pillar 1 (江湖是活的，不止围绕你而转), Pillar 3 (武侠味先于游戏味)

## Overview

自然日 + 体力是《风止》的时间节奏引擎和行动资源管理器。作为基础设施，它驱动整个游戏世界的时间推进——12 时辰制日历、季节流转、延迟事件触发——是 NPC 独立旅程、飞书到达、活江湖事件和场景环境变化的"心跳"来源。

作为玩家体验，它让旅途有重量：每一段路程消耗时间和体力，迫使玩家在"多走一段还是就近歇脚"之间抉择。体力归零不会致死，但行动效率明显下降，形成"赶路还是休息"的日常决策循环。时辰的流逝改变场景的光照和氛围、NPC 的出没、商铺的开关，让玩家感受到"江湖有自己的作息"——而不只是为你等在原地。

核心职责：
1. **时间推进** — 管理游戏日和 12 时辰的流转，按大地图移动和剧情事件推进
2. **季节管理** — 按游戏日推进四季循环，通知场景管理和事件系统
3. **体力管理** — 维护玩家体力池的消耗、恢复和状态效果
4. **延迟事件调度** — 为 NPC 飞书、代办结算、传闻出现等系统提供"第 N 日触发"的服务
5. **休息与恢复** — 定义客栈休息的规则、效果和时间推进

## Player Fantasy

**"赶路赶了一天，天色将暗，远处客栈升起灯笼——歇还是不歇？"**

玩家直接感受这个系统的方式不是看数字，而是感知旅途的"分量"：

**路途有代价** — 从江南到塞北不是一键传送的菜单选择，而是一段需要考虑"还有多少体力""天黑前能不能到""走不到的话今晚露宿"的实际行程。这让每次出发都像武侠小说里"负剑远行"的慎重——不是因为害怕失败，而是因为江湖够大，你要想清楚今天走哪段路。

**时间有呼吸** — 时辰不只是屏幕角落的文字提示，而是世界在你身边流转的节奏：晨起时看到江面的薄雾，午后在树荫下遇到赶路的商队，入夜后客栈里人声鼎沸。你不需要"管理时间"，但你会自然地意识到"我在这里待了很久了"或"天快黑了，差不多走了"。

**休息是奖赏** — 在长途跋涉后进入客栈，点一壶茶等天亮——这不是惩罚机制的结束，而是节奏设计给予的"呼吸时刻"。休息时可以整理飞书、听传闻、看看新来的旅人——江湖的信息密度在这里自然聚拢。

**支柱对齐：**
- **Pillar 1**（江湖是活的）— 时间推进驱动季节、NPC 行动和世界事件，你不走时世界也在转
- **Pillar 3**（武侠味先于游戏味）— 不做"疲劳值 72/100"的数字展示，用境界文学和行为表现传达体力状态

## Detailed Design

### Core Rules

**1. 游戏日与时辰**

一个游戏日 = 12 时辰，采用中国传统时辰制：

| 序号 | 时辰 | 现实对应 | 光照分类 |
|---|---|---|---|
| 1 | 子 | 23:00–01:00 | 夜 |
| 2 | 丑 | 01:00–03:00 | 夜 |
| 3 | 寅 | 03:00–05:00 | 晨 |
| 4 | 卯 | 05:00–07:00 | 晨 |
| 5 | 辰 | 07:00–09:00 | 日 |
| 6 | 巳 | 09:00–11:00 | 日 |
| 7 | 午 | 11:00–13:00 | 日 |
| 8 | 未 | 13:00–15:00 | 日 |
| 9 | 申 | 15:00–17:00 | 日 |
| 10 | 酉 | 17:00–19:00 | 昏 |
| 11 | 戌 | 19:00–21:00 | 昏 |
| 12 | 亥 | 21:00–23:00 | 夜 |

光照分类：日（5 时辰：辰巳午未申）、晨（2 时辰：寅卯）、昏（2 时辰：酉戌）、夜（3 时辰：子丑亥）。

每时辰持续 1/12 游戏日。时辰切换时发送 `shichen_changed(new_shichen)` 事件。

**2. 时间推进来源**

时间不自动流逝（非实时制），仅以下行为推进时间：

| 推进来源 | 推进量 | 规则 |
|---|---|---|
| 大地图移动 | 0.01 天/格 | 逐格实时扣除 |
| 驿站传送 | 步行距离 × 0.005 天/格 | 一次性推进（= 步行时间的一半） |
| 客栈休息 | 可选：至下一个时辰 / 至次日卯时 / 自定义时辰 | 一次性推进 |
| 剧情事件 | 配置的 `time_advance` 值 | 由主线叙事或对话系统触发 |
| 战斗 | 0（不消耗时间） | 战斗处于时间暂停状态 |
| 场景内探索 | 0（不消耗时间） | 场景内活动不推进日历 |

**3. 季节管理**

每季 = 配置天数（默认 30 游戏日/季），全年 = 4 季 × 30 天 = 120 游戏日。

| 季节 | 顺序 | 日数 | 启动时发送事件 |
|---|---|---|---|
| 春 | 1 | 30 | `season_changed("spring")` |
| 夏 | 2 | 30 | `season_changed("summer")` |
| 秋 | 3 | 30 | `season_changed("autumn")` |
| 冬 | 4 | 30 | `season_changed("winter")` |

游戏开始时为春。季节循环，第 121 天回到春。

**4. 体力管理**

| 属性 | 定义 | 来源 |
|---|---|---|
| 最大体力 | `max_stamina = base_stamina + constitution × stamina_per_con` | 角色属性系统 |
| 当前体力 | 实时值，随移动消耗和休息恢复 | 本系统维护 |
| 体力状态 | 充沛 / 疲惫 / 力竭 | 由当前体力百分比决定 |

体力状态阈值：
- **充沛**：体力 > 50% max → 无任何惩罚
- **疲惫**：体力 ≤ 50% 且 > 0 → 视觉提示（角色走路动画变慢），无机械惩罚
- **力竭**：体力 = 0 → 移动速度 ×0.5，不再扣除体力，角色显著疲态

体力消耗：
- 大地图移动：0.2 点/格
- 驿站传送：0
- 战斗：0（但战后可能因剧情扣减）
- 场景内：0

体力恢复：
- 客栈休息：完全恢复至 max_stamina
- 食物/道具：恢复配置量（由物品系统定义）
- 自然回复：无（不做自动回体力，必须主动休息）

**5. 延迟事件调度**

其他系统可向本系统注册延迟事件：

```
register_delayed_event(event_id, trigger_day, callback, priority)
```

每次日推进时，检查是否有事件到达 `trigger_day`。到达时按优先级排序执行回调。

典型使用方：
- NPC 状态管理：飞书到达（第 N 日）、代办结算
- 活江湖层：传闻出现、世界事件
- 主线叙事：限时节点倒计时

**6. 客栈休息规则**

玩家在客栈场景中可选择"休息"：
- 不收费（基础客栈）或收取少量银两（高级客栈提供额外恢复）
- 休息方式：
  - "小憩"：推进至下一个时辰，体力恢复 30%
  - "过夜"：推进至次日卯时（清晨），体力完全恢复，气血/内息完全恢复
  - "休至指定时辰"：推进至玩家选择的目标时辰，体力按推进时辰数比例恢复
- 休息期间时间正常推进（触发延迟事件、季节变化等）
- 休息不可中断（一旦选择即跳转完成）

### States and Transitions

**日历状态**

| 状态字段 | 类型 | 说明 |
|---|---|---|
| `current_day` | int | 当前游戏日（从第 1 天开始） |
| `current_shichen` | enum(12) | 当前时辰 |
| `day_progress` | float | 当前时辰内的进度（0.0–1/12） |
| `current_season` | enum(4) | 当前季节 |
| `season_day` | int | 当前季节内的第几天 |

**体力状态**

| 状态字段 | 类型 | 说明 |
|---|---|---|
| `current_stamina` | float | 当前体力值 |
| `max_stamina` | float | 体力上限（由角色属性计算） |
| `stamina_state` | enum | 充沛 / 疲惫 / 力竭 |

**状态转换**

| 转换 | 触发条件 | 结果 |
|---|---|---|
| 时辰切换 | `day_progress` 累积越过 1/12 边界 | 发送 `shichen_changed`，更新光照 |
| 日切换 | 12 个时辰走完 | `current_day += 1`，触发天气刷新，检查延迟事件 |
| 季节切换 | `season_day > days_per_season` | 发送 `season_changed`，重置 `season_day` |
| 体力状态降级 | 消耗导致体力跌破阈值 | 更新 `stamina_state`，触发视觉/速度变化 |
| 体力状态升级 | 恢复导致体力超过阈值 | 更新 `stamina_state`，恢复正常速度/视觉 |

### Interactions with Other Systems

| 系统 | 方向 | 接口 |
|---|---|---|
| **角色属性** | 属性 → 日历 | `GetMaxStamina()` 提供体力上限；体魄变化时重算上限 |
| **地图/场景管理** | 双向 | 大地图移动调用 `advance_time(0.01)` + `consume_stamina(0.2)`；本系统发送 `shichen_changed` / `season_changed` 供场景切换光照/天气 |
| **NPC 状态管理** | 日历 → NPC | 注册延迟事件（飞书到达、代办结算）；日推进时批量触发 |
| **主线叙事** | 双向 | 主线可调用 `advance_time(N)` 推进剧情时间；限时节点查询 `current_day` 判定超时 |
| **活江湖层** | 日历 → 活江湖 | 日推进触发传闻、世界事件；季节变化影响事件池 |
| **存档系统** | 双向 | 持久化 `current_day` / `current_shichen` / `day_progress` / `current_season` / `current_stamina` / 延迟事件队列 |
| **物品/道具** | 道具 → 日历 | 食物道具调用 `restore_stamina(amount)` |
| **对话系统** | 对话 → 日历 | 某些对话节点可触发 `advance_time(N)` 表示"时间流逝" |

## Formulas

### F1. 体力上限计算

`max_stamina = base_stamina + constitution × stamina_per_con`

**Variables:**

| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 基础体力 | `base_stamina` | int | 20–30 | 角色初始体力池（默认 20） |
| 体魄 | `constitution` | int | 1–50 | 角色属性系统提供 |
| 体魄体力系数 | `stamina_per_con` | float | 0.5–2.0 | 每点体魄增加的体力（默认 1.0） |

**Output Range:** 21 到 80（典型游戏范围 20–50）
**Example:** 初期角色 base=20, constitution=10, 系数=1.0 → max_stamina=30

### F2. 时间推进

`new_day_progress = day_progress + time_delta`

每次推进后检查：
- `if new_day_progress >= 1/12` → 触发时辰切换，`current_shichen` 前进一位，`day_progress -= 1/12`
- `if current_shichen` 循环完 12 个 → 触发日切换

**Example:** 大地图走 1 格 → time_delta=0.01 天。若当前 day_progress=0.075（接近 1/12≈0.0833），走完后 0.085 > 0.0833 → 时辰切换。

### F3. 客栈休息恢复

`stamina_restored = min(rest_ratio × max_stamina, max_stamina - current_stamina)`

| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 休息比例 | `rest_ratio` | float | 0.3–1.0 | 小憩=0.3，过夜=1.0，自选=推进时辰数/12 |
| 时间推进 | `rest_time` | float | 1/12 到 1.0 天 | 小憩=1时辰=1/12天，过夜=至次日卯时 |

**Example:** 当前体力 10/30，选择"过夜" → rest_ratio=1.0 → stamina_restored=20 → 满体力。

### F4. 季节推进

`season_index = floor((current_day - 1) / days_per_season) % 4`

| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 当前游戏日 | `current_day` | int | 1+ | 从第 1 天开始 |
| 每季天数 | `days_per_season` | int | 20–40 | 默认 30 |

**Output Range:** 0–3（春=0, 夏=1, 秋=2, 冬=3）
**Example:** 第 31 天 → floor(30/30)%4 = 1 → 夏季开始。

### F5. 体力状态判定

`stamina_state = current_stamina > max_stamina × 0.5 ? "充沛" : current_stamina > 0 ? "疲惫" : "力竭"`

**Output:** enum{充沛, 疲惫, 力竭}
**Example:** 体力 8/30 → 8 > 15? No → 8 > 0? Yes → 疲惫。

## Edge Cases

- **If 大地图移动跨越多个时辰/日/季节边界**：逐格检查，每格推进后依次判定：先时辰切换 → 再日切换（含天气刷新 + 延迟事件检查）→ 再季节切换。不跳步。

- **If 驿站传送的时间推进跨越日或季节边界**：一次性推进时间后，按到达时刻的最终状态结算。中间经过的每一日仍需逐日触发延迟事件（批量执行）。

- **If 客栈休息期间触发延迟事件**：延迟事件在休息结算时批量触发。事件回调中不允许要求玩家交互——需要玩家交互的事件（如飞书送达）标记为"休息后待送达"，在玩家离开客栈进入自由活动后再触发。

- **If 玩家在限时主线期间大量休息导致超时**：休息推进时间不被阻止。超时由主线叙事系统判定和处理（强制推进），本系统只忠实推进时间，不做"限时保护"。

- **If 体力恢复超过上限**：`current_stamina = min(current_stamina + amount, max_stamina)`，永远不超过上限。

- **If 体魄属性变化导致 max_stamina 改变**：立即重算上限。若新上限 < current_stamina，不主动削减当前体力（允许暂时超标），下次消耗后自然回落。

- **If 存档加载后 current_stamina > max_stamina**：允许，视为合法状态（可能因属性暂时下降导致）。不做自动修正。

- **If 存档加载后 current_day 或 current_shichen 非法（负数或超范围）**：使用安全默认值（day=1, shichen=卯, season=春, stamina=max），记录警告日志。

- **If 多个延迟事件注册了同一天**：按优先级排序执行。同优先级按注册顺序（FIFO）。

- **If 某延迟事件的回调触发了新的时间推进**：禁止递归推进。延迟事件回调内不得调用 `advance_time()`。若需要"事件 A 触发后第 N 日再触发事件 B"，应注册新的延迟事件。

- **If 玩家在某时辰边界同时触发奇遇和时辰切换**：优先暂停时间 → 触发奇遇 → 奇遇结束后再应用时辰切换（与地图 GDD 一致）。

- **If 季节天数配置不整除 12 时辰**：无影响——季节以整天为单位切换，不受时辰影响。

## Tuning Knobs

| 调节旋钮 | 默认值 | 安全范围 | 过高风险 | 过低风险 | 来源 |
|---|---|---|---|---|---|
| `days_per_season` | 30 | 20–40 | 季节变化太慢，视觉单调 | 季节变化太快，失去时间感 | F4 |
| `base_stamina` | 20 | 15–30 | 初期体力过多，移动无成本 | 初期几步就力竭，探索受挫 | F1 |
| `stamina_per_con` | 1.0 | 0.5–2.0 | 体魄成长价值过高，体力无限 | 体魄成长无感，不值得投入 | F1 |
| `rest_ratio_nap` | 0.3 | 0.2–0.5 | 小憩回复过多，过夜无意义 | 小憩无感，只有过夜可选 | F3 |
| `zero_stamina_speed_mult` | 0.5 | 0.3–0.8 | 力竭惩罚过轻，无动力休息 | 力竭几乎无法移动，体验恶劣 | 核心规则 4 |
| `fatigue_threshold` | 0.5 | 0.3–0.7 | 充沛区间太小，总是看到疲态 | 疲惫提示太晚，缺乏预警 | F5 |

> **参数归属说明**：`time_per_grid`（0.01 天/格）和 `stamina_per_grid`（0.2 点/格）由地图系统（map-scene-management）定义和拥有，在调用 `advance_time(delta)` / `consume_stamina(amount)` 时作为参数传入本系统。本系统不持有这两个值。

**旋钮交互关系：**
- `time_per_grid`（地图系统所有）× 地图总格数 = 一天能走的总距离。与 `days_per_season` 共同决定"一季能走多远"。
- `stamina_per_grid`（地图系统所有）× `max_stamina` = 体力满时能走的最大格数。需确保最远两个驿站之间的距离 < 此值，否则玩家会被迫力竭。
- `rest_ratio_nap` 与"限时主线"机制联动：若小憩回复足够高，玩家可以频繁小憩而不推进太多时间。

| **季节场景色板** | 4 套环境调色板 | 同上，由场景管理消费 `season_changed` 后切换 |
| **体力状态 — 角色动画** | 3 套行走帧率（充沛/疲惫/力竭） | 充沛=正常 8fps，疲惫=6fps 且略弯腰，力竭=4fps 且明显蹒跚 |
| **力竭呼吸粒子** | 1 个粒子特效（气喘白雾） | 力竭状态下角色头顶每 2 秒播放一次 |
| **客栈休息过场** | 1 段像素过渡动画 | 屏幕渐暗 → 显示时间推进文字 → 渐亮，≤2 秒 |
| **季节切换过渡** | 1 段全屏 flash（柔光白） | 0.5 秒白闪 + 渐隐，表示季节更替 |
| **时辰切换无独立演出** | — | 光照渐变由场景管理平滑过渡，本系统不出演出 |

## Acceptance Criteria

### 时间推进

- **Given** 玩家在大地图，**When** 移动 1 格，**Then** `day_progress` 增加 0.01 天，且若跨越时辰边界则发送 `shichen_changed`。
- **Given** `day_progress` 累积满 12 个时辰（1 天），**When** 触发日切换，**Then** `current_day += 1`，执行所有该日到期的延迟事件，刷新天气。
- **Given** 当前为春季第 30 天，**When** 日切换触发，**Then** `current_season` 变为夏，发送 `season_changed("summer")`。

### 驿站传送

- **Given** 两点间步行距离为 20 格，**When** 玩家选择驿站传送，**Then** 时间推进 20×0.005=0.1 天，体力不消耗，中间经过的每一日的延迟事件均被触发。

### 体力消耗与状态

- **Given** 体力=15/30（>50%），**When** 移动消耗后体力降至 14（<50%），**Then** `stamina_state` 切换为"疲惫"，角色动画切换为疲惫帧率。
- **Given** 体力=0（力竭），**When** 玩家继续移动，**Then** 移动速度 ×0.5，不再扣除体力。
- **Given** 体力=0，**When** 玩家在客栈选择"过夜"，**Then** 体力恢复至 max_stamina，`stamina_state` 切换为"充沛"。

### 客栈休息

- **Given** 当前时辰=午，**When** 选择"小憩"，**Then** 时间推进至未时，体力恢复 30% max_stamina。
- **Given** 当前时辰=酉，**When** 选择"过夜"，**Then** 时间推进至次日卯时，体力完全恢复。
- **Given** 休息期间有延迟事件到期，**When** 休息结算完成，**Then** 延迟事件批量触发；需要玩家交互的事件标记为"休息后待送达"。

### 延迟事件

- **Given** NPC 注册了一个第 5 天触发的飞书事件，**When** `current_day` 从 4 推进到 5，**Then** 回调执行，飞书标记为已到达。
- **Given** 同一天有 3 个延迟事件（priority 2, 1, 3），**When** 日切换触发，**Then** 按 priority 升序（1→2→3）执行。
- **Given** 延迟事件回调内尝试调用 `advance_time()`，**Then** 调用被拒绝（无操作），记录错误日志。

### 存档

- **Given** 玩家存档，**Then** `current_day`, `current_shichen`, `day_progress`, `current_season`, `season_day`, `current_stamina`, `max_stamina`, `stamina_state`, 延迟事件队列 全部持久化。
- **Given** 加载存档后 `current_day` < 1，**Then** 重置为安全默认值（day=1, shichen=卯, season=春, stamina=max），记录警告。

### HUD

- **Given** 玩家在大地图，**Then** 时辰指示和体力条始终可见。
- **Given** 体力状态从"充沛"切换为"疲惫"，**Then** 体力条颜色从青白渐变为淡黄，同时显示"疲惫"toast 1.5 秒。

## Open Questions

1. **客栈是否收费？** 当前设定"基础客栈免费，高级客栈收少量银两"——但"高级客栈"尚无物品/经济系统支撑。VS 阶段是否统一免费，等经济系统设计后再加收费？

2. **体力恢复道具的节奏控制** 食物道具恢复体力会与客栈休息形成替代关系。若食物廉价且恢复量高，客栈休息将失去意义。是否需要在本系统侧设置"道具恢复冷却"或交由物品系统自行平衡？

3. **夜间行走是否应有额外惩罚？** 目前力竭以外无移动惩罚。是否在"夜"光照分类下增加"视野缩小"或"奇遇概率变化"？这可能增加复杂度但提升昼夜感知。

4. **延迟事件队列的存档大小** 若大量系统注册延迟事件，队列可能膨胀。是否需要设置队列上限或过期自动清理机制？

5. **时辰圆盘 picker 的操作体感** 12 时辰的圆盘 UI 是否在手柄/键盘操作下足够便捷？是否需要备选方案（如列表选择）？
