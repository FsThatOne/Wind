# 对话系统 (Dialogue System)

> **Status**: In Design
> **Author**: user + agents
> **Last Updated**: 2026-06-03
> **Implements Pillar**: Pillar 2 (每个选择必须有重量), Pillar 3 (武侠味先于游戏味), Pillar 4 (情感深度优先于内容广度)

## Summary

对话系统是《风止》叙事 RPG 的骨架管道，负责承载所有角色对话、剧情分支、心境选择和关系互动。它将武侠文学的对话质感（留白、暗示、一语双关）转化为可交互的游戏体验，同时为心境双轴、感情系统和主线叙事提供统一的事件接口。

> **Quick reference** — Layer: `Foundation` · Priority: `MVP` · Key deps: `None`

## Overview

对话系统是《风止》的叙事骨架 — 所有角色交互、剧情分支、心境抉择和关系推进都通过它流转。作为 Foundation 层系统，它为心境双轴、感情系统和主线叙事提供统一的事件管道；作为玩家直接面对的交互界面，它承载了武侠叙事的文学质感。

玩家在大部分时间里**阅读**角色之间的对白，感受武侠小说式的语言节奏 — 留白、暗示、一语双关、江湖切口。在关键叙事节点，系统呈现**有重量的选择**：杀或留、追或弃、信或疑。这些选择不可撤销，通过对话系统的事件接口直接驱动心境位移、关系变化和主线分支。

对话系统同时支持武侠特有的叙事机制：**洞察**（在对话中感知 NPC 的隐藏意图或线索）、**暗号**（特定暗语触发隐藏对话分支）、**心境选择**（选项本身反映并推动玩家的执念/释怀、入世/出世倾向）。系统的核心设计原则是**"对话即游玩"** — 不是战斗之间的过渡，而是叙事 RPG 中与战斗同等重要的核心互动。

## Player Fantasy

**"我不是在点击对话框 — 我正身处一场命运交错的江湖对话之中，每一句回应都在编织我与这些角色之间不可逆的羁绊。"**

对话系统服务三层玩家幻想：

**文学沉浸** — 玩家感觉自己在**阅读和参与一部顶级武侠小说**。角色的语言有温度和层次：谢残翁的话里藏着未言之意，白苓的暗号像诗句般隽永，仇人的言辞在威压中暴露破绽。对话不是信息传递的载体，而是武侠世界质感的直接来源 — 如同金庸笔下"你瞧这些白云聚了又散、散了又聚"那一句，轻描淡写间改变了整部小说的走向。

**选择的重量** — 关键对话节点让玩家感受到**"说出口就不能收回"的凝重**。当玩家在仇人面前选择"留你一命"或"剑下无情"时，不是在选一个 RPG 选项 — 是在以剑客的身份做出一生的抉择。系统通过不可撤销的选择 + 延迟显现的后果 + 其他角色对你过去言行的记忆，让每一次开口都具有仙剑式的宿命感。

**情感羁绊** — 玩家通过对话**真正关心角色的命运**。三位女主不是等待你推进好感度的 NPC — 她们在对话中展露自己的脆弱、骄傲和选择。当白苓在书信中用你们之间才懂的暗号传递消息时，当谢残翁终于说出那句藏了三章的真话时，玩家的情感反应来自于对话系统积累的每一次真诚交谈。正如仙剑系列的名场面，最让人落泪的不是 CG 动画，而是那句简单的对白。

**支柱对齐**：
- **Pillar 2**（每个选择有重量）— 对话选择不可回溯，后果延迟显现
- **Pillar 3**（武侠味先于游戏味）— 用文学语言而非 UI 标签传递信息
- **Pillar 4**（情感深度优先）— 深度角色关系通过对话积累

## Detailed Design

### Core Rules

**1. 对话序列模型**

对话以**序列（DialogueSequence）**为基本单元，每个序列是一次完整的对话交互（如"与谢残翁在山道上的对话"）。序列内部采用**线性流 + 条件分支**结构：主干为线性叙述，在关键节点通过条件或选择分叉，分支结束后可回到主干或跳转到其他位置。

复杂场景（Boss 对峙、三女主共聚、多阶段审讯）采用**图结构**，支持回环、合流、多条件跳转。

**2. 节点类型（7 种）**

| 节点类型 | 标识 | 描述 | 视觉呈现 |
|---------|------|------|---------|
| **Speech** | `[角色名]` | NPC 或主角的对白 | 标准对话框，角色立绘 |
| **Choice** | `+` | 2-4 个选项，玩家择一 | 选项列表，可带文学暗示 |
| **InnerMonologue** | `~思~` | 主角的内心独白/反应 | 区别于对白的独立样式（如斜体、不同底色） |
| **Narration** | `>` | 旁白、环境描写、动作描述 | 无角色头像，全屏或半屏文字 |
| **Letter** | `✉` | 书信、字条、告示 | 独立信笺 UI，可存入书信匣 |
| **InsightPrompt** | `◉` | 洞察触发后显示的隐藏信息 | 特殊视觉效果（如水墨晕染展开） |
| **CodePhrase** | `※` | 暗号触发的隐藏选项/分支 | 在常规选项中以暗号样式显示 |

**3. 选择系统**

选择分为四类，每类有不同的呈现规则：

- **标准选择（Standard）**：2-4 个选项，纯文字。日常对话、支线互动。无暗示标签。
- **心境选择（Mindset）**：选项带有文学暗示，暗示用括号内的武侠语言表达，如 *"（此言带几分执念）"*、*"（话中有释怀之意）"*。仅在选项会影响心境位移时出现暗示；暗示不显示具体数值。
- **洞察选择（Insight-gated）**：仅在洞察成功触发并被玩家确认追查后出现。若洞察未触发或玩家忽略线索，该选项**不可见**（非灰色不可选，而是完全不存在）。
- **暗号选择（Code Phrase）**：玩家已学会相关暗号 + 当前对话场景匹配时，暗号自动出现为额外选项。暗号选项有独特视觉标记，让玩家知道这是"江湖暗语"。

**选择呈现原则**：
- 不可用选项**不显示**（不灰化）— 玩家永远不知道自己错过了什么，直到二周目
- 选择**不可撤销** — 确认后立即生效，无回退
- 对话**无限时逻辑** — 玩家可以在任何选择节点停留任意时间。若"沉默"是有意义的回应，它必须作为显式选项出现（如 *"……（沉默不语）"*），而非超时触发

**4. 洞察机制（对话内）**

对话中部分 NPC 台词包含**隐藏线索**。系统处理流程：

1. NPC 说出包含线索的台词
2. 系统判定：玩家角色的**洞察属性（insight）**是否满足该线索的门槛
3. 若满足 → 显示**微妙视觉暗示**（特定文字渐显高亮、或台词旁浮现若隐若现的图标），暗示在当前节点期间**持续可见**，无时间限制
4. 玩家可选择**追查**（点击暗示区域或选择"追查"选项）或**推进到下一节点**（视为忽略）
5. 追查成功 → 进入 InsightPrompt 节点，揭示额外信息（NPC 真实意图、隐藏线索、角色背景）
6. 推进到下一节点 → 暗示消失，本次对话不可回退重试（但同一信息可能在后续对话中再次出现）

洞察门槛由内容设计时设定，不由公式计算 — 对话系统只做"属性 ≥ 门槛？"的布尔判定。

**5. 暗号系统（对话内）**

暗号通过游戏过程习得（书信教授、NPC 传授、环境发现）。系统处理流程：

1. 玩家与特定 NPC 在特定场景/条件下对话
2. 系统检查：玩家的暗号簿中是否有与当前上下文匹配的暗号
3. 若有 → 暗号自动出现为选项列表中的一个额外选项
4. 使用正确暗号 → 解锁隐藏对话分支（可能是整段新对话、新支线、或关键信息）
5. 暗号使用后标记为"已使用"（同一暗号不同场景可能有不同效果）

**6. 事件管道**

每个对话节点可触发 0 到多个**事件（Event）**，事件在节点显示完毕且玩家确认后触发：

| 事件类型 | 参数 | 下游消费者 |
|---------|------|-----------|
| `mindset_shift` | axis(执念↔释怀 / 入世↔出世 / 善↔恶), delta | 心境双轴系统 |
| `relationship_change` | npc_id, delta | 感情系统 |
| `quest_flag` | flag_id, value | 主线叙事 |
| `npc_state_change` | npc_id, new_state | NPC 状态管理 |
| `insight_discovered` | insight_id | 探索/洞察系统 |
| `code_phrase_learned` | phrase_id | 对话系统自身（暗号簿） |
| `item_grant` | item_id, quantity | 物品/道具系统 |
| `combat_trigger` | combat_id | 战斗系统 |
| `chapter_advance` | chapter_id | 主线叙事 |

**7. 条件系统**

对话节点和选项可设置**入口条件**，条件不满足时该节点/选项被跳过：

| 条件类型 | 参数 | 数据来源 |
|---------|------|---------|
| `flag_check` | flag_id, operator, value | 主线叙事 / 存档 |
| `mindset_check` | axis, operator, threshold | 心境双轴 |
| `relationship_check` | npc_id, operator, threshold | 感情系统 |
| `item_check` | item_id, operator, quantity | 物品/道具 |
| `insight_check` | insight_id | 探索/洞察 |
| `code_phrase_check` | phrase_id | 暗号簿 |
| `power_check` | operator, threshold | 角色属性 |
| `chapter_check` | chapter_id, operator | 主线叙事 |

条件支持 AND / OR 组合。条件判定在节点显示**之前**执行。

**8. 书信规则**

书信作为特殊对话类型，有独立规则：
- 在独立的**信笺 UI** 中显示（非标准对话框）
- 书信到达由自然日系统调度（基于日历事件）
- 所有收到的书信存入**书信匣**，可随时重读
- 书信可包含：正文、暗号（隐藏在文字中，需要洞察发现）、情感线索
- 书信可触发事件（心境位移、关系变化）
- 部分书信需要**回信**（回信选项 = 心境选择的变体）

**9. 内心独白规则**

- 以视觉上与角色对白明确区分的方式呈现
- 由剧情节点、进入特定场景、特定 NPC 台词触发
- 内心独白可包含选择（主角内心的权衡 — "我该相信他吗？"）
- 内心独白中的选择与标准选择同规则，但视觉风格为"自我对话"

### States and Transitions

| 状态 | 进入条件 | 退出条件 | 行为 |
|------|---------|---------|------|
| **Idle** | 无对话活动 | 玩家触发对话 / 脚本触发 | 游戏正常运行 |
| **Entering** | 对话被触发 | 镜头/UI 过渡完成 | 镜头调整，对话 UI 淡入，世界暂停 |
| **Displaying** | 文字节点激活 | 所有文字显示完毕（或玩家按键加速） | 逐字显示文字（打字机效果），支持按键加速和跳过 |
| **WaitingForInput** | 文字完全显示 | 玩家确认（普通节点）或选择（选择节点） | 等待玩家操作，无时间限制 |
| **InsightCue** | 洞察线索被触发 | 玩家追查或忽略 | 显示微妙视觉暗示，等待玩家决策 |
| **ProcessingChoice** | 玩家做出选择 | 事件触发完毕，下一节点解析完成 | 触发事件，评估条件，推进到下一节点 |
| **LetterReading** | 书信节点激活 | 玩家关闭信笺 / 完成回信 | 切换到信笺 UI，显示书信内容 |
| **Exiting** | 到达终止节点 / 对话结束 | UI 完全关闭 | 对话 UI 淡出，镜头恢复，世界恢复 |

**世界暂停规则**：对话进行时，世界时钟暂停（不消耗自然日），但 NPC 的"当前状态"在进入对话前已锁定。对话不会改变正在对话的 NPC 之外的世界状态 — 所有状态变更在对话结束后批量生效。

**文字显示速度**：可在设置中调整（慢 / 标准 / 快 / 瞬间）。

### Interactions with Other Systems

| 系统 | 方向 | 接口 |
|------|------|------|
| **心境双轴** | 对话 → 心境 | `mindset_shift(axis, delta)` 事件推送；`mindset_check(axis, op, threshold)` 条件查询 |
| **感情系统** | 对话 → 感情 | `relationship_change(npc_id, delta)` 事件推送；`relationship_check(npc_id, op, threshold)` 条件查询 |
| **主线叙事** | 对话 → 叙事 | `quest_flag(flag_id, value)` / `chapter_advance(chapter_id)` 事件推送；`flag_check` / `chapter_check` 条件查询 |
| **NPC 状态管理** | 双向 | `npc_state_change` 事件推送；对话启动时查询 NPC 当前状态以选择合适的对话序列 |
| **角色属性** | 属性 → 对话 | `power_check(op, threshold)` 条件查询；洞察属性值用于 insight 门槛判定 |
| **存档系统** | 双向 | 对话状态（已读标记、暗号簿、书信匣、已触发事件历史）全量持久化 |
| **物品/道具** | 对话 → 物品 | `item_grant(item_id, qty)` 事件推送；`item_check(item_id, op, qty)` 条件查询 |
| **战斗系统** | 对话 → 战斗 | `combat_trigger(combat_id)` 事件推送 — 对话结束后立即进入战斗 |
| **自然日 + 体力** | 日历 → 对话 | 日历事件触发书信到达、NPC 位置变化、时限对话解锁/过期 |
| **UI（下游）** | 对话 → UI | 显示指令：文字内容、角色立绘、选择列表、信笺 UI、洞察效果 |

**接口所有权原则**：对话系统**定义**事件格式，下游系统**订阅**并处理。对话系统不知道事件的具体效果 — 它只负责在正确时机发送正确数据。

## Formulas

对话系统主要是事件管道和条件路由器，自身执行的数值计算极少。所有下游数值（心境位移量、关系变化量等）由内容编辑在节点上配置，对话系统只负责传递。

### 洞察门槛检定（Insight Threshold Check）

对话中洞察线索的触发判定 — 对话系统唯一执行的数值比较。

`insight_triggered = player.insight >= node.insight_threshold`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 玩家洞察属性 | `player.insight` | int | 5–50 | 来自角色属性系统，反映角色的察言观色能力（初始基础值 ≥ 5） |
| 节点洞察门槛 | `node.insight_threshold` | int | 5–40 | 由内容编辑在对话节点上设置，越高的线索越难察觉 |

**输出范围**：布尔值。前期（insight 5–15）能触发简单线索（门槛 5–10，最低门槛=初始 insight，确保新手也能触发基础线索）；中期（15–30）能触发重要线索（门槛 15–25）；后期（30–50）能触发关键剧情线索（门槛 25–40）。

**示例**：玩家 insight=18，节点 insight_threshold=15 → 18 ≥ 15 = true → 显示洞察暗示

### 条件评估（Condition Evaluation）

对话节点的入口条件判定，为布尔逻辑组合：

`node_visible = condition_1 AND/OR condition_2 AND/OR ...`

每个条件是 `(source_value, operator, threshold)` 三元组，operator 支持：`==`, `!=`, `>`, `>=`, `<`, `<=`。对话系统**不计算** `source_value` — 它向对应系统查询当前值，然后执行比较。

### 非对话系统公式声明

以下数值在对话节点中配置，但不是对话系统的公式 — 它们是传递给下游系统的参数：

- `mindset_shift.delta`（心境位移量）— 由心境双轴系统定义规则
- `relationship_change.delta`（关系变化量）— 由感情系统定义规则
- `item_grant.quantity`（物品数量）— 由物品系统定义规则

对话系统只做 `emit(event_type, params)` — 不做任何数值变换。

## Edge Cases

- **If 选择节点的所有选项条件均不满足**：至少保留一个**默认选项**（无条件）。对话序列验证工具应在构建时检测并报错"选择节点 X 无默认选项"。若运行时仍发生，显示一个兜底选项"……（无言以对）"并记录错误日志。

- **If 对话图结构中出现循环（无限循环）**：对话序列设置**最大节点访问次数上限**（单次对话最多 500 个节点）。达到上限时强制退出对话并记录错误日志。此为防御性设计 — 正常对话不应触及此限制。

- **If 洞察暗示出现在选择节点期间**：洞察暗示**不在选择节点触发**。洞察仅在 Speech / Narration 节点的 WaitingForInput 阶段触发。内容编辑不应在选择节点的前置 Speech 上挂洞察标记。

- **If 玩家拥有多个匹配当前上下文的暗号**：所有匹配的暗号**均显示为可用选项**。每个暗号独立评估上下文匹配，互不排斥。

- **If combat_trigger 事件在对话序列中间触发**：对话系统**先完成当前节点的所有事件**，然后进入 Exiting 状态关闭对话 UI，最后交由战斗系统启动战斗。combat_trigger 之后的对话节点标记为"战斗后继续"或"丢弃"，由内容编辑在节点上指定。

- **If 玩家再次与已完成对话的 NPC 交谈**：每个 NPC 可配置多个对话序列，按优先级和条件排列。系统从最高优先级开始评估条件，使用第一个满足条件的序列。若所有条件序列均不满足，使用**默认闲聊序列**（每个可对话 NPC 必须有一个）。

- **If 书信在对话进行中到达**：书信到达事件**排队等待**，不打断当前对话。对话结束后按到达顺序通知玩家。

- **If 对话序列中所有节点条件均不满足（空对话）**：显示一条默认台词（如"他看了你一眼，没有说话。"）并正常退出。构建时验证工具应标记此为警告。

- **If 同一事件被重复触发**：事件系统采用**幂等语义** — `quest_flag(flag_id, value)` 重复设置同一值不产生副作用。`mindset_shift` 和 `relationship_change` 是累加的，不做去重 — 内容编辑负责不在同一对话序列中重复放置相同事件。

- **If 玩家在逐字显示期间快速按键**：第一次按键 → 立即显示当前节点全部文字。文字完全显示后的按键 → 确认并进入下一节点。**不允许单次按键跳过整段对话** — 每个节点至少需要一次确认。

- **If 存档中的对话状态与当前版本不匹配**：对话序列使用**版本号**。加载存档时比较版本号，若不匹配 → 对话状态重置为该序列起始点，已触发的事件保留。

## Dependencies

对话系统作为 Foundation 层，无上游硬依赖。核心角色是被其他系统依赖的事件管道。

| 系统 | 方向 | 依赖性质 | 硬/软 |
|------|------|---------|-------|
| **角色属性** | 对话 depends on 属性 | 洞察门槛检定需查询 insight 属性值；功力检定需查询 power | 软 |
| **心境双轴** | 心境 depends on 对话 | 心境选择通过 `mindset_shift` 事件驱动位移；`mindset_check` 条件查询 | 硬 |
| **感情系统** | 感情 depends on 对话 | 关系互动通过 `relationship_change` 事件驱动变化；`relationship_check` 条件查询 | 硬 |
| **主线叙事** | 叙事 depends on 对话 | 章节推进和任务标记通过 `quest_flag` / `chapter_advance` 事件驱动 | 硬 |
| **NPC 状态管理** | 双向 | 对话启动时查询 NPC 状态；对话可触发 `npc_state_change` | 软 |
| **存档系统** | 双向 | 对话状态需持久化（已读标记、暗号簿、书信匣、事件历史） | 硬 |
| **物品/道具** | 对话 → 物品 | 对话可通过 `item_grant` 赠予物品；`item_check` 条件查询 | 软 |
| **战斗系统** | 对话 → 战斗 | `combat_trigger` 事件在对话结束后启动战斗 | 软 |
| **自然日 + 体力** | 日历 → 对话 | 日历事件触发书信到达和时限对话 | 软 |
| **UI** | 对话 → UI | 对话系统向 UI 发送显示指令 | 硬 |

**双向一致性声明**：当心境双轴、感情系统、主线叙事的 GDD 编写时，它们的 Dependencies 节必须列出"depends on 对话系统"，且接口描述必须与本 GDD 的事件管道定义一致。

## Tuning Knobs

| 参数 | 当前值 | 安全范围 | 增大的效果 | 减小的效果 |
|------|--------|---------|-----------|-----------|
| **文字显示速度** (chars/sec) | 30 | 10–100 | 更快推进，可能来不及阅读 | 更慢，沉浸感更强但可能让快节奏玩家不耐烦 |
| **最大选项数** (per choice node) | 4 | 2–6 | 更多选择自由度，但决策负担增大 | 更聚焦，但限制设计空间 |
| **洞察暗示视觉强度** (0-1) | 0.4 | 0.1–0.8 | 更明显，降低难度 | 更隐蔽，与"朦胧化"原则一致但可能被忽略 |
| **洞察入场动画时长** (ms) | 600 | 200–1500 | 缓慢浮现，更含蓄 | 快速出现，更直接 |
| **节点访问上限** (per dialogue) | 500 | 200–2000 | 支持更复杂的对话图 | 更早捕获循环 bug |
| **书信通知延迟** (seconds after dialogue exit) | 2.0 | 0.5–5.0 | 不突兀，但可能让玩家忘记查看 | 更及时，但可能打断对话后的沉浸 |
| **打字机加速倍率** (player press) | instant | instant / 3x / 5x | — | — |
| **对话进入/退出过渡时间** (ms) | 500 | 200–1200 | 更从容，但频繁对话时拖沓 | 更爽快，但可能打破沉浸 |

**交互关系**：
- 洞察暗示视觉强度 × 入场动画时长：低强度 + 长入场动画 = 最含蓄（适合高洞察玩家的奖励感）；高强度 + 短动画 = 最直接

## Visual/Audio Requirements

| 事件 | 视觉反馈 | 音频反馈 | 优先级 |
|------|---------|---------|--------|
| **对话开始** | 底部对话框淡入 + 角色立绘滑入 | 无（BGM 继续） | MVP |
| **文字逐字显示** | 打字机效果，每字依次出现 | 无（静默打字） | MVP |
| **角色切换** | 当前说话者立绘高亮，其余暗淡 | 无 | MVP |
| **选择出现** | 选项列表从下方滑入 | 无 | MVP |
| **选择确认** | 选中项短暂高亮后消失 | 轻微 SE（笔墨落纸声） | MVP |
| **心境选择暗示** | 暗示文字以不同颜色或字体风格显示（更细字体 + 微暖/微冷色调） | 无 | MVP |
| **洞察暗示出现** | 关键文字渐显高亮（水墨晕染效果），节点旁浮现若隐若现的"眼"图标 | 轻微 SE（风声或弦音一响） | MVP |
| **洞察追查成功** | InsightPrompt 以展开卷轴式动画呈现 | 短 SE（拨弦声） | MVP |
| **暗号选项出现** | 暗号选项以独特样式标记（加引号 + 特殊底色） | 无 | MVP |
| **内心独白** | 文字斜体 + 半透明暗色底板（区别于对白） | 无 | MVP |
| **旁白/描述** | 无角色立绘，文字居中或全宽显示 | 无 | MVP |
| **书信到达** | 信笺 UI 展开（独立于对话框），纸张质感背景 | 轻微 SE（纸张展开声） | MVP |
| **书信关闭** | 信笺 UI 收拢 | 无 | MVP |
| **对话结束** | 对话框淡出 + 立绘滑出 | 无（BGM 继续） | MVP |
| **combat_trigger** | 对话框快速消失 + 画面闪切 | 战斗 SE（由战斗系统处理） | VS |

**视觉风格原则**：
- 对话框采用半透明暗色底板 + 白色文字，与游戏冷峻像素风格一致
- 角色立绘为像素风半身像，关键角色 2-3 套表情差分
- UI 元素（对话框边框、选项框）使用水墨/宣纸质感纹理
- 信笺 UI 用独立的信纸质感，与标准对话框有明确视觉区分

**音频方案**：纯文字 + BGM，不含语音和咕哝音效。仅在关键交互节点使用极少量 SE（选择确认、洞察触发、书信展开）作为操作反馈。

## Acceptance Criteria

1. **GIVEN** Speech 节点被激活，**WHEN** 节点进入，**THEN** 说话者立绘、名牌和对话文字出现，文字以打字机效果渲染，文字未完全显示前不显示选项面板。

2. **GIVEN** Choice 节点到达，**WHEN** 选项面板渲染，**THEN** 仅条件满足的选项可见；条件不满足的选项完全不存在（无灰化状态），可见选项按编辑顺序排列。

3. **GIVEN** 心境选择（Mindset）可见，**WHEN** 选项面板渲染，**THEN** 选项文字旁显示文学暗示（武侠语言），暗示与标准选项在视觉上有明确区分。

4. **GIVEN** 含洞察线索的节点激活且玩家 insight ≥ 门槛，**WHEN** 文字显示完毕，**THEN** 视觉暗示出现并无限期持续（无倒计时），玩家可选择"追查"或"推进"。

5. **GIVEN** 含洞察线索的节点激活且玩家 insight < 门槛，**WHEN** 文字显示完毕，**THEN** 无洞察暗示出现，无"追查"选项，对话作为普通 Speech 节点继续。

6. **GIVEN** 洞察暗示显示中，**WHEN** 玩家选择"追查"，**THEN** 隐藏信息分支展开，关联的 `insight_discovered` 事件恰好触发一次，之后对话正常推进。

7. **GIVEN** 玩家已学会某暗号，**WHEN** 进入上下文匹配的对话节点，**THEN** 暗号选项自动出现在选项列表中，无需额外操作，且与标准选项有视觉区分。

8. **GIVEN** Letter 节点被触发，**WHEN** 书信送达，**THEN** 在独立信笺 UI 中打开，同时存入书信匣供重读，若书信含暗号则首次查看时自动加入暗号簿。

9. **GIVEN** 玩家在书信匣中选择已收书信，**WHEN** 信笺 UI 显示，**THEN** 完整内容可见（含已发现暗号），重读不触发任何游戏状态变更。

10. **GIVEN** 对话节点触发了下游事件，**WHEN** 对话序列结束且世界恢复，**THEN** 所有批量事件按编辑顺序分发到各系统，每个事件恰好触发一次，对话 UI 未关闭前无事件触发。

11. **GIVEN** Choice 节点的所有选项条件均不满足，**WHEN** 选项面板将渲染，**THEN** 系统回退到默认分支或对话结束，不显示空选项面板，不产生错误或挂起。

12. **GIVEN** Speech/Narration 节点正在打字机显示，**WHEN** 玩家按一次确认键，**THEN** 剩余文字立即全部显示；第二次确认键推进到下一节点；快速连续按键不跳过多个节点。

13. **GIVEN** 对话序列已结束，**WHEN** 玩家与同一 NPC 再次对话，**THEN** 一次性节点被跳过，对话图路由到正确的重谈入口点，已应用的状态变更在条件评估中正确反映。

14. **GIVEN** 选择节点呈现了洞察门控选项，**WHEN** 玩家选择并确认，**THEN** 选择不可撤销 — 对话立即沿该分支推进，无确认对话框或撤销选项。

15. **GIVEN** InnerMonologue 或 Narration 节点激活，**WHEN** 节点显示，**THEN** 无角色立绘（InnerMonologue 可显示主角内心标签，Narration 无名牌），文字框使用各节点类型的独立视觉样式。
