# 战斗 UI

> **Status**: Designed
> **Author**: user + game-designer + ux-designer
> **Last Updated**: 2026-06-03
> **Implements Pillar**: Pillar 3 — 武侠味先于游戏味（战斗是棋局，让棋手看到棋盘）

## Overview

战斗 UI 是《风止》行气战棋战斗的**战术信息平台**——将棋盘、行气、当前气机、身位、范围、内息与破绽等信息，通过武侠韵味的视觉语言呈现给玩家，确保每一次取位和出手都是有据可查的战术判断。

本系统有两层职责：

**信息层（让棋手看到棋盘）**：棋盘常驻显示单位位置、朝向、移动格、招式范围、行气条、行动队列与当前气机。招式 / 轻功 / 内功 / 道具面板只在当前行动角色被选中时展开；目标预览显示克制关系、预计破绽变化、侧背击收益和决胜窗口。这一切数据都通过战斗系统事件驱动（`XingqiAdvanced / ActorTurnStarted / MovePreviewChanged / MoveResolved / StaggerChanged / DecisiveWindowOpened`），保持零延迟同步。

**沉浸层（让棋盘有武侠质感）**：相同的信息不等于相同的呈现质感——克制命中时画面闪光、被克时微震、一击决胜时全屏慢动作拉伸时间。战斗 UI 通过演出语言，将数值结算翻译为"高手过招"的武侠美学，而非冰冷的 RPG 数字屏幕。

没有战斗 UI，玩家无法"观气取位"，无法感受到那个"踏入门中、一招分胜负"的瞬间——战斗系统的核心幻想将失去承载。

技术上，本系统订阅行气战棋战斗系统发布的事件，向玩家展示实时状态；玩家的移动、出手、调息、道具、轻功和内功切换选择通过 UI 层收集后传回战斗系统执行。

## Player Fantasy

**"江湖处处朦胧，唯独临敌时，棋盘向你彻底清明——你不是在读数字，你是在读气、读步、读破绽。"**

大多数武侠高手的绝学，不是提前知道对方下一招，而是看见对方此刻气机如何运转、脚步如何迟疑、门户如何露出。旁人看见剑光四射，你看见剑光之前的那一寸入门处。

这是战斗 UI 想要交给玩家的感受：**掌握了棋盘信息等于掌握了先机**——不是作弊，而是境界。

一场战斗的情感弧线是这样展开的：起初，敌方当前气机有时是灰色迷雾（"?"）——这是江湖的正常状态。你试探、走位、观察气机切换，雾一层层散。当刚 / 柔 / 巧气机变得清晰，你的决策从猜测变成判断，从判断变成笃定。

然后是那个决断的瞬间：破绽积满，决胜提示亮起，整个战场在你眼中静下来。所有数字仍在——气血条、内息条、破绽计数——但你此刻感受到的不是数字，而是那道缝隙。你按下，一切收束。

这就是战斗 UI 的核心体验：不是让你管理按钮，而是让你在最关键的时刻，拥有宗师一样的视野——**清楚地看见，笃定地踏步，笃定地落手**。

*Pillar 3 对齐*：UI 上的每个数字都有对应的武侠意象——"破绽"不是一个 stagger 计数器，它是你在对手防御上凿开的漏洞；"内息"不是 MP，它是你能不能撑到那一击的底气。

*设计测试*：如果玩家在战斗结束后说"我算赢了"，这个 UI 失败了；如果他说"我**看准气机，站到了该站的位置**"，才是成功。

## Detailed Design

### Core Rules

**1. 层级架构**

战斗 UI 由三个层级组成：
- **BoardTacticsLayer**（棋盘层）：显示方格、单位、朝向、移动路径、攻击范围、不可达格、侧背击预览和轻功路径。
- **WorldUnitLayer**（单位头顶层）：每个单位显示 HP 简条、行气条、当前气机、破绽状态和关键状态图标。
- **HUDLayer**（屏幕空间固定）：行动队列、当前行动菜单、招式/轻功/内功详情、目标预览、战斗日志、剧情目标和决胜提示。

**2. 当前气机显示系统**

每个参战单位头顶可显示当前气机图标。敌方默认显示当前运转内功的气机，而不是下一招意图：
- 刚 = 红色拳意符文
- 柔 = 蓝色水纹符文
- 巧 = 绿色风旋符文
- "?" = 灰色迷雾符文

图标由 `InnerPowerSwitched`、`MovePreviewChanged` 或洞察相关信息更新触发。高洞察只改变显示深度（如内功名称、可能招路、隐藏数值），不得改变行气或行动顺序。

**3. 行动菜单（移动 + 出手）**

角色行气满并进入 `ActorTurnStarted` 后，UI 默认聚焦当前单位所在棋盘格。玩家可以先选择移动，也可以原地停留；移动确认后进入出手动作选择。行动菜单包含：
- 出招：显示装备招式，含气质图标、内息消耗、范围/位移摘要、冷却和特殊效果。
- 切换内功：显示主内功与备用内功，切换后当前气机立即更新。
- 使用轻功：显示位移路径、内息消耗、冷却和是否保留行气。
- 调息：回复内息，并显示防护/破绽恢复预览。
- 使用道具：打开战斗背包，仅显示 `combat_usable: true` 的合法物品。
- 决胜一击：仅当目标破绽达标且当前角色有合法范围时显示高亮。

UI 不提供"普通攻击"兜底。最简单的攻击也必须来自已配置招式。

**效果预览行为**：悬停/聚焦到某个行动时，棋盘层和目标预览同步显示：
- 合法移动格、攻击范围、位移路径和不可达格。
- 当前目标气机与所选招式气质关系（克制 ✓ / 被克 ⚠ / 中性 =）。
- 预计伤害区间、预计破绽变化、侧击/背击收益、是否打开决胜窗口。
- 内息变化、冷却变化和行气回落/保留规则。

*设计意图*：让玩家凭棋盘和气机做武侠判断，同时给足战斗内数值透明度。

**灰显逻辑**：
- 内息不足 → 置灰 + 显示"差 X 内息"。
- 目标不合法 → 置灰 + 高亮缺失条件（距离、朝向、障碍、武器、冷却）。
- 冷却未好 → 置灰 + 显示剩余自然行动数。
- 禁用项可见但不可聚焦，符合 ADR-0002 焦点栈规则。

**决胜提示**：当目标进入"破绽大开"且当前行动角色有合法决胜范围，目标身上与行动菜单同时出现"▶ 决胜一击"金色脉冲提示。

**4. 资源条（气血 / 内息 / 破绽）**

每个参战角色在 HUD 区有一组资源条：
- **气血条（红）**：当前/最大值，击中时先闪白再扣减（非瞬降），下方弹出伤害数字
- **内息条（蓝墨）**：消耗时即时扣减可见；调息恢复时缓慢回升
- **破绽条（橙→红）**：0 到 5 的进度条；当破绽 ≥ 5 时，整条变深红 + 脉冲动效 + 对应角色身上出现"破绽！"浮字

**伤害数字样式**：
- 克制命中 → 数字放大 + 金色
- 同系命中 → 正常大小 + 白色
- 被克命中 → 数字缩小 + 灰色
- 暴击 → 数字额外放大 + 橙红 + 微爆炸特效

**5. 克制预览**

克制不再是独立按钮。当所选招式气质克制目标当前气机时，目标预览显示克制收益（伤害、破绽或行气干扰），确认招式命中后自然生效。

**6. 一击决胜演出流程（Engine.TimeScale）**

```
玩家选择"决胜一击"
  → Phase 1：伤害预结算（逻辑先行）
  → Phase 2：Engine.TimeScale 降至 0.2（~0.3 秒内插值过渡）
  → Phase 3：Camera2D 小幅推进+锁定目标（特写）
  → Phase 4：播放体系专属招式动画
       刚体系 → 劈裂光效 + 大地震动
       柔体系 → 水旋包裹 + 气旋扩散
       巧体系 → 瞬闪残影 + 多段切割线
  → Phase 5：伤害数字弹出（最大尺寸 + 黑边）
  → Phase 6：Engine.TimeScale 恢复至 1.0（~0.3 秒内插值）
  → Phase 7：Camera2D 归位
```

*注意*：TimeScale 变化会同时影响音效播放速度。击中声在 Phase 4 触发（此时 TimeScale 已低，效果为自然拖长）；TimeScale 恢复时配合鼓点音效标记战斗节奏回归。

**7. 围势提示**

当两个己方角色在同一行气周期内对同一目标形成围势并命中，在目标角色头顶浮现"围势！"字样，金色 + 合围线图标。该提示随破绽变化一并显示。

**8. 行动队列**

屏幕右上角显示未来 3-5 个即将行动单位，包含阵营、行气剩余、当前气机和破绽状态。多个角色同时行气满时，队列顺序必须与战斗系统排序一致。

**9. 手柄 / 键盘完整导航**

- 棋盘格、行动菜单、目标预览支持 D-pad/摇杆导航，A/确认键选定
- 决胜一击作为高亮行动存在于行动菜单中，不需要额外操作触达
- Godot 4.6 双焦点：鼠标悬停和手柄焦点可同时独立工作；面板打开时默认聚焦第一个可用招式（`grab_focus()`）
- 所有 `focus_neighbor_*` 在面板内配置为循环导航，防止焦点逃出面板

### States and Transitions

```
[INACTIVE]
  ↓ OnBattleStart
[BATTLE_ACTIVE]
  → 棋盘、单位头顶信息、行动队列刷新
  ↓ 动画完成
[ACTOR_TURN]
  → 默认聚焦当前行动单位
  → 选择移动或原地停留
  ↓ 移动确认
[ACTION_PREVIEW]
  → 选择出招 / 调息 / 道具 / 轻功 / 切换内功 / 决胜
  → 显示范围、路径、克制、身位、破绽和资源预览
  ↓ 确认动作
[RESOLVING_ACTION]
  → 播放移动 / 出手动画
  → 气血 / 内息 / 破绽 / 行气条动态更新
  → 一击决胜触发时进入 TimeScale 演出子状态
  ↓ 结算完成
[QUEUE_ADVANCE]
  → 更新行动队列
  → 检查战斗结束
  ↓ 未结束 → 回到 BATTLE_ACTIVE / ACTOR_TURN
  ↓ 已结束
[BATTLE_END]
  → 胜利/失败动画
  → 结算界面：战斗统计、获得物品
```

## Formulas

战斗 UI 是 Presentation 层——不自行计算战斗数值；所有预计伤害、预计破绽和克制收益都来自行气战棋战斗系统的预览 DTO。以下两个公式仅用于视觉表现参数化，不影响战斗逻辑。

---

**F1. 伤害数字缩放系数**

| 情况 | font_scale（相对基准） | 颜色 |
|---|---|---|
| 克制命中 | ×1.4 | 金色 `#FFD700` |
| 同系命中 | ×1.0 | 白色 `#FFFFFF` |
| 被克命中 | ×0.75 | 灰色 `#AAAAAA` |
| 暴击（叠加） | 额外 ×1.3 | 橙红 `#FF6600` |
| 一击决胜 | ×2.0（固定，不叠加） | 深金 `#FF8C00` + 黑边 |

**Variables:**

| 变量 | 符号 | 类型 | 范围 | 说明 |
|---|---|---|---|---|
| 基准字号 | `base_damage_font_size` | int | 20-32 px | 调参控制；见 Tuning Knobs |
| 缩放倍率 | `scale_factor` | float | 0.75-2.0 | 按命中类型查表 |

**Output Range**: 字号 15–64 px（基准×缩放倍率）

---

**F2. TimeScale 插值（一击决胜演出）**

```
慢进：TimeScale = lerp(1.0, decisive_timescale_min, t / slow_in_duration)
演出：TimeScale = decisive_timescale_min
快出：TimeScale = lerp(decisive_timescale_min, 1.0, t / slow_out_duration)
```

**Variables:**

| 变量 | 符号 | 类型 | 范围 | 说明 |
|---|---|---|---|---|
| 最低倍速 | `decisive_timescale_min` | float | 0.1-0.4 | 0.2 = 1/5 速，拖长感强 |
| 慢进时长 | `slow_in_duration` | float | 0.1-0.5 s | 过渡太快显突兀 |
| 演出持续 | `hold_duration` | float | 0.5-2.0 s | 太长显拖沓 |
| 快出时长 | `slow_out_duration` | float | 0.1-0.5 s | 配合鼓点音效 |

**Output Range**: TimeScale 0.1–1.0（整个演出 ~1.6 s，默认参数）

## Edge Cases

- **如果 `XingqiAdvanced` 到达时某单位已落败**：跳过该单位的行气条刷新，并确保其从行动队列中消隐，不崩溃。

- **如果战斗中玩家切换目标时当前决胜提示目标变更**：关闭旧目标的"决胜一击"高亮，重新检查新目标破绽状态，若满足则显示。

- **如果招式面板打开时战斗系统广播 `OnDamageDealt`（多角色同时行动）**：UI 更新不中断面板交互，资源条在后台刷新，待玩家关闭面板后显示最新值（或非阻塞式刷新而不关闭面板）。

- **如果 Engine.TimeScale 在演出途中被其他系统修改（如暂停菜单呼出）**：TimeScale 演出应通过独立 Tween 管理，暂停菜单关闭后恢复演出而不重置。

- **如果多个目标同时破绽达标**：每个满足条件的目标各自显示"破绽大开"浮字；行动菜单中"决胜一击"默认指向当前焦点目标，玩家可通过目标选择切换。

- **如果内息在当前选择确认前被状态效果改变**：行动菜单刷新一次可用内息，若某招式因此变得不可用，即时变灰 + 提示"内息不足"。

- **如果 "?" 气机图标在洞察提升后变得可读**：图标从迷雾动效过渡到正确气机颜色，带解迷动画（不是突兀替换）。

- **如果手柄玩家在招式面板中下移超出最后一个招式**：焦点循环回第一个招式（循环导航），不丢失焦点到面板外。

- **如果一击决胜演出期间玩家按了任何输入键**：演出不可跳过（保护武侠高光时刻）；若需要允许跳过，由 Tuning Knobs 的 `allow_decisive_skip` 控制。

## Dependencies

| 方向 | 系统 | 依赖类型 | 接口说明 |
|---|---|---|---|
| 上游（硬） | 行气战棋战斗 | 硬 | 订阅战斗事件（`XingqiAdvanced / ActorTurnStarted / MovePreviewChanged / MoveResolved / StaggerChanged / DecisiveWindowOpened / BattleEnded`）；战斗不存在则 UI 无法展示 |
| 上游（硬） | 武学组合 | 硬 | 读取 `GetEquippedMoves()` 和 `GetMoveDetails(id)` 填充招式面板；武学系统不存在则面板无数据 |
| 下游（软） | 音乐/音效 | 软 | 战斗 UI 触发时机（如一击决胜阶段）与音效配合，但 UI 系统本身不驱动音效系统——由音效系统订阅相同事件 |
| 下游（软） | CG/演出 | 软 | 一击决胜演出动画可能与 CG 系统共享 Camera2D 控制权；届时需要优先级协调，但两者互不强依赖 |

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 过高/过低影响 |
|---|---|---|---|
| `base_damage_font_size` | 24 px | 18-36 px | 过大→占据画面；过小→视觉反馈弱 |
| `decisive_timescale_min` | 0.2 | 0.1-0.4 | 过低→过于缓慢/夸张；过高→慢动作感消失 |
| `decisive_slowin_duration` | 0.3 s | 0.1-0.5 s | 过短→突兀；过长→等待感强 |
| `decisive_hold_duration` | 1.0 s | 0.5-2.0 s | 过短→高光太快过；过长→每次都显臃肿 |
| `decisive_slowout_duration` | 0.3 s | 0.1-0.5 s | 同慢进 |
| `qi_icon_fadein_duration` | 0.4 s | 0.2-0.8 s | 过短→突兀出现；过长→气机揭示拖沓 |
| `resource_bar_update_speed` | 0.25 s | 0.1-0.5 s | 过快→变化不可追踪；过慢→响应感差 |
| `damage_float_duration` | 1.2 s | 0.8-2.0 s | 过短→来不及看；过长→屏幕很快堆满数字 |
| `stagger_pulse_speed` | 0.5 s 间隔 | 0.3-1.0 s | 影响破绽临界时的紧张感 |
| `allow_decisive_skip` | false | bool | 设为 true 时允许玩家按键跳过演出（可访问性选项，默认关）|
| `formation_float_visible_duration` | 1.0 s | 0.5-2.0 s | 围势提示浮字显示时长 |
| `action_queue_visible_count` | 5 | 3-7 | 过少→难以规划；过多→挤占画面 |

## Visual/Audio Requirements

### 招式选择面板

面板形态：**残卷帛书**——已展开的半旧绢布帛书，边缘有轻微磨损像素。每个招式格是一段短墨迹区域，分隔线用细毛笔横线。字体腔调：像素化仿宋/隶书风，招式名主字较大，消耗和效果用更小字号。置灰时字色降至 30% 透明度。面板背景：`#2A2A20`；边框：`#5A4A30`（旧铜锈色）。

### 资源条视觉语言

三条资源条用完全不同的形态表达，拒绝"同款进度条换色"：

- **气血（生机焰）**：一组竖向排列的小火焰像素块，满血为橙红光焰，受伤后逐格熄灭变灰。最后 30% 时火焰变暗红 + 轻微颤抖动效
- **内息（砚台墨）**：横向砚台形容器，墨水从左向右消耗。消耗时墨色向右收缩，恢复时从左缓慢渗回。满=深蓝墨 `#1A2A4A`；空=浅灰白
- **破绽（玉裂格）**：5 格离散计数器，每格是一块玉石像素。0 格=完整白玉；填充后逐格变成裂纹橙；≥5 格时整排血红 + 裂纹动效脉冲

### 破绽爆满视觉语言

"破绽！"浮字：**篆刻印章风**——朱砂红底白文，方形印章形态，像素化外框。动效：从大到正常尺寸快速缩小（盖章感），带轻微旋转，停留 1-2 帧后保持。

### 当前气机图标精细化

每个图标 8×8 px 基础单元，放大 3-4x 显示：

- **刚（赤红）**：钟鼎文"力"字变体，下部笔画加粗为拳形。主色 `#C03020`，亮部 `#FF4A30`
- **柔（蓝墨）**：小篆"水"字，三点水笔画呈流动弧线。主色 `#2A508A`，亮部 `#4A80C0`
- **巧（碧绿）**：甲骨文"风"旋涡形，逆时针螺旋感。主色 `#205A30`，亮部 `#40A050`
- **?（迷雾）**：故意残缺的像素方块，右下角缺口，左上角多余噪点，传达"信息不完整"。颜色 `#6A6A6A`，淡入时从全噪点渐变到残缺方块形态

图标出现时：从模糊（高斯点状噪点）渐变至清晰符文，持续 `qi_icon_fadein_duration` 秒。

### UI 整体色调规范（7色主色板）

| 色彩用途 | 十六进制 | 饱和度上限 | 适用范围 |
|---|---|---|---|
| 面板底色 | `#2A2A20` | 5% | 所有面板背景 |
| 主文字 | `#E8E0D0` | 8% | 招式名/数值 |
| 弱提示文字 | `#8A8070` | 8% | 消耗数字/效果摘要 |
| 置灰文字 | `#4A4840` | 5% | 不可用招式 |
| 气血焰红 | `#C03020` | 40% | 气血条/刚系图标 |
| 内息墨蓝 | `#2A508A` | 40% | 内息条/柔系图标 |
| **战术金（严格保留）** | `#D4A020` | 55% | **仅 3 处**：决胜一击提示 / 围势！浮字 / 克制标记 ✓ |

战术金是唯一高饱和元素，稀缺性赋予它高亮权重。其他任何地方不得使用。

### 音效腔调规范

骨架音效：Foley 质感（纸张/竹/金属碰撞/呼吸）。情绪着色：古乐器（古琴/箫/琵琶/铜磬）在关键时刻叠加。

| UI 事件 | 音效 | 说明 |
|---|---|---|
| 气机图标出现 | "唰"（纸张翻动/细竹声） | 信息揭示的轻盈感 |
| 招式面板弹出 | 轻微展卷声（绢布） | 开启武学帛书 |
| 招式选中/确认 | 轻木击声 | 落子感 |
| 克制命中 | 琵琶短拨 + 金属共鸣 | 锐利 |
| 被克制命中 | 低沉木击 | 钝感 |
| 破绽爆满 | 铜磬洪声 | 道理揭示，非暴击 |
| 一击决胜起手 | 古琴弦拨（单音拉长） | 时间拉伸感配合慢动作 |
| 一击决胜命中 | 全频爆发 + 箫长音余韵 | 高潮 + 余音 |
| 围势触发 | 双声短击 | 两人合围 |
| 行动队列刷新 | 极轻竹筹声 | 不抢占出手反馈 |
| **保持静音** | 手柄导航焦点移动 / 内息自然恢复 / 破绽小幅填充（<5）/ 面板关闭 | 稀缺音效才有重量 |

## UI Requirements

战斗 UI 贡献一整套战斗屏幕，主要 UI 组件需求：

**布局（1920×1080 参考分辨率）**：
- 中央：棋盘、角色、移动路径、招式范围、朝向和合法目标。
- 单位头顶：HP 简条、行气条、当前气机、破绽状态和关键状态图标。
- 右上：行动队列，显示未来 3-5 个即将行动单位。
- 下方/角色附近：当前行动菜单与招式 / 轻功 / 内功详情。
- 右侧或下侧：目标预览面板，显示克制、身位、预计伤害、预计破绽和决胜可用性。

**输入要求**：
- 所有交互必须支持鼠标点击 + 键盘 + 手柄（D-pad/摇杆）三种输入
- 禁止任何 hover-only 交互（Steam Deck 兼容）
- 行动开始时必须默认聚焦当前行动单位所在棋盘格
- 行动菜单开启时必须自动获得手柄焦点
- 焦点不得逃出当前焦点栈（棋盘、行动菜单、目标预览各自循环导航）

**可访问性**：
- 体系区分不可仅依赖颜色（需结合图标形状/纹理——刚=拳形/柔=流线/巧=旋涡）
- `allow_decisive_skip` 参数为可访问性预留（默认关，v1.1 考虑暴露为设置选项）
- 字体基准 24 px，支持缩放（由全局设置控制）

**分辨率适配**：面板和资源条使用相对布局（锚点系统），确保在 1280×720 和 2560×1440 下均可用。

📌 **UX Flag — 战斗 UI**：本系统是全游戏 UI 密度最高的屏幕。Pre-Production 阶段运行 `/ux-design` 为战斗主界面创建完整 UX 规格（含线框图、焦点流、触控区尺寸），在写 Epics 之前完成。

## Acceptance Criteria

1. **GIVEN** 行气战棋战斗触发 `XingqiAdvanced`，**WHEN** UI 接收事件，**THEN** 所有参战单位头顶行气条和行动队列同步更新，且队列顺序与战斗系统排序一致。

2. **GIVEN** 玩家方角色进入 `ActorTurnStarted`，**WHEN** UI 接收事件，**THEN** 焦点默认落在当前角色所在棋盘格，并显示合法移动格与原地停留选项。

3. **GIVEN** 玩家悬停/聚焦到一个克制目标当前气机的招式，**WHEN** 预览卡显示，**THEN** 克制标记 ✓ 高亮，显示预计伤害区间、预计破绽变化和合法范围；不显示任何"反制按钮"。

4. **GIVEN** 目标破绽达标且当前角色有合法范围，**WHEN** `DecisiveWindowOpened` 事件到达，**THEN** 行动菜单显示"▶ 决胜一击"金色高亮行，目标角色身上出现"破绽大开"脉冲浮字。

5. **GIVEN** 玩家选择"决胜一击"，**WHEN** 确认触发，**THEN** Engine.TimeScale 在 0.3s 内降至 0.2，播放体系专属动画，完成后 TimeScale 在 0.3s 内恢复至 1.0，整个演出期间玩家输入被屏蔽。

6. **GIVEN** 两个己方角色在同一行气周期内对同一目标形成围势，**WHEN** 第二个角色命中该目标，**THEN** 目标处浮现"围势！"金色字样，持续 `formation_float_visible_duration` 秒。

7. **GIVEN** 角色选择使用轻功，**WHEN** UI 进入预览态，**THEN** 棋盘显示位移路径、目的格、内息消耗、冷却和是否保留行气。

8. **GIVEN** 手柄玩家在行动菜单底部选项处按下移，**WHEN** 导航触发，**THEN** 焦点循环回行动菜单第一个可聚焦选项，不丢失焦点到面板外。

9. **GIVEN** 鼠标玩家和手柄玩家在 Godot 4.6 双焦点系统下同时存在，**WHEN** 鼠标悬停某棋盘格 + 手柄焦点在行动菜单，**THEN** 两者各自的预览状态独立显示，互不干扰。

10. **GIVEN** 某敌方角色已落败，**WHEN** `XingqiAdvanced` 或 `MovePreviewChanged` 广播仍包含该目标，**THEN** 已落败目标从行动队列和可选目标中消隐，其他目标正常显示，不崩溃。

## Open Questions

1. **结算界面（Battle End）的具体内容**：战斗结束后显示什么统计数据？武学残片获得动画属于战斗 UI 还是单独的物品获取 UI？（待物品/道具系统和主线叙事设计解决）

2. **多角色战斗时的面板管理**：当玩家方有两个角色时，是为每个角色各弹出一次面板（顺序决策），还是同时显示两个面板并排？顺序决策更清晰但更慢；并排更快但信息密度大。（待 UX 设计验证）

3. **TimeScale 与暂停菜单的优先级**：如果玩家在一击决胜演出途中强行暂停，是立即冻结演出还是让演出完成再暂停？（待暂停/设置系统设计解决）

4. **气机图标的"模糊洞察"表现**：当洞察不足但存在部分线索时，"?"是稳定显示还是图标在"清晰/模糊"之间短暂摇摆？（设计感上闪烁更有趣，但对玩家可能造成混淆——待 MVP 玩测验证）
