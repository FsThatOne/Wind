# 战斗 UI

> **Status**: Designed
> **Author**: user + game-designer + ux-designer
> **Last Updated**: 2026-06-03
> **Implements Pillar**: Pillar 3 — 武侠味先于游戏味（战斗是棋局，让棋手看到棋盘）

## Overview

战斗 UI 是《孤山遗剑》回合制战斗的**信息平台**——将战斗系统的所有运算结果，通过武侠韵味的视觉语言呈现给玩家，确保每一次过招都是有据可查的智力博弈。

本系统有两层职责：

**信息层（让棋手看到棋盘）**：每回合开始时，敌方头顶浮现意图图标（刚=红色拳意 / 柔=蓝色水纹 / 巧=绿色风旋，或"?"迷雾）；招式选择面板展示可用武学的体系、内息消耗和当前效果；气血/内息/破绽条实时刷新；当破绽积累到阈值，"决胜一击"高亮提示玩家那个一击定胜负的窗口就在眼前。这一切数据都通过战斗系统事件驱动（`OnIntentRevealed / OnDamageDealt / OnStaggerChanged / OnDecisiveStrikeAvailable`），保持零延迟同步。

**沉浸层（让棋盘有武侠质感）**：相同的信息不等于相同的呈现质感——克制命中时画面闪光、被克时微震、一击决胜时全屏慢动作拉伸时间。战斗 UI 通过演出语言，将数值结算翻译为"高手过招"的武侠美学，而非冰冷的 RPG 数字屏幕。

没有战斗 UI，玩家无法"读穿"对手，无法感受到那个"断水寒光、一招分胜负"的瞬间——战斗系统的核心幻想将失去承载。

技术上，本系统订阅战斗系统发布的事件，向玩家展示实时状态；玩家的招式选择通过 UI 层收集后传回战斗系统执行。

## Player Fantasy

**"江湖处处朦胧，唯独临敌时，世界向你彻底清明——你不是在读数字，你是在读人。"**

大多数武侠高手的绝学，正是这种**洞察力**。旁人看见剑光四射，你看见剑光之前的那一寸杀机；旁人等待对手出招，你在对手出招之前便已知晓。

这是战斗 UI 想要交给玩家的感受：**掌握了信息等于掌握了先机**——不是作弊，而是境界。

一场战斗的情感弧线是这样展开的：起初，敌方有时是灰色迷雾（"?"）——这是江湖的正常状态。你试探、记招，雾一层层散。当意图图标的颜色变得清晰（赤红/蓝水/碧旋），你的决策从猜测变成判断，从判断变成笃定。

然后是那个决断的瞬间：破绽积满，决胜提示亮起，整个战场在你眼中静下来。所有数字仍在——气血条、内息条、破绽计数——但你此刻感受到的不是数字，而是那道缝隙。你按下，一切收束。

这就是战斗 UI 的核心体验：不是让你管理状态，而是让你在最关键的时刻，拥有宗师一样的视野——**清楚地看见，笃定地落手**。

*Pillar 3 对齐*：UI 上的每个数字都有对应的武侠意象——"破绽"不是一个 stagger 计数器，它是你在对手防御上凿开的漏洞；"内息"不是 MP，它是你能不能撑到那一击的底气。

*设计测试*：如果玩家在战斗结束后说"我算赢了"，这个 UI 失败了；如果他说"我**看穿**了他"，才是成功。

## Detailed Design

### Core Rules

**1. 层级架构**

战斗 UI 由两个 CanvasLayer 组成：
- **WorldIntentLayer**（场景层，Z-index 高于角色）：意图图标跟随敌方角色，在世界空间中浮现于头顶
- **HUDLayer**（屏幕空间固定）：资源条、招式选择面板、HUD 意图汇总区、回合计数、协同/决胜提示

**2. 意图图标系统（双层展示）**

*场景层*：每个敌方角色头顶各有一个意图图标槽。回合开始时，`OnIntentRevealed` 事件触发，图标从透明淡入 + 轻微上升动画。图标内容：
- 刚 = 红色拳意符文
- 柔 = 蓝色水纹符文
- 巧 = 绿色风旋符文
- "?" = 灰色迷雾符文

*HUD 汇总区*（屏幕左上角）：所有参战敌方的意图图标横排汇总，用于玩家在视线不在场景层时快速浏览全局。

**3. 招式选择面板（弹出 + 效果预览）**

玩家轮到某角色行动时，面板从该角色附近弹出（或中下区）。面板内容：
- 6 个装备招式格，每格显示：招式名 + **体系图标（体系色调，不附加品质颜色）** + 内息消耗 + **触发条件图标（一个小图标代表条件类型）** + 特殊效果摘要（一行）。**玩家通过条件图标和效果描述做决策，不靠颜色层级判断取舍**
- 心法专属招式（若有）：标注"心法"角标
- 调息（内息回复，本回合不攻击）
- 普通攻击（零消耗，无体系，低伤害，紧急备用）

**效果预览行为**：悬停/聚焦到某个招式时，面板旁显示预览卡，内容：
- 体系关系标记（克制 ✓ 绿高亮 / 被克 ⚠ 橙警告 / 同系 = 中性）——**只显示关系，不显示数字**
- 反制提示（若满足反制条件：显示"可反制 - 消耗 3 内息"，无具体数值预测）

*设计意图*：让玩家凭武侠直觉读体系，而非算伤害期望值。

**灰显逻辑**：
- 内息不足 → 置灰 + 显示"差 X 内息"
- 心法被封印 → 心法专属招式置灰 + 显示"心法封印中"

**决胜提示**：当当前目标破绽 ≥ 5，面板顶部插入特殊高亮行"▶ 决胜一击"，金色脉冲，优先吸引注意力。

**4. 资源条（气血 / 内息 / 破绽）**

每个参战角色在 HUD 区有一组资源条：
- **气血条（红）**：当前/最大值，击中时先闪白再扣减（非瞬降），下方弹出伤害数字
- **内息条（蓝墨）**：消耗时即时扣减可见；调息恢复时缓慢回升
- **破绽条（橙→红）**：0 到 5 的进度条；当破绽 ≥ 5 时，整条变深红 + 脉冲动效 + 对应角色身上出现"破绽！"浮字

**伤害数字样式**：
- 克制命中 → 数字放大 + 金色
- 同系命中 → 正常大小 + 白色
- 被克命中 → 数字缩小 + 灰色
- 暴击 → 数字额外放大 + 橙红 + 微爆炸特效

**5. 反制按钮**

当玩家选中的招式体系克制目标当前公开体系，且内息 ≥ 3 时：该招式格旁出现「反制」标签（金色），确认选择即自动扣除 3 内息并激活反制判定。若内息 < 3，标签显示但置灰（"内息不足"）。

**6. 一击决胜演出流程（Engine.TimeScale）**

```
玩家选择"决胜一击"
  → Phase 1：伤害预结算（逻辑先行）
  → Phase 2：Engine.TimeScale 降至 0.2（~0.3 秒内插值过渡）
  → Phase 3：Camera2D 小幅推进+锁定目标（特写）
  → Phase 4：播放体系专属招式动画
       刚体系 → 劈裂光效 + 大地震动
       柔体系 → 水旋包裹 + 气旋扩散
       巧体系 → 瞬闪残影 + 多段切割线
  → Phase 5：伤害数字弹出（最大尺寸 + 黑边）
  → Phase 6：Engine.TimeScale 恢复至 1.0（~0.3 秒内插值）
  → Phase 7：Camera2D 归位
```

*注意*：TimeScale 变化会同时影响音效播放速度。击中声在 Phase 4 触发（此时 TimeScale 已低，效果为自然拖长）；TimeScale 恢复时配合鼓点音效标记战斗节奏回归。

**7. 协同提示**

当两个己方角色在同一回合对同一目标选择了克制体系招式（结算前检测），在目标角色头顶浮现"协同！"字样，金色 + 双拳图标。结算时该提示随伤害弹出一并显示。

**8. 回合计数**

屏幕右上角显示「第 [N] 回合」，达到 12 回合后额外变色（橙），14 回合红色，提醒玩家接近上限。

**9. 手柄 / 键盘完整导航**

- 招式面板支持 D-pad 上下导航，A/确认键选定
- 反制和决胜一击作为独立行存在于面板中，不需要额外操作触达
- Godot 4.6 双焦点：鼠标悬停和手柄焦点可同时独立工作；面板打开时默认聚焦第一个可用招式（`grab_focus()`）
- 所有 `focus_neighbor_*` 在面板内配置为循环导航，防止焦点逃出面板

### States and Transitions

```
[INACTIVE]
  ↓ OnBattleStart
[ROUND_START]
  → 意图图标浮现动画
  → 资源条刷新
  ↓ 动画完成
[PLAYER_DECISION]
  → 为当前待决策角色弹出招式面板
  → 等待玩家确认招式
  ↓ 所有角色决策完成
[RESOLVING]
  → 按速度顺序播放行动动画
  → 气血/内息/破绽条动态更新
  → 一击决胜触发时进入 TimeScale 演出子状态
  ↓ 结算全部完成
[ROUND_END]
  → 破绽衰减刷新
  → 检查战斗结束
  ↓ 未结束 → 回到 ROUND_START
  ↓ 已结束
[BATTLE_END]
  → 胜利/失败动画
  → 结算界面：战斗统计、获得物品
```

### Interactions with Other Systems

| 系统 | 接口 | 数据方向 | UI 行为 |
|---|---|---|---|
| **回合制战斗** | `OnIntentRevealed(enemies[])` | 战斗→UI | 触发意图图标显示动画 |
| | `OnDamageDealt(source, target, amount, type)` | 战斗→UI | 弹出伤害数字，刷新气血条 |
| | `OnStaggerChanged(target, delta)` | 战斗→UI | 刷新破绽条；≥5 时脉冲+浮字 |
| | `OnDecisiveStrikeAvailable(target)` | 战斗→UI | 高亮面板"决胜一击"选项 |
| | `OnBattleEnd(result)` | 战斗→UI | 切换到 BATTLE_END 状态 |
| | `OnNeixiChanged(actor, amount)` | 战斗→UI | 刷新内息条 |
| **武学组合** | `GetEquippedMoves()` | 武学→UI | 填充招式选择面板 |
| | `GetMoveDetails(id)` | 武学→UI | 显示招式名/体系/消耗/倍率/`special_condition`/`special_effect`；批注版传回 `condition_override` 和 `effect_override` |
| 玩家输入 | `MoveSelected(actorId, moveId, targetId, isCounter)` | UI→战斗 | 玩家确认后传回战斗系统 |

## Formulas

战斗 UI 是 Presentation 层——不做数值计算，不显示伤害预测数字（玩家靠体系关系和感觉决策，而非计算）。以下两个公式仅用于视觉表现参数化，不影响战斗逻辑。

---

**F1. 伤害数字缩放系数**

| 情况 | font_scale（相对基准） | 颜色 |
|---|---|---|
| 克制命中 | ×1.4 | 金色 `#FFD700` |
| 同系命中 | ×1.0 | 白色 `#FFFFFF` |
| 被克命中 | ×0.75 | 灰色 `#AAAAAA` |
| 暴击（叠加） | 额外 ×1.3 | 橙红 `#FF6600` |
| 一击决胜 | ×2.0（固定，不叠加） | 深金 `#FF8C00` + 黑边 |

**Variables:**

| 变量 | 符号 | 类型 | 范围 | 说明 |
|---|---|---|---|---|
| 基准字号 | `base_damage_font_size` | int | 20-32 px | 调参控制；见 Tuning Knobs |
| 缩放倍率 | `scale_factor` | float | 0.75-2.0 | 按命中类型查表 |

**Output Range**: 字号 15–64 px（基准×缩放倍率）

---

**F2. TimeScale 插值（一击决胜演出）**

```
慢进：TimeScale = lerp(1.0, decisive_timescale_min, t / slow_in_duration)
演出：TimeScale = decisive_timescale_min
快出：TimeScale = lerp(decisive_timescale_min, 1.0, t / slow_out_duration)
```

**Variables:**

| 变量 | 符号 | 类型 | 范围 | 说明 |
|---|---|---|---|---|
| 最低倍速 | `decisive_timescale_min` | float | 0.1-0.4 | 0.2 = 1/5 速，拖长感强 |
| 慢进时长 | `slow_in_duration` | float | 0.1-0.5 s | 过渡太快显突兀 |
| 演出持续 | `hold_duration` | float | 0.5-2.0 s | 太长显拖沓 |
| 快出时长 | `slow_out_duration` | float | 0.1-0.5 s | 配合鼓点音效 |

**Output Range**: TimeScale 0.1–1.0（整个演出 ~1.6 s，默认参数）

## Edge Cases

- **如果 `OnIntentRevealed` 到达时当前目标已死亡（多目标战斗中某敌提前落败）**：跳过该目标的意图动画，图标槽变暗/消隐，不崩溃。

- **如果战斗中玩家切换目标时当前决胜提示目标变更**：关闭旧目标的"决胜一击"高亮，重新检查新目标破绽状态，若满足则显示。

- **如果招式面板打开时战斗系统广播 `OnDamageDealt`（多角色同时行动）**：UI 更新不中断面板交互，资源条在后台刷新，待玩家关闭面板后显示最新值（或非阻塞式刷新而不关闭面板）。

- **如果 Engine.TimeScale 在演出途中被其他系统修改（如暂停菜单呼出）**：TimeScale 演出应通过独立 Tween 管理，暂停菜单关闭后恢复演出而不重置。

- **如果多个目标同回合破绽达标**：每个满足条件的目标各自显示"破绽！"浮字，面板中"决胜一击"默认高亮第一个满足条件的目标，玩家可通过目标选择切换。

- **如果内息在当前选择确认前被同回合另一个己方角色消耗（多角色战斗）**：面板在该角色选招时刷新一次可用内息，若某招式因此变得不可用，即时变灰 + 提示"内息已被消耗"。

- **如果 "?" 意图图标显示后该敌下回合 intent 洞察成功（重新判定）**：图标从迷雾动效过渡到正确体系颜色，带解迷动画（不是突兀替换）。

- **如果手柄玩家在招式面板中下移超出最后一个招式**：焦点循环回第一个招式（循环导航），不丢失焦点到面板外。

- **如果一击决胜演出期间玩家按了任何输入键**：演出不可跳过（保护武侠高光时刻）；若需要允许跳过，由 Tuning Knobs 的 `allow_decisive_skip` 控制。

## Dependencies

| 方向 | 系统 | 依赖类型 | 接口说明 |
|---|---|---|---|
| 上游（硬） | 回合制战斗 | 硬 | 订阅战斗事件（`OnIntentRevealed / OnDamageDealt / OnStaggerChanged / OnDecisiveStrikeAvailable / OnBattleEnd / OnNeixiChanged`）；战斗不存在则 UI 无法展示 |
| 上游（硬） | 武学组合 | 硬 | 读取 `GetEquippedMoves()` 和 `GetMoveDetails(id)` 填充招式面板；武学系统不存在则面板无数据 |
| 下游（软） | 音乐/音效 | 软 | 战斗 UI 触发时机（如一击决胜阶段）与音效配合，但 UI 系统本身不驱动音效系统——由音效系统订阅相同事件 |
| 下游（软） | CG/演出 | 软 | 一击决胜演出动画可能与 CG 系统共享 Camera2D 控制权；届时需要优先级协调，但两者互不强依赖 |

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 过高/过低影响 |
|---|---|---|---|
| `base_damage_font_size` | 24 px | 18-36 px | 过大→占据画面；过小→视觉反馈弱 |
| `decisive_timescale_min` | 0.2 | 0.1-0.4 | 过低→过于缓慢/夸张；过高→慢动作感消失 |
| `decisive_slowin_duration` | 0.3 s | 0.1-0.5 s | 过短→突兀；过长→等待感强 |
| `decisive_hold_duration` | 1.0 s | 0.5-2.0 s | 过短→高光太快过；过长→每次都显臃肿 |
| `decisive_slowout_duration` | 0.3 s | 0.1-0.5 s | 同慢进 |
| `intent_icon_fadein_duration` | 0.4 s | 0.2-0.8 s | 过短→突兀出现；过长→等待意图太久 |
| `resource_bar_update_speed` | 0.25 s | 0.1-0.5 s | 过快→变化不可追踪；过慢→响应感差 |
| `damage_float_duration` | 1.2 s | 0.8-2.0 s | 过短→来不及看；过长→屏幕很快堆满数字 |
| `stagger_pulse_speed` | 0.5 s 间隔 | 0.3-1.0 s | 影响破绽临界时的紧张感 |
| `round_warning_threshold` | 12 回合 | 10-14 | 过早→虚惊；过晚→玩家来不及反应 |
| `allow_decisive_skip` | false | bool | 设为 true 时允许玩家按键跳过演出（可访问性选项，默认关）|
| `coop_float_visible_duration` | 1.0 s | 0.5-2.0 s | 协同提示浮字显示时长 |

## Visual/Audio Requirements

### 招式选择面板

面板形态：**残卷帛书**——已展开的半旧绢布帛书，边缘有轻微磨损像素。每个招式格是一段短墨迹区域，分隔线用细毛笔横线。字体腔调：像素化仿宋/隶书风，招式名主字较大，消耗和效果用更小字号。置灰时字色降至 30% 透明度。面板背景：`#2A2A20`；边框：`#5A4A30`（旧铜锈色）。

### 资源条视觉语言

三条资源条用完全不同的形态表达，拒绝"同款进度条换色"：

- **气血（生机焰）**：一组竖向排列的小火焰像素块，满血为橙红光焰，受伤后逐格熄灭变灰。最后 30% 时火焰变暗红 + 轻微颤抖动效
- **内息（砚台墨）**：横向砚台形容器，墨水从左向右消耗。消耗时墨色向右收缩，恢复时从左缓慢渗回。满=深蓝墨 `#1A2A4A`；空=浅灰白
- **破绽（玉裂格）**：5 格离散计数器，每格是一块玉石像素。0 格=完整白玉；填充后逐格变成裂纹橙；≥5 格时整排血红 + 裂纹动效脉冲

### 破绽爆满视觉语言

"破绽！"浮字：**篆刻印章风**——朱砂红底白文，方形印章形态，像素化外框。动效：从大到正常尺寸快速缩小（盖章感），带轻微旋转，停留 1-2 帧后保持。

### 意图图标精细化

每个图标 8×8 px 基础单元，放大 3-4x 显示：

- **刚（赤红）**：钟鼎文"力"字变体，下部笔画加粗为拳形。主色 `#C03020`，亮部 `#FF4A30`
- **柔（蓝墨）**：小篆"水"字，三点水笔画呈流动弧线。主色 `#2A508A`，亮部 `#4A80C0`
- **巧（碧绿）**：甲骨文"风"旋涡形，逆时针螺旋感。主色 `#205A30`，亮部 `#40A050`
- **?（迷雾）**：故意残缺的像素方块，右下角缺口，左上角多余噪点，传达"信息不完整"。颜色 `#6A6A6A`，淡入时从全噪点渐变到残缺方块形态

图标出现时：从模糊（高斯点状噪点）渐变至清晰符文，持续 `intent_icon_fadein_duration` 秒。

### UI 整体色调规范（7色主色板）

| 色彩用途 | 十六进制 | 饱和度上限 | 适用范围 |

| 面板底色 | `#2A2A20` | 5% | 所有面板背景 |
| 主文字 | `#E8E0D0` | 8% | 招式名/数值 |
| 弱提示文字 | `#8A8070` | 8% | 消耗数字/效果摘要 |
| 置灰文字 | `#4A4840` | 5% | 不可用招式 |

### 音效腔调规范

骨架音效：Foley 质感（纸张/竹/金属碰撞/呼吸）。情绪着色：古乐器（古琴/箫/琵琶/铜磬）在关键时刻叠加。

| UI 事件 | 音效 | 说明 |
|---|---|---|
| 意图图标出现 | "唰"（纸张翻动/细竹声） | 信息揭示的轻盈感 |
| 招式面板弹出 | 轻微展卷声（绢布） | 开启武学帛书 |
| 招式选中/确认 | 轻木击声 | 落子感 |
| 克制命中 | 琵琶短拨 + 金属共鸣 | 锐利 |
| 被克制命中 | 低沉木击 | 钝感 |
| 破绽爆满 | 铜磬洪声 | 道理揭示，非暴击 |
| 一击决胜起手 | 古琴弦拨（单音拉长） | 时间拉伸感配合慢动作 |
| 一击决胜命中 | 全频爆发 + 箫长音余韵 | 高潮 + 余音 |
| 协同触发 | 双声短击 | 两人共鸣 |
| 回合数警告（12 回合） | 低频脉冲（无音调） | 沉默的压迫感 |
| **保持静音** | 手柄导航焦点移动 / 内息自然恢复 / 破绽小幅填充（<5）/ 面板关闭 | 稀缺音效才有重量 |

## UI Requirements

战斗 UI 贡献一整套战斗屏幕，主要 UI 组件需求：

**布局（1920×1080 参考分辨率）**：
- 上方：回合计数（右上）+ 敌方资源条组（上中区，敌方排列）
- 下方：己方角色资源条组（下方两侧），招式选择面板（中央弹出）
- 场景层叠加：敌方意图图标（浮于角色头顶）
- HUD 汇总区：左上角小尺寸意图归纳

**输入要求**：
- 所有交互必须支持鼠标点击 + 键盘 + 手柄（D-pad/摇杆）三种输入
- 禁止任何 hover-only 交互（Steam Deck 兼容）
- 招式面板开启时必须自动获得手柄焦点
- 焦点不得逃出面板（循环导航）

**可访问性**：
- 体系区分不可仅依赖颜色（需结合图标形状/纹理——刚=拳形/柔=流线/巧=旋涡）
- `allow_decisive_skip` 参数为可访问性预留（默认关，v1.1 考虑暴露为设置选项）
- 字体基准 24 px，支持缩放（由全局设置控制）

**分辨率适配**：面板和资源条使用相对布局（锚点系统），确保在 1280×720 和 2560×1440 下均可用。

📌 **UX Flag — 战斗 UI**：本系统是全游戏 UI 密度最高的屏幕。Pre-Production 阶段运行 `/ux-design` 为战斗主界面创建完整 UX 规格（含线框图、焦点流、触控区尺寸），在写 Epics 之前完成。

## Acceptance Criteria

1. **GIVEN** 回合制战斗触发 `OnIntentRevealed`，**WHEN** UI 接收事件，**THEN** 所有参战敌方角色头顶在 `intent_icon_fadein_duration`（默认 0.4s）内显示对应体系图标（刚/柔/巧/？），HUD 汇总区同步更新。

2. **GIVEN** 玩家轮到某角色行动，**WHEN** 进入 PLAYER_DECISION 状态，**THEN** 招式面板弹出，显示 6 个装备招式（含体系色块+消耗），内息不足的招式置灰，面板第一个可用招式自动获得焦点。

3. **GIVEN** 玩家悬停/聚焦到一个克制当前目标意图的招式，**WHEN** 预览卡显示，**THEN** 克制标记 ✓ 绿色高亮，且"可反制"提示可见（若内息 ≥ 3）；不显示任何数字伤害预测。

4. **GIVEN** 目标破绽 ≥ 5（基准阈值），**WHEN** `OnDecisiveStrikeAvailable` 事件到达，**THEN** 面板顶部显示"▶ 决胜一击"金色高亮行，目标角色身上出现"破绽！"脉冲浮字。

5. **GIVEN** 玩家选择"决胜一击"，**WHEN** 确认触发，**THEN** Engine.TimeScale 在 0.3s 内降至 0.2，播放体系专属动画，完成后 TimeScale 在 0.3s 内恢复至 1.0，整个演出期间玩家输入被屏蔽。

6. **GIVEN** 两个己方角色在同一回合对同一目标选择了克制体系招式，**WHEN** 结算开始，**THEN** 目标处浮现"协同！"金色字样，持续 `coop_float_visible_duration` 秒。

7. **GIVEN** 回合计数达到 12，**WHEN** 回合计数刷新，**THEN** 回合数字颜色变为橙色；达到 14 时变为红色。

8. **GIVEN** 手柄玩家在招式面板底部招式处按下移，**WHEN** 导航触发，**THEN** 焦点循环回面板第一个招式，不丢失焦点到面板外。

9. **GIVEN** 鼠标玩家和手柄玩家在 Godot 4.6 双焦点系统下同时存在，**WHEN** 鼠标悬停某招式 + 手柄焦点在另一招式，**THEN** 两者各自的预览卡独立显示，互不干扰。

10. **GIVEN** 某敌方角色在回合内已落败，**WHEN** `OnIntentRevealed` 广播包含该目标，**THEN** 已落败目标的图标槽消隐，其他目标正常显示，不崩溃。

## Open Questions

1. **结算界面（Battle End）的具体内容**：战斗结束后显示什么统计数据？武学残片获得动画属于战斗 UI 还是单独的物品获取 UI？（待物品/道具系统和主线叙事设计解决）

2. **多角色战斗时的面板管理**：当玩家方有两个角色时，是为每个角色各弹出一次面板（顺序决策），还是同时显示两个面板并排？顺序决策更清晰但更慢；并排更快但信息密度大。（待 UX 设计验证）

3. **TimeScale 与暂停菜单的优先级**：如果玩家在一击决胜演出途中强行暂停，是立即冻结演出还是让演出完成再暂停？（待暂停/设置系统设计解决）

4. **意图图标的"模糊洞察"表现**：当 intent_insight 判定落入 80% base_chance 的 20% miss 时，"?"是稳定显示还是图标在"清晰/模糊"之间随机闪烁？（设计感上闪烁更有趣，但对玩家可能造成混淆——待 MVP 玩测验证）
